# Как менять и выпускать pet-companion

Этот репозиторий — единственный источник модуля. Копии на сайтах, в `node_modules` и в распакованных архивах не правят: исправление делается здесь и выходит новой версией.

## Устройство

| Путь | Что |
| --- | --- |
| `pet/` | модуль целиком (то, что получает сайт): `pet.mjs` — вход, остальные `.mjs` — внутренние модули, три файла CSS, `pet.d.mts` — типы |
| `pet/core/` | внутреннее ядро без DOM (этапы PL03 и PL04.1, не выпущено): экземпляр, раунд доставки, координатор хранения, порты, правила и форматы ключей `cat`, `companion`, `look`, `treat`; реакции и время — правила режиссёра (`director.mjs`), банки и выбор реплик (`phrases.mjs`), сессия экземпляра с задачами планировщика (`session.mjs`). Импортирует только `pet/core/**`, к браузеру не обращается |
| `pet/web/storage.mjs` | веб-координатор хранения на `localStorage` для ядра |
| `example.html` | полный пример — первый блок html README (проверка сверяет) |
| `examples/importmap.html` | пример пакета из `node_modules` без сборщика (в пакет не входит) |
| `scripts/sync-version.mjs` | шаг `npm version`: номер из `package.json` → `VERSION`, README, CHANGELOG |
| `test/*.test.mjs` | правила, хранение, рисунки, стили, форма пакета — `node:test`, без браузера; ядро — `core.test.mjs`, `core-storage.test.mjs` (контракт хранения), `core-round.test.mjs` (раунд доставки), `core-fresh.test.mjs` (решение по подтверждённому: сверка перед командой и её граница с фазой команды), `core-life.test.mjs` (реакции, память событий и Р1, тишина, реплики), `core-time.test.mjs` (планировщик, покой, полночь, приветствие, доставка), `core-globals.test.mjs` (ловушки браузерных глобалов); общие подделки — `core-kit.mjs` (в том числе ручные часы с местным днём, ручной планировщик, заданная случайность) |
| `test/browser.mjs`, `test/browser-storage.mjs`, `test/browser-core.mjs`, `test/browser-life.mjs`, `test/stand.html` | модуль в Chrome на проверочном стенде (компьютер и телефон, отключение, отказ подключения, две копии, стили сайта; сохранность данных — `browser-storage.mjs`; оболочка на ядре и решение по подтверждённому — `browser-core.mjs`; реакции и время, Р1 настоящими кнопками — `browser-life.mjs`) |
| `test/package.mjs` | упакованный архив: состав, установка в чистый проект, входы Node, типы, пример из архива и из `node_modules` в Chrome |
| `test/fixtures/pet-0.1.1/` | неизменяемые файлы выпуска 0.1.1 — для сценария «старая копия на странице» |
| `test/fixtures/pet-0.1.4/` | неизменяемые файлы выпуска 0.1.4 — для сценария «смешанные версии» хранения (вкладка прежней версии) |
| `docs/ARCHITECTURE.md` | проект архитектуры: факты 0.1.4, целевой контракт ядра, команд, расширений, хранения и этапы (в пакет не входит) |

## Окружение

Node.js 22 или новее, npm, Google Chrome (браузерные проверки запускают системный Chrome через `playwright-core`). `npm ci` ставит только средства проверки (`playwright-core`, `typescript`); у самого пакета зависимостей нет.

## Проверки

```sh
npm ci
npm test               # правила и форма пакета
npm run test:browser   # стенд в Chrome
npm run test:package   # упакованный архив, установка, типы, примеры в Chrome
```

Те же три команды выполняет CI (`.github/workflows/ci.yml`) на каждый push и pull request.

## Правила изменений

- **Публичный интерфейс** — то, что описано в README: `mountPet` и его настройки, методы и свойства экземпляра, `localDay`, `VERSION`, входы пакета (`pet-companion`, `pet-companion/pet.css`, `pet-companion/dog.css`, `pet-companion/pet-base.css`), классы и переменные CSS, отметки на `<html>`, ключи и форматы хранения. Внутренние модули и их экспорты — не интерфейс.
- **Версии** — README, «Версии и обновление»: patch — исправления и совместимые дополнения; minor (до 1.0) — несовместимое изменение интерфейса с описанием в CHANGELOG.
- **Хранение** — новые поля и ключи только с чтением прежних; прежние данные пользователей не теряются. Запись — функцией записи ключа (исходное значение + изменённые поля, README «Хранение»), а не нормализованным показом; новая запись — с проверкой, что неизвестное и больший `v` переживают её и повторное подключение.
- **Без зависимостей, сети и скриптов установки.** Модуль не делает запросов и не загружает внешние файлы; `pet/` самодостаточна (импорты — только относительные пути внутри `pet/`; ядро `pet/core/**` — только `pet/core/**`, без DOM и браузерных глобалов; новый файл в `pet/` — и в явном списке `test/package.mjs`).
- **Ядро** — единственная реализация перенесённых правил: оболочка их не повторяет, берёт решения и снимок ядра; запись ключей ядра — только его командами через координатор (`client.write`), не `setItem` из оболочки. Время, случайность и задачи ядра — только его порты (`clock`, `random`, `scheduler`): в `pet/core/**` нет `Date.now`, `Math.random`, `setTimeout`, кроме системных реализаций портов по умолчанию (`core/ports.mjs`); у оболочки остаются только таймеры показа (конец микродвижения, подсказки, фокус, `aria-live`).
- **Поведение** меняется вместе с проверкой, которая его фиксирует; изменение без проверки не принимается.
- **Архитектура** — ядро, команды, расширения, хранение и отображения делаются по `docs/ARCHITECTURE.md`; отступление от контракта — правкой документа в том же изменении, с причиной. Реализованная часть отмечается там же, проект не выдаётся за выпущенное.
- Каждое изменение — строка в разделе `## Не выпущено` CHANGELOG (раздел создаётся над последней версией).

## Выпуск

1. В `main` всё проверено (CI зелёный), в CHANGELOG есть раздел `## Не выпущено` с изменениями.
2. `npm version patch` (или `minor`): npm меняет `package.json`, `scripts/sync-version.mjs` согласует `VERSION`, README и CHANGELOG (раздел получает номер и дату), затем npm делает коммит и тег `vX.Y.Z`.
3. `npm test && npm run test:browser && npm run test:package`.
4. `npm pack --json` — архив `pet-companion-X.Y.Z.tgz`; записать его `integrity` и SHA-256 (`shasum -a 256`).
5. `git push --follow-tags`.
6. `npm publish pet-companion-X.Y.Z.tgz` — публикуется ровно проверенный архив (нужен вход в npm с двухфакторной проверкой).
7. Выпуск на GitHub для тега `vX.Y.Z`: тот же `.tgz`, в описании — раздел CHANGELOG, `integrity` и SHA-256.
8. Сверка: `npm view pet-companion@X.Y.Z dist.integrity` совпадает с записанным.

Опубликованную версию не меняют и не удаляют: исправление — новая версия; неудачную можно пометить `npm deprecate`.
