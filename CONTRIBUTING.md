# Как менять и выпускать pet-companion

Этот репозиторий — единственный источник модуля. Копии на сайтах, в `node_modules` и в распакованных архивах не правят: исправление делается здесь и выходит новой версией.

Node.js 22.16 или новее (с PL09 проверки используют `node:sqlite` и `DatabaseSync.isTransaction`), npm, Google Chrome (браузерные проверки запускают системный Chrome через `playwright-core`). `npm ci` ставит только средства проверки точных версий: `playwright-core`, `typescript`, с PL08 — `react`, `react-dom`, `@types/react` (серверный рендер в `npm test`, с PL09 — и хук натива, с PL10.1 — `PetView` и типы входа `/native` в `test:package`) и `vite` (сборки потребителей); у самого пакета зависимостей нет, `react`, `react-native`, `react-native-svg`, `expo-sqlite` — необязательные партнёры только своих входов. `expo`, `react-native`, `react-native-svg` и `expo-sqlite` в библиотеку не ставятся: проверки натива в Node подменяют их загрузчиком и тестовым драйвером на `node:sqlite`; настоящие — только в `examples/expo/` (своя установка, `examples/expo/README.md`). `npm run test:consumers` ставит архив и те же версии (и React 18.3.1) во временные проекты — нужна сеть npm или её кэш; мобильных партнёров он не ставит.

## Проверки

```sh
npm ci
npm test               # правила и форма пакета (в том числе проверки натива)
npm run test:native    # только натив: SQLite на node:sqlite, резервирование, жизненный цикл, входы, SIGKILL, PetView и наборы, уголок и координатор, «Поиграть» и жесты, пример Expo
npm run test:browser   # стенд в Chrome
npm run test:package   # упакованный архив, установка, типы, примеры и сайт по перечню в Chrome
npm run test:consumers # архив в чистых проектах: Vite, React 18 и 19, SSR и гидратация (сеть или кэш npm)
```

Те же четыре команды выполняет CI (`.github/workflows/ci.yml`) на каждый push и pull request; затем шаг «Запись архива» (PL12) упаковывает коммит и сохраняет запись артефактом `release-record` (на теге — с проверкой номера). `test:package` и `test:consumers` с `PET_TARBALL=путь.tgz` проверяют этот архив вместо свежей упаковки (шаг `prepare` выпуска). Нативную платформу эти команды не проверяют: Node с подделками React Native и `react-native-svg` подтверждает контракт отображения, а запуск на iOS и Android — пример `examples/expo/` (его README: запуск в iOS Simulator — касания XCUITest, запуск в Android-эмуляторе — касания `adb` по дереву UI Automator, матрица доказательств; симулятор, эмулятор и телефон — разные отметки). Перечень файлов: `npm run manifest` — пересобрать после изменения состава модулей, `node scripts/manifest.mjs --check` — сверить (то же делает `npm test`).

## Правила изменений

- **Публичный интерфейс** — то, что описано в README: `mountPet` и его настройки, методы и свойства экземпляра (с 0.2.0, PL05, — ещё `pet.core` и команды ядра; с PL06 — `pet.setBehavior`, настройки `pets`, `behaviors`, `kits`), `localDay`, `VERSION`, входы пакета (`pet-companion`, `pet-companion/core` — с PL05, `pet-companion/pets` и `pet-companion/behaviors` — с PL06, `pet-companion/web` (`mountPetIn` и его настройки, вид, `createWebStorage`, `createWebScenes`, `catWeb`, `dogWeb`, поле `styles` набора) — с PL07, `pet-companion/react` (`PetCompanion` и его свойства, `usePetState`), с 0.3.0 (U01) — `pet-companion/character` (`defineCharacter` и формат персонажа 1, `createCharacter` и его команды, снимок, эффекты), `pet-companion/character-web` (`mountCharacterIn` и его настройки, вид, набор отображения персонажа, переменные темы `--pet-*`) и `pet-companion/character-react` (`Character`, `useCharacterState`), и `pet-companion/manifest.json` (схема перечня, README «Файлы пакета без сборщика») — с PL08, `pet-companion/native-sqlite` (`createSqliteStorage`, `createSqliteScenes`, их настройки, таблицы `pet_kv` и `pet_scene`) и `pet-companion/native` (`useNativeLifecycle`, `usePetState`) — с PL09, `PetView` и его свойства, `catNative`, `dogNative` и контракт нативного набора (`NativePetKit`) — с PL10.1, `pet-companion/pet.css`, `pet-companion/dog.css`, `pet-companion/pet-base.css`), формат определений 1 и набора отображения веба, классы и переменные CSS, отметки на `<html>`, ключи и форматы хранения. Внутренние модули и их экспорты — не интерфейс.
- **Публичное ядро — только через фасад** (`pet/core/facade.mjs`): новый публичный метод или поле результата добавляется в фасад явным списком, в типы `pet/core.d.mts` и README вместе с проверками (`test/core-public.test.mjs`, при необходимости `@ts-expect-error` в `test/package.mjs`); всё остальное во внутреннем экземпляре остаётся внутренним. Фасад поля только копирует: успех внутренней команды несёт все свои поля на каждом пути — повтор без изменений тоже, сбой после применения — через `extra` у `act` (`pet/core/index.mjs`). Массив строк из аргумента — проверкой `strings` (строка в каждом индексе), не `every`/`some`: они пропускают пустые индексы. Входы legacy-отображения (`setPlace`, `arrive`, `stopScene`, признак `scene` события без `key`, признак `pick` имени) наружу не выдаются; снимок — без `place`.
- **Кнопки и команды — один путь** (`pet/web/shell.mjs`; до PL07 — `pet/pet.mjs`): обработчик кнопки вызывает команду ядра и делает только то, что знает лишь он (фокус на нажатой кнопке, объявление о выборе); всё, что видно, рисует подписка `onCore` по снимку (`reflect`, `syncView`) — так же для прямой команды хоста, другой вкладки и задачи ядра. Поверхность, которая пересоздаёт вход диалога (кнопку питомца, лапку вызова), сразу подписывает его общим `labelOpeners` (доступное имя, `aria-expanded`, точка «новое»), а не обработчиком отдельной настройки. Подписка команд ядра не вызывает (кроме объявления сменившейся раскладки `setDisplay`) и рисует по `getState()`, а не по переданному снимку.
- **Отображение — на экземпляр** (PL07, архитектура § 1.3, Р3): состояние показа, жест, таймеры, кадры, наблюдатели и слушатели живут в замыкании `createShell` и его поверхности, а не на уровне модуля (проверка формы пакета ищет модульные `let`/`var` и общий объект состояния в `pet/web/**`, `pet-play.mjs`, `pet-toys.mjs`, `pet-room.mjs`, `pet-move.mjs`); жест — через указатель своей сцены (`createPointer`), свои элементы — через корень поверхности (`root()`), а не `document.getElementById`. Различия `mountPet` и контейнера — только в поверхности; у `mountPet` вид и поведение прежние (весь `test:browser` legacy; при PL07 снимки экрана стенда сверены с прежним кодом разово, вне набора проверок), id, места, отметки на `<html>` и реестр одного питомца не меняются.
- **CSP** (PL07): в разметке модуля нет атрибутов `style` и встроенных `<style>`/`<script>` — динамические размеры и координаты только через CSSOM (`el.style.setProperty`), цвета рисунков — классами; стили — файлы. Проверка — стенды с заголовком `default-src 'self'; style-src 'self'` (`test:browser`, `test:package`): нарушений `securitypolicyviolation` нет.
- **Версии** — README, «Версии и обновление»: patch — исправления и совместимые дополнения; minor (до 1.0) — несовместимое изменение интерфейса с описанием в CHANGELOG. Несовместимость установки — тоже minor: новый или суженный диапазон `peerDependencies`, с которым npm откажет прежнему корректному проекту (так выпущена 0.2.0). Нативные входы, пока не закрыты критерии PL10 (физические телефоны, VoiceOver и TalkBack вживую, Android-отмена жеста по фокусу окна, «Обустроить уголок» и сценки на нативе), выпускаются предварительными — README («Поддержка платформ») и запись версии в CHANGELOG говорят это прямо; Node-проверки, симулятор и эмулятор за проверку телефонов не выдаются.
- **Хранение** — новые поля и ключи только с чтением прежних; прежние данные пользователей не теряются. Запись — функцией записи ключа (исходное значение + изменённые поля, README «Хранение»), а не нормализованным показом; новая запись — с проверкой, что неизвестное и больший `v` переживают её и повторное подключение.
- **Без зависимостей, сети и скриптов установки.** Модуль не делает запросов и не загружает внешние файлы; `pet/` самодостаточна (импорты — только относительные пути внутри `pet/`; ядро `pet/core/**` — только `pet/core/**`, без DOM и браузерных глобалов; определения `pet/defs/**` — только `core/define.mjs` и `defs/**`; новый файл в `pet/` — и в явном списке `test/package.mjs`, и в перечне: `npm run manifest`, иначе `npm test` падает). Стили вида `mountPetIn` — файлы пакета рядом с модулем и `styles` наборов, которые передал сайт: `<link>` в своё теневое дерево, других адресов нет. Адрес файла пакета — всегда отдельный литерал `new URL('./file.css', import.meta.url)`: перечисление, шаблон или переменная невидимы сборщику и перечню (`scripts/manifest.mjs` откажет).
- **React — только в своём слое** (PL08): голое имя `react` импортируют лишь `pet/react.mjs` (ещё `pet/web/**`, `pet/core/**`, `pet/hooks/**`) и `pet/hooks/**` (только `react`, ядро — аргументом, без DOM и веба); `pet-companion`, `/core`, `/pets`, `/behaviors`, `/web` React не достигают (проверки графа — `test/package-shape.test.mjs` по исходникам и `test/package.mjs` по архиву, перечень — `peers` только у `./react`). `react` — необязательный партнёр в `peerDependencies`, не `dependencies`; средства проверки — `devDependencies` точными версиями. Диапазон партнёра расширяется только вместе с проверкой новой версии в `test:consumers`.
- **Натив — только в своём слое** (PL09, PL10.1, PL10.2.1, PL10.2.2): `react-native` импортирует лишь `pet/native.mjs` и отображение (`pet/native/view.mjs`, `figure.mjs`, `provider.mjs`, `corner.mjs`, `play.mjs`), `react-native-svg` — лишь рисунки и поверхности (`pet/native/figure.mjs`, `corner.mjs`, `play.mjs`, `room.mjs`, `svg.mjs`, `cat.mjs`, `dog.mjs`), `expo-sqlite` — лишь `pet/native-sqlite.mjs`; `pet/storage/**`, `pet/native/lifecycle.mjs`, `pet/native/kits.mjs` и `pet/native/gesture.mjs` — только `pet/core/**` (системные модули — аргументом); распознавание жестов — отображение (пороги в точках экрана, попадание по областям определения), смысл — команды ядра `stroke.*`, `interact`, `toy.*`, правил лимита, удержания, мест и доката в нативе нет; системная отмена жеста не ждёт отпускания (его может не быть), а поздние события прежнего касания отсекаются по `identifier` и `timestamp` — без своих полей в `nativeEvent`; обработчики поверхностей проверяют привязку в момент вызова (ядро, показанный питомец и, у игры, вид — по каждому обновлению ядра), а не только по отрисовке; натив без DOM, CSS, `import.meta` и веба; отображение не дублирует правил ядра — рисует снимок, касание — публичная команда; объявление отображения ядру — один владелец (`PetProvider` в композиции или отдельный `PetView`), открытый вид — только `view` снимка; прежние входы натива не достигают (проверки графа — `test/package-shape.test.mjs`, `test/package.mjs`, перечень — `peers` у `./native` и `./native-sqlite`). Все SQL-транзакции библиотеки — на её соединении записи и через мьютекс файла, с `BEGIN IMMEDIATE` до чтения; соединение приложения не используется. Гонки и отказы в проверках — шлюзами и инъекциями драйвера, без пауз; инъекция и настоящая ошибка SQLite называются по-разному.
- **Обёртка React** — `useEffect` с `mountPetIn`: на сервере и при первом клиентском рендере — пустой `<div>`, без SSR-рисования и подавления предупреждений гидратации; функции сайта — через ref, настройки подключения — в зависимостях эффекта (список определений — по составу); `onCore(null)` — до `view.destroy()`. Хук — ровно контракт `docs/ARCHITECTURE.md` § 11.3 (`useSyncExternalStore` с серверным снимком `null`, подписка `initial: false`), не прямой `core.subscribe`/`core.getState`.
- **Ядро** — единственная реализация перенесённых правил: оболочка их не повторяет, берёт решения и снимок ядра; запись ключей ядра — только его командами через координатор (`client.write`), не `setItem` из оболочки. Время, случайность и задачи ядра — только его порты (`clock`, `random`, `scheduler`): в `pet/core/**` нет `Date.now`, `Math.random`, `setTimeout`, кроме системных реализаций портов по умолчанию (`core/ports.mjs`); у оболочки остаются только таймеры показа (конец микродвижения, подсказки, фокус, `aria-live`).
- **Питомцы и модели — данные** (PL06): различия кота и собаки — в определениях `pet/defs/**` и наборах `pet/web/kits.mjs`, не в ветвлениях ядра. В `pet/core/**` нет строк и полей `cat`/`dog` вне `formats/legacy.mjs` и ID примера (проверка формы пакета). Новое правило поведения формулируется через словарь формата 1 (позы, реакции, группы реплик, классы — `core/define.mjs`) и действует для любого корректного питомца и модели; новое поле формата — новая версия формата, а не тихое расширение `format: 1`.
- **Новый питомец или модель.** Определение — `definePet` / `defineBehavior` с данными (README, «Питомцы и модели поведения»); штатное — файл в `pet/defs/`, экспорт во входе `pets.mjs` или `behaviors.mjs`, типы `*.d.mts`, явный список `test/package.mjs`. Для веба — набор отображения (`art`, `item`, `mini?`, списки поз, сценок, обликов, аксессуаров, вещей) и его CSS; `kitProblem` должен его принять. Обязательные позы набора — по роли (`kitNeeds`: конечная поза обязательных и лапы после замен, даже если её использует сценка), а не по списку `poses` определения; изменение определения кота или собаки — вместе с их штатным набором: `mountPet` проверяет и штатные наборы против переданных определений. Проверки — исполнение пары в Node (`core-pl06.test.mjs` — образец: позы и замены, лапа, зевок, длительности, реплики, лимит, сценки), сценарий в Chrome на четырёх размерах. Сторонние определения и наборы в пакет не входят — образец `examples/extension/`.
- **Поведение** меняется вместе с проверкой, которая его фиксирует; изменение без проверки не принимается.
- **Архитектура** — ядро, команды, расширения, хранение и отображения делаются по `docs/ARCHITECTURE.md`; отступление от контракта — правкой документа в том же изменении, с причиной. Реализованная часть отмечается там же, проект не выдаётся за выпущенное.
- Каждое изменение — строка в разделе `## Не выпущено` CHANGELOG (раздел создаётся над последней версией).

## Выпуск

С PL12 — через `scripts/release.mjs`: архив упаковывается из коммита, его запись (SHA-256, integrity, содержимое) идёт от проверок до сверки опубликованного, а публикация отказывает до реестра при любом расхождении. Устройство цепочки, отказы и подключение проектов — [docs/RELEASES.md](docs/RELEASES.md).

1. В `main` всё проверено (CI зелёный), в CHANGELOG есть раздел `## Не выпущено` с изменениями.
2. Кандидат: `npm version X.Y.Z --no-git-tag-version` (npm меняет `package.json`; `scripts/sync-version.mjs` согласует `VERSION`, README и CHANGELOG — раздел получает номер и дату; `scripts/manifest.mjs` пересобирает `manifest.json`) и обычный коммит.
3. `node scripts/release.mjs prepare X.Y.Z --candidate --out DIR` — чистое дерево, согласованный номер, тега и номера в npm ещё нет; архив `DIR/pet-companion-X.Y.Z.tgz` из `HEAD` и `DIR/record.json`; затем `npm test`, `test:browser`, `test:package` и `test:consumers` — последние два ставят **этот** архив (`PET_TARBALL`). Устаревший перечень остановит уже `npm test`.
4. Независимая проверка кандидата — по `record.json` и архиву.
5. Тег на проверенный коммит: `git tag -a vX.Y.Z -m "pet-companion X.Y.Z"`, `git push origin main vX.Y.Z`. CI тега прогоняет четыре набора и шаг «Запись архива» (`record --expect-tag`) — артефакт `release-record`.
6. `node scripts/release.mjs publish DIR/record.json` — в терминале (двухфакторная проверка npm 11 — только с TTY; вход в npm — у владельца): архив = запись, аннотированный тег на коммите записи локально и на `origin`, последний CI тега зелёный и упаковал то же содержимое; затем `npm publish` ровно этого файла, выпуск GitHub с ним же (описание — раздел CHANGELOG и контрольные суммы) и `verify`. Повтор после частичного сбоя доводит до конца, ничего не публикуя второй раз. `--dry-run` — всё, кроме публикации.
7. Сверка в любой момент: `node scripts/release.mjs verify X.Y.Z [--record DIR/record.json]` — npm, файл и описание выпуска GitHub, тег → коммит, повторная упаковка коммита тега.

Опубликованную версию не меняют и не удаляют, тег не переносят: исправление — новая версия; неудачную можно пометить `npm deprecate`. `npm publish` архива не запускает `prepublishOnly` — защита выпуска в гейтах шага 6.
