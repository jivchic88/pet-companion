# Питомец — изменения

Версии — по README, «Версии и обновление». Номер версии — в `package.json` (он же `VERSION` в `pet/pet.mjs`; в исходниках после 0.1.4 — одна константа `pet/core/version.mjs` для обоих входов); форматы данных (`v1` в ключах) — отдельно.

## Не выпущено

- Мобильное хранение и жизненный цикл (этап PL09; **на устройстве не проверено — этап не завершён**). Прежние входы, ключи и форматы `v1`, вид и поведение питомца не менялись.
  - Новый вход `pet-companion/native-sqlite` (`pet/native-sqlite.mjs`, типы `pet/native-sqlite.d.mts`): `createSqliteStorage({ db, namespace?, busyTimeout?, log? })` — координатор хранения для `createPetCore` на `expo-sqlite`, `createSqliteScenes(…)` — резервирование дня сценки. Своё соединение записи к файлу базы приложения (`useNewConnection: true`) — одно на файл в процессе для всех `namespace`, записей и резервирования, мьютекс файла; файл узнаётся по `databasePath` (путь, `file:`-адрес), база в памяти — отказ. Таблицы `pet_kv (ns, key, value)` и `pet_scene (ns, value)` — только если их нет; запись — `INSERT … ON CONFLICT` (другие столбцы строки не трогаются; таблица без ключа уникальности — честный отказ).
  - Операция ключа — весь участок в одной транзакции: `BEGIN IMMEDIATE` до чтения → `SELECT` → правка → `INSERT` и `COMMIT`, либо `ROLLBACK`, если писать нечего; «сохранено» — только после `COMMIT`. Для этого общий координатор (`pet/core/storage.mjs`) получил внутреннюю возможность платформы `transact(key, plan)`: очереди, кэш, сверка, фиксация и `settle` — прежние, публичный `createStorage({ backend })` не изменился. Занятый файл дольше `busyTimeout` (по умолчанию 1000 мс) — отказ без повторов; не удался `ROLLBACK` — проверка `isInTransactionAsync` и при открытой транзакции сброс своего соединения; режим журнала и `synchronous` приложения не меняются (не WAL — одно предупреждение).
  - Резервирование дня: тот же мьютекс и соединение, `BEGIN IMMEDIATE` → `SELECT` → `decide` после всех ожиданий → `INSERT` поставлен и `show()` в том же шаге → `COMMIT` (`shown`); отказ после начала показа — `ROLLBACK` после поставленного `INSERT` (`lost`); повреждённая запись дня (не JSON, не строка) — `fail` без решения и не переписывается.
  - Новый частичный вход `pet-companion/native` (`pet/native.mjs`, типы `pet/native.d.mts`): `useNativeLifecycle(core | null)` — `AppState` (`active`/`background`, iOS `inactive` и Android `blur` — отмена идущего жеста) и системное «уменьшить движение» → входы ядра `setVisible`, `setReducedMotion`; возвращает `true`, когда начальная настройка движения известна (тогда `core.start()`); `usePetState` — общий хук `pet/hooks/state.mjs`. Нативного отображения (`PetView`, наборы) нет — PL10. Вход не достигает веба, DOM и CSS.
  - `react-native` (`>=0.88.0`) и `expo-sqlite` (`>=58.0.0`) — необязательные партнёры только новых входов; `pet-companion`, `/core`, `/pets`, `/behaviors`, `/web`, `/react` их не требуют. Перечень `manifest.json` — с новыми входами и их партнёрами.
  - Диагностический пример `examples/expo/` (в пакет не входит): Expo SDK 58 (`expo` 58.0.12, `react-native` 0.88.0, `react` 19.3.0, `expo-sqlite` 58.0.13; lock собран по метаданным реестра, без установки), экран на `View`/`Text`/`Button`, библиотека — локальным архивом `npm run lib`. Зависимости не устанавливались, на устройстве не запускался (нужно решение владельца и поддерживаемый Node для Expo CLI).
  - Проверки: новая команда `npm run test:native` (часть `npm test`): общий контракт хранения на асинхронном хранилище и на SQLite, SQLite на настоящем `node:sqlite` с потоком на соединение (два соединения и вторая копия адаптера, занятый файл с замером, § 8.7.2, настоящие отказы SQLite и инъекции отказов драйвера), резервирование дня, жизненный цикл, публичные входы с подменой партнёров загрузчиком и хук в настоящем React 19 со StrictMode, `SIGKILL` процесса; форма пакета и перечень — графы натива; `test:package` — архив с новыми файлами, входы без партнёров, типы, логика примера на установленном архиве.
- Установка в веб-проекты, React и файлы пакета (этап PL08). Интерфейс `mountPet` 0.1.4, `mountPetIn` и ядра, ключи и форматы `v1`, вид, тексты и стили — прежние; поведение питомца не менялось.
  - Новый вход `pet-companion/react` (`pet/react.mjs`, типы `pet/react.d.mts`): `<PetCompanion>` — один пустой `<div>` на сервере и при первом клиентском рендере, питомец (`mountPetIn`) — после клиентского эффекта; `onCore(core)` после подключения, `onCore(null)` до отключения, при отказе и после отключения помимо обёртки; настройки подключения (`namespace`, `pets`, `behaviors`, `kits`, `watchTyping`) — смена пересоздаёт питомца, функции сайта (`progress`, `home`, `onOpenChange`, `onCore`) — последние, без пересоздания; `className`; неизвестное свойство и `children` — отказ подключения. `usePetState(core | null)` — снимок или `null` (сервер, гидратация, нет ядра, ядро отключено), подписка `initial: false`; общий хук `pet/hooks/state.mjs` зависит только от `react`. Вход — `'use client'`.
  - `react` — необязательная зависимость-партнёр (`peerDependencies` `^18.3.1 || ^19.0.0`, `peerDependenciesMeta.optional`): нужен только `/react`; остальные входы и ядро React не требуют и не импортируют. Проверены React и react-dom 18.3.1 и 19.3.1.
  - Перечень файлов `pet-companion/manifest.json` (файл `manifest.json` в корне пакета): для каждого входа — файл входа, все файлы для отдачи, стили страницы в порядке каскада (у `mountPet`), пакеты-партнёры (`react` у `/react`). Серверу без сборщика больше не нужен свой список внутренних файлов. Перечень собирает `scripts/manifest.mjs` по импортам и адресам стилей; `npm test` и проверка архива сверяют его, `npm version` пересобирает с новым номером.
  - Стили вида в контейнере: каждый адрес — отдельный литерал `new URL('…', import.meta.url)` (прежде — перечисление через `map`, которое сборщик не видит: в сборке Vite стили запрашивались мимо файлов и вид отключался). Без сборщика адреса прежние.
  - Проверенный сборщик — Vite 8.3.4: production-сборка и сервер разработки; строгий CSP со сборщиком — `build.assetsInlineLimit: 0` (иначе `pet-base.css` встраивается как `data:`). Примеры `examples/vite/`, `examples/react/` (серверный рендер и гидратация), `examples/manifest/` (сайт без сборщика: копирование по перечню, страницы контейнера и `mountPet`).
  - Проверки: `test/manifest.test.mjs` (перечень против графа и загрузчика Node, отрицательные контроли), `test/react.test.mjs` (импорт и серверный рендер без браузерных глобалов), новая команда `npm run test:consumers` (архив в чистых проектах с Vite и React 18/19: сборки, SSR и гидратация, жизненный цикл в development и production, типы), раздача по перечню в `test:package`, граф импортов с `react` только в слое React.
- Изолированный веб-компонент в одном контейнере (этап PL07). Интерфейс `mountPet` 0.1.4 и его места, ключи и форматы `v1`, вид, тексты, классы и стили кота и собаки — прежние.
  - Новый вход `pet-companion/web` (`pet/web.mjs`, типы `pet/web.d.mts`): `mountPetIn(container, options)` → вид `{ mounted, core, open, close, destroy }`; `createWebStorage({ namespace })` и `createWebScenes({ namespace })` — веб-адаптеры для своего ядра (`createPetCore` входа `pet-companion/core`); штатные наборы `catWeb`, `dogWeb`. Импорт ничего не делает (ни DOM, ни хранилища).
