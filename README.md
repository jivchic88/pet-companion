# pet-companion — питомец для сайта

Версия **0.1.4** (номер — в `package.json`; история — [CHANGELOG.md](CHANGELOG.md)). В исходниках репозитория после неё — невыпущенные изменения: хранение (раздел «Хранение») и общее ядро без DOM, на котором работает `mountPet`, — с реакциями и временем, исправлением «Скрыть», которое забывало учтённые события и тишину сайта, с присутствием, видами уголка и редкими сценками, комнатой и игрой, а также **публичные команды, снимок и подписка**: методы `pet.setName`, `pet.feed`, `pet.subscribe` и другие, свойство `pet.core` и вход ядра `pet-companion/core` для приложений без браузера, и **подключаемые питомцы и модели поведения** — определения формата 1 (`definePet`, `defineBehavior`, входы `pet-companion/pets` и `pet-companion/behaviors`, `pet.setBehavior`, свой питомец со своим набором рисунков), и **питомец в одном контейнере** — вход `pet-companion/web` (`mountPetIn`: свой элемент и Shadow DOM в блоке сайта — без мест, шапки и CSS питомца на странице, несколько питомцев на странице), и **установка в веб-проекты и React** — вход `pet-companion/react` (`PetCompanion`, `usePetState`, серверный рендер и гидратация), перечень файлов `pet-companion/manifest.json` для серверов без сборщика, проверенная сборка Vite, и **мобильное хранение и жизненный цикл** — входы `pet-companion/native-sqlite` (SQLite через `expo-sqlite`) и `pet-companion/native` (`useNativeLifecycle`, `usePetState`), и **минимальное нативное отображение** — `PetView` и наборы `catNative`, `dogNative` того же входа (рисунки `react-native-svg`, без WebView), и **уголок на нативе** — `PetProvider` и `PetCorner` (проверено в Node, в iOS Simulator и в Android-эмуляторе, на физических телефонах ещё не запускалось) (разделы «Питомец в контейнере», «Подключение из npm», «React и серверный рендер», «Мобильное хранение и жизненный цикл», «Нативное отображение», «Файлы пакета без сборщика», «Команды и состояние», «Ядро без отображения», «Питомцы и модели поведения», «Хранение», «Архитектура и будущий API»; CHANGELOG «Не выпущено»). Прежний интерфейс 0.1.4 сохранён; **опубликованный пакет 0.1.4 этих изменений не содержит** — как получить их для проверки, сказано в разделе «Команды и состояние».

> **In English, briefly.** A calm cat or dog companion that lives next to a web page and reacts to the site’s confirmed
> learning activity. Plain browser ES modules + CSS, inline SVG art, no runtime dependencies, no network, no build step.
> The interface texts and this guide are in Russian; other languages are not supported yet. License — [LICENSE](LICENSE).

Кот или собака рядом со страницей: спокойный спутник, который радуется подтверждённым занятиям сайта. Уголок (ступени по знакам, лакомство дня, имя, облик, аксессуар, место и вид, присутствие, движение), сцена «Поиграть» (поглаживание, лапа, миска, мячик), «Обустроить уголок» (расстановка комнаты), редкие сценки после занятия, «Всегда рядом» / «Приходит по зову». Клавиатура, Esc, возврат фокуса, объявления для скринридера, «уменьшить движение». Без сети, аналитики и сборки: ES-модули и CSS.

Модуль не знает, что такое занятие: знаки, «первое занятие дня» и следующий шаг считает сайт и передаёт их через небольшой интерфейс ниже. Оценки ответов питомцу не передаются.

## Установка

Три способа — одни и те же файлы одной версии:

- **npm** (сайт со сборщиком или с `node_modules` на сервере): `npm install pet-companion` — раздел «Подключение из npm».
- **Архив выпуска** (сайт без npm и сборки): файл `pet-companion-<версия>.tgz` — на странице выпуска (Releases) репозитория или из реестра командой `npm pack pet-companion@<версия>`. Это тот же архив, что в npm: внутри папка `package/` с `pet/`, `example.html`, README, CHANGELOG, LICENSE. Скопируйте `package/pet/` на сайт — раздел «Быстрый старт».
- **Папка из установленного пакета:** `node_modules/pet-companion/pet/` можно скопировать на сайт целиком (например, в `/vendor/pet/`). Скопированные файлы не правят — обновляют целиком (раздел «Версии и обновление»). В исходниках после 0.1.4 (не выпущено) можно скопировать только файлы нужного входа — по перечню `manifest.json` (раздел «Файлы пакета без сборщика»).

## Быстрый старт

1. Скопируйте папку `pet/` на сайт целиком, в любое место: модули импортируют друг друга относительными путями (`./pet-rules.mjs`), поэтому папка работает и в корне сайта, и во вложенном адресе.
2. Подключите стили и вызовите `mountPet` после того, как в разметке есть места для питомца (у `<script type="module">` в конце `<body>` — уже есть).
3. Сообщайте питомцу о подтверждённых занятиях (`pet.notify('saved', …)`).

Полный рабочий пример — `example.html` (пути `./pet/…` — относительно страницы; страница в другом месте — поправьте их). Открывать через http(s), а не `file://`: браузер не загружает ES-модули с диска.

```html
<!doctype html>
<html lang="ru">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>Мой сайт</title>
    <link rel="stylesheet" href="./pet/pet-base.css" />
    <link rel="stylesheet" href="./pet/pet.css" />
    <link rel="stylesheet" href="./pet/dog.css" />
  </head>
  <body>
    <header id="head" style="position: relative"><span id="title">Мой сайт</span></header>
    <main><button id="done" type="button">Урок пройден</button></main>
    <script type="module">
      import { mountPet } from './pet/pet.mjs';

      let marks = 0; // знаки за занятия — считает сайт
      let today = 0; // из них сегодня
      const head = document.getElementById('head');
      const pet = mountPet({
        storage: 'mysite',
        places: {
          logo: (el) => head.append(el), // компьютер: в шапке; здесь же «Показать …» после «Скрыть»
          top: (el) => head.prepend(el), // телефон: в шапке; без places.restore здесь же «Показать …»
          float: (el) => document.body.append(el), // компьютер: в правом нижнем углу окна
        },
        progress: () => ({ marks, today, limit: 3 }),
      });
      if (!pet.mounted) console.info('Питомец не подключён — причина выше в консоли');

      // Занятие сохранено и засчитано (здесь — по кнопке): сначала счёт сайта, затем событие.
      document.getElementById('done').addEventListener('click', () => {
        marks += 1;
        today += 1;
        pet.notify('saved', { key: `lesson-${marks}`, counted: true, first: today === 1 });
      });
    </script>
  </body>
</html>
```

Это полный минимум: `logo` и `top` обязательны (без них питомца негде показать и после «Скрыть» не вернуть — подключение откажет), остальные места — по желанию.

## Питомец в контейнере (pet-companion/web)

> **Не выпущено (этап PL07).** Только в исходниках репозитория после 0.1.4, как разделы «Команды и состояние» и ниже; опубликованный пакет 0.1.4 этого не содержит (как попробовать — раздел «Команды и состояние»). Интерфейс может уточниться до выпуска.

Питомец живёт в одном блоке сайта: ни мест в шапке и панелях, ни CSS питомца на странице, ни отметок на `<html>`. В контейнер вставляется свой элемент `<div data-pet-view>` с открытым Shadow DOM: id, классы и стили изолированы в обе стороны, стили пакета вид загружает сам. Таких питомцев на странице может быть несколько — и вместе с `mountPet`.

```js
import { mountPetIn } from 'pet-companion/web';

let marks = 0; // знаки за занятия — считает сайт
let today = 0; // из них сегодня
const view = mountPetIn(document.getElementById('pet'), { namespace: 'mysite', progress: () => ({ marks, today, limit: 3 }) });
if (!view.mounted) console.info('Питомец не подключён — причина выше в консоли');

// Занятие сохранено и засчитано: сначала счёт сайта, затем событие (команды ядра вида — раздел «Команды и состояние»).
marks += 1;
today += 1;
view.core?.notify('saved', { key: `lesson-${marks}`, counted: true, first: today === 1 });
```

Без сборщика — карта импортов `{ "imports": { "pet-companion/web": "./node_modules/pet-companion/pet/web.mjs" } }`; полный пример — `examples/container.html` репозитория (два контейнера, занятие, повторное подключение, блокировка прокрутки сайтом). Под строгим CSP встроенная карта импортов запрещена: модуль страницы импортирует файл входа по пути (`examples/csp/`). Стили (`pet-base.css`, `pet.css`, `dog.css`, `web/view.css`) вид находит по адресу своего модуля — пакет может лежать под любым адресом. Типы — `pet/web.d.mts` (условие `types` входа).

**Что передаёт сайт** — то же, что в разделе «Что передаёт сайт и когда», командами ядра вида: занятие и ошибка сохранения — `view.core.notify('saved', …)` и `notify('failed')`; числа изменились без события — `view.core.refresh()`; состояние страницы — `view.core.setContext({ focus, timer, dictation, dialog })`; переход по сайту — `view.close()` или, если экран уходит, `view.destroy()`.

**`mountPetIn(container, options?) → view`** — синхронно, не бросает исключений.

| Настройка | Что | По умолчанию |
| --- | --- | --- |
| `namespace` | пространство имён хранения (непустая строка): ключи `<namespace>:cat:v1` и др., база IndexedDB `<namespace>:scene` (раздел «Хранение»). Одинаковое у двух видов — общие настройки и дневные лимиты (ниже) | `'pet'` |
| `progress()` | счёт сайта `{ marks, today, limit }`, как у `mountPet` | ноль знаков |
| `pets`, `behaviors`, `kits` | питомцы, модели поведения и наборы отображения (раздел «Питомцы и модели поведения»); CSS своего набора — его `styles` (ниже) | кот, собака, `calm`; наборы `catWeb`, `dogWeb` |
| `home()` | куда поставить фокус, когда своего входа нет: закрытие диалога, пока питомца не видно; отключение вида с фокусом внутри | — |
| `onOpenChange(open)` | диалог питомца открылся (`true`) или закрылся (`false`) — только настоящие переходы; блокировку прокрутки страницы решает сайт | — |
| `watchTyping` | наблюдать ввод в поля страницы (только чтение `focusin`/`focusout` документа) — тишина реакций, пока пользователь печатает; свои поля питомца — не ввод. `false` — не наблюдать, слушателей нет | `true` |

Других настроек нет: места, `zone`, `step`, `go`, `classes`, `texts` — только у `mountPet`; неизвестная настройка — отказ.

| Вид | Что |
| --- | --- |
| `view.mounted` | подключён ли: `false` после отказа, `destroy()`, `view.core.destroy()` и поздней ошибки загрузки стилей |
| `view.core` | ядро вида — тот же интерфейс, что `pet.core` (команды, снимок, подписка — раздел «Команды и состояние»); `null` при отказе; после отключения — тот же отключённый экземпляр (`status: 'destroyed'`). Итог команды показывается сразу, как после кнопки |
| `view.open(view = 'corner')` | открыть уголок, сразу «Поиграть» (`'play'`: «Закрыть» ведёт к странице, как вызов «по зову») или «Обустроить уголок» (`'room'`); диалог уже открыт — смена вида. Результат — как у команд ядра; питомец не на виду (стили ещё грузятся, контейнер скрыт или без размеров) — `unsupported`; после отключения — `destroyed` |
| `view.close()` | закрыть диалог; фокус — на питомца в контейнере (иначе `home()`) |
| `view.destroy()` | отключить ядро и вид: свой элемент, слушатели, таймеры, наблюдатели, кадры анимации, захват указателя; повторно — ничего. То же делает `view.core.destroy()` (и из слушателя подписки) |

**Подключение и жизненный цикл.**

- Проверка — до любых действий: контейнер (элемент этой страницы, уже в документе), настройки, определения и каждый выбранный набор, штатный тоже, против своего определения. Отказ — `mounted: false`, `core: null`, одно `console.error('Питомец не подключён: …')`; ни элемента, ни записей хранилища, ни ядра. Исключение при запуске откатывает только своё: соседние виды и `mountPet` не трогаются.
- Контейнер уже занят живым видом — отказ, прежний вид не тронут; после его `destroy()` можно подключить снова. Чужие дети контейнера не трогаются, свой элемент встаёт последним.
- Подключайте после вставки контейнера в документ. Контейнер убрали из документа без `destroy()` — вид приостановлен: диалог закрыт (`onOpenChange(false)`), жест отменён, для ядра питомец не на виду (реакции и сценки не начинаются); вернули — продолжает. Ресурсы освобождает только `destroy()`: вызывайте его при уходе с экрана (SPA).
- Повторное подключение — новое ядро с подтверждёнными настройками; несохранённое прежнего ядра не наследуется, его поздние операции в новый вид не попадают.
- `mountPetIn` не ждёт загрузки стилей: `mounted` говорит о ядре и разметке, команды `view.core` работают сразу. Пока стили (пакета и `styles` наборов) грузятся, место питомца скрыто и питомец не на виду — для ядра как вкладка в фоне: реакции и сценки не начинаются, день редкой сценки не резервируется, диалог не открывается (`view.open()` — `unsupported`). Загрузились — питомец на виду (если у контейнера есть размеры); отменённое за время загрузки не доигрывается, следующее событие — как обычно. Поэтому приветствия дня при подключении вида нет: ядро решает его при запуске, а питомец в этот момент ещё не на виду — как у вкладки, открытой в фоне, день приветствия записывается без проигрывания. Стиль не загрузился (сеть, 404, CSP) — одно `console.error('Питомец: стили не загрузились …')` и вид отключается (`mounted: false`): без стилей питомца не показываем.
- Исключения `progress()`, `home()` и `onOpenChange` после подключения — журнал браузера; наружу они не выходят и соседей не трогают.

**Размеры.** Свой элемент занимает ширину контейнера, а высоту — контейнера, если она задана, иначе по пропорции рисунка (220 × 204), не выше 360 px. Вид выбирается по размеру своего элемента (`ResizeObserver`), а не окна: от 160 × 148 px — питомец целиком (с облаком реплики), меньше — портрет. Нулевой размер, `display: none`, контейнер вне документа — питомец не на виду: диалог закрыт (показать его негде), жест отменён, `view.open()` — `unsupported`; размеры вернулись — снова на виду. Сам диалог модальный, над всей страницей: его размер — по окну.

**Диалог, фокус, прокрутка.** Уголок, «Поиграть» и «Обустроить уголок» — `<dialog>` в своём теневом дереве (`showModal`, ловушка фокуса браузера). Esc — по шагам, как у `mountPet`: перенос в редакторе → редактор → уголок → закрыт; одна клавиша с автоповтором не закрывает несколько уровней; из двух открытых диалогов Esc получает верхний. Прокрутку страницы вид не блокирует и не возвращает — это делает сайт по `onOpenChange`. Фокус при закрытии — на кнопку, открывшую диалог (питомец в контейнере), иначе `home()`; отключение вида не забирает фокус у соседа. Кнопка питомца в контейнере пересоздаётся при смене облика, питомца, вида и присутствия — любым путём (кнопкой уголка, командой, правкой соседнего вида или другой вкладки) — и каждый раз сразу с доступным именем («Имя — уголок кота», с «, есть новая вещь» и точкой, пока новая ступень не увидена), `aria-expanded` и `aria-controls`; фокус, если был на ней, остаётся на новой. Объявления для скринридера — своя область `aria-live` в теневом дереве.

**Тема и изоляция.** Переменные темы `--pet-*` и `--cat-*` (раздел «Стили») наследуются от контейнера и его предков: на контейнере — тема только этого вида, на `:root` — всех; без них — умолчания, светлые и тёмные по `prefers-color-scheme`. Других способов стилизовать содержимое снаружи нет: правила сайта (`*`, теги, `!important`, `svg`, `path`, классы `cat-*`) внутрь теневого дерева не проходят, наследуемые шрифт, межбуквенный интервал и регистр — тоже. CSS вида не меняет ни одного элемента сайта.

**Хранение.** Как у `mountPet` (раздел «Хранение»): `localStorage` и IndexedDB этого браузера. Одинаковый `namespace` у двух видов (или у вида и `mountPet` с тем же `storage`) — один общий координатор: правка одного приходит другому тихо, независимые поля не теряются, лакомство и день редкой сценки — одни на всех. Изоляция DOM не изолирует настройки: независимые питомцы — разные `namespace`.

**Своё отображение на тех же адаптерах.** `createWebStorage({ namespace })` — координатор на `localStorage` страницы, тот же, что у видов и `mountPet` с этим пространством имён в этой копии модуля (создаётся загруженным; перед каждым новым ядром — `load()`). `createWebScenes({ namespace })` — резервирование дня редкой сценки на IndexedDB, общее для этого пространства имён. Ошибки настроек — исключение `PetError` (`invalid-options`). Ядро — `createPetCore` входа `pet-companion/core` этой же копии пакета:

```js
import { calm } from 'pet-companion/behaviors';
import { createPetCore } from 'pet-companion/core';
import { cat, dog } from 'pet-companion/pets';
import { createWebScenes, createWebStorage } from 'pet-companion/web';

const storage = createWebStorage({ namespace: 'mysite' });
storage.load(); // барьер перед новым ядром — синхронно
const pet = createPetCore({ storage, scenes: createWebScenes({ namespace: 'mysite' }), pets: [cat, dog], behaviors: [calm], progress: () => ({ marks, today }) });
pet.subscribe(({ snapshot }) => draw(snapshot));
pet.start();
```

**Свой питомец в контейнере.** Набор отображения — как для `mountPet` (раздел «Питомцы и модели поведения») плюс `styles`: абсолютные адреса CSS набора, обычно `new URL('./my.css', import.meta.url).href`. Вид подключает их в своё теневое дерево; не абсолютный адрес — отказ подключения. `mountPet` поле `styles` не загружает: там CSS набора подключает страница. Пример — `examples/extension/container.html` репозитория.

**CSP.** Вид не вставляет встроенных скриптов, стилей и атрибутов `style`: размеры и координаты — через CSSOM, стили — файлы (`<link>`), сети нет. Проверено в Chrome под заголовком `default-src 'self'; style-src 'self'` (стенд `examples/csp/` с файлами установленного пакета): нарушений нет, стили применены, уголок, «Поиграть» и редактор работают. Файлы пакета и CSS наборов должны отдаваться с источника, который разрешает политика.

**Пределы.** Проверено только в Google Chrome: компьютер и эмуляция телефона по ширине, это не проверка iPhone и Android. Safari, Firefox и скринридеры не проверялись. Стили вид находит по `import.meta.url` своего модуля — каждый адрес отдельным литералом `new URL('…', import.meta.url)`: проверено без сборщика (файлы пакета по их адресам, раздел «Файлы пакета без сборщика») и со сборщиком Vite 8.3.4 — production-сборка и сервер разработки с предварительной сборкой зависимостей (раздел «Подключение из npm»). Другие сборщики не проверялись: им нужно переносить файлы из `new URL('…', import.meta.url)` в модулях зависимостей, иначе вид отключится с ошибкой стилей. Импорт `pet-companion/web` на сервере безопасен (ничего не делает), сам питомец — только в браузере: без `document` `mountPetIn` отказывает. Для React — `pet-companion/react` (раздел «React и серверный рендер»). Тексты — на русском.

## Подключение из npm

**Со сборщиком** (Vite, webpack, esbuild и др.) — публичные входы пакета:

```js
import { mountPet, localDay } from 'pet-companion';
import 'pet-companion/pet-base.css'; // только если у сайта нет своих классов кнопок (раздел «Стили»)
import 'pet-companion/pet.css';
import 'pet-companion/dog.css';
```

Порядок импорта стилей — порядок каскада (раздел «Стили»). Стили объявлены в `sideEffects` пакета — сборщик их не выбрасывает. Другие пути внутри пакета (`pet-companion/pet/pet-rules.mjs` и т. п.) не экспортируются: внутренние модули не входят в публичный интерфейс. Питомцу в контейнере (`import { mountPetIn } from 'pet-companion/web'`, не выпущено) импорт стилей не нужен: он подключает их сам (раздел «Питомец в контейнере»).

**Проверенный сборщик — Vite 8.3.4** (исходники после 0.1.4, не выпущено; этап PL08): `npx vite build`, на сервер — только папка `dist/`. Стили питомца в контейнере Vite переносит в `dist/assets/` сам, сайт их не копирует; стили `mountPet` из импорта выше остаются в CSS сборки. Сервер разработки (`npx vite`) тоже работает: стили контейнера берутся из файлов установленного пакета. Полный пример — `examples/vite/` репозитория: контейнер со своим питомцем-кроликом (его стили — `styles` набора), `mountPet` в шапке, `vite.config.js`. Строгий CSP (`style-src 'self'`) со сборщиком — настройка `build: { assetsInlineLimit: 0 }`: иначе Vite встроит `pet-base.css` (меньше 4 КБ) адресом `data:`, такой стиль политика запретит и вид отключится. Без строгого CSP настройка не нужна. Другие сборщики (webpack, esbuild, Parcel) не проверялись: им нужно переносить файлы из `new URL('…', import.meta.url)` в модулях зависимостей, иначе вид в контейнере отключится с ошибкой стилей.

**Без сборщика, `node_modules` отдаёт сервер** — карта импортов и ссылки на стили (пути — от страницы):

```html
<link rel="stylesheet" href="./node_modules/pet-companion/pet/pet-base.css" />
<link rel="stylesheet" href="./node_modules/pet-companion/pet/pet.css" />
<link rel="stylesheet" href="./node_modules/pet-companion/pet/dog.css" />
<script type="importmap">
  { "imports": { "pet-companion": "./node_modules/pet-companion/pet/pet.mjs" } }
</script>
<script type="module">
  import { mountPet } from 'pet-companion';
  // дальше — как в «Быстром старте»
</script>
```

**Типы.** `pet/pet.d.mts` описывает `mountPet`, настройки, экземпляр, `localDay` и `VERSION`; TypeScript находит их по входу пакета (`moduleResolution` — `bundler`, `node16` или `nodenext`), а при копировании папки — рядом с `pet.mjs`. У входов стилей — своя декларация `pet/css.d.mts` (условие `types` в `exports`; сборщик по тем же входам получает настоящий `.css`): импорт стилей выше проходит проверку типов и с `noUncheckedSideEffectImports`, без общей декларации `declare module '*.css'` в проекте сайта. Значений стиль не экспортирует — это не CSS Modules.

## React и серверный рендер (pet-companion/react)

> **Не выпущено (этап PL08).** Только в исходниках репозитория после 0.1.4, как разделы «Питомец в контейнере» и ниже; опубликованный пакет 0.1.4 этого не содержит. Интерфейс может уточниться до выпуска.

`npm install pet-companion react react-dom` — `react` нужен только этому входу (необязательная зависимость-партнёр пакета: остальные входы React не требуют, npm его сам не ставит). Питомец живёт в браузере, поэтому на сервере и при первом клиентском рендере `<PetCompanion>` — один пустой `<div>`, а питомец подключается после эффекта (тот же `mountPetIn`, раздел «Питомец в контейнере»). Заглушку на время загрузки рисует сайт рядом с контейнером — по `usePetState(core) === null`:

```jsx
import { useState } from 'react';
import { PetCompanion, usePetState } from 'pet-companion/react';

// Питомец в блоке страницы: на сервере и при гидратации — пустой контейнер и заглушка сайта (снимка нет), после эффекта —
// питомец и строка по его снимку. Ядро приходит через onCore; заглушку рисует сайт рядом с контейнером, не внутри.
export function Corner({ progress }) {
  const [core, setCore] = useState(null);
  const pet = usePetState(core);
  return (
    <>
      <PetCompanion namespace="mysite" className="pet" progress={progress} onCore={setCore} />
      {pet ? <p>{pet.name.display}: {pet.treat === 'ready' ? 'можно угостить' : 'рядом'}</p> : <p>Питомец появится после загрузки страницы.</p>}
    </>
  );
}
```

На сервере (`renderToString`) и при гидратации (`hydrateRoot`) выводится вторая строка, после эффекта — первая; расхождений разметки нет. Полный пример с серверным рендером — `examples/react/` репозитория (Vite: сборка клиента, сборка сервера `--ssr`, `prerender.mjs`). Занятие — `core.notify('saved', …)` полученного ядра, как в разделе «Питомец в контейнере».

**`<PetCompanion>`** — свойства:

| Свойство | Что |
| --- | --- |
| `namespace`, `pets`, `behaviors`, `kits`, `watchTyping` | настройки подключения, как у `mountPetIn`. Смена — прежний вид отключается (`onCore(null)`), новый подключается (`onCore(новое ядро)`); горячей замены нет. Новый массив того же состава (`pets={[cat, dog]}` прямо в разметке) — та же настройка, питомец не пересоздаётся |
| `progress`, `home`, `onOpenChange` | функции сайта, как у `mountPetIn`: вызывается последняя переданная, новая функция при новом рендере питомца не пересоздаёт. Новый `progress` ядро прочитает при следующем событии или `core.refresh()`; сама смена свойства ничего не показывает и наград не выдаёт |
| `onCore(core \| null)` | ядро после подключения; `null` — до отключения (размонтирование, смена настроек подключения), при отказе подключения и после отключения помимо обёртки (`core.destroy()`, стили не загрузились) — тогда питомец сам не возвращается: снова подключит смена настроек подключения или `key` |
| `className` | класс контейнера: его размер выбирает вид «целиком» или «портрет» |

Других свойств нет: содержимым контейнера управляет библиотека, поэтому детей у `<PetCompanion>` нет; неизвестное свойство (и `children`) — отказ подключения: `console.error('Питомец не подключён: неизвестная настройка: …')` и `onCore(null)`. Исключение `onCore` — журнал браузера. В StrictMode (разработка) React дважды выполняет эффект при подключении: `onCore(core1)`, `onCore(null)`, `onCore(core2)` — первое ядро отключено (его повторный `destroy()` безопасен), живёт один вид с подтверждёнными настройками; в production — один `onCore(core)`. При размонтировании React убирает контейнер раньше эффекта: фокус, если был внутри питомца, браузер отдаёт странице, `home()` здесь не вызывается — сайт ставит фокус сам; при смене настроек подключения фокус изнутри уходит в `home()`.

**`usePetState(core | null)`** → снимок ядра (раздел «Команды и состояние») или `null`: ядра нет, сервер и гидратация, ядро отключено. Подписка — `core.subscribe(…, { initial: false })`, снимается при смене ядра и размонтировании; снимок — одна ссылка, пока состояние не изменилось, поэтому лишних рендеров нет. Прямой `useSyncExternalStore(core.subscribe, core.getState)` не подходит: он не знает `null`, отключённого ядра и серверного снимка.

**Серверный рендер.** Импорт `pet-companion/react` (и `/core`, `/pets`, `/behaviors`, `/web`) на сервере не трогает браузер и ничего не делает. Вход начинается с `'use client'` — граница клиентских компонентов для сред с серверными компонентами (например, Next.js App Router; эта среда не проверялась). Vite 8 при сборке печатает о ней предупреждение `MODULE_LEVEL_DIRECTIVE` — ожидаемо, на работу не влияет.

**Версии и типы.** Партнёр — `react` `^18.3.1 || ^19.0.0`; проверены React и react-dom **18.3.1** и **19.3.1**, типы `@types/react` 18.3.29 и 19.3.0 (`moduleResolution` `bundler` и `nodenext`, `jsx: react-jsx`), сборка — Vite 8.3.4, development и production. Другие версии из диапазона отдельно не проверялись. Типы входа — `pet/react.d.mts` (нужен `@types/react` проекта). Без сборщика вход не поддерживается: у React нет своей сборки ES-модулей для карты импортов.

## Мобильное хранение и жизненный цикл (pet-companion/native-sqlite, pet-companion/native)

> **Не выпущено (этап PL09); проверено в iOS Simulator и Android-эмуляторе, на телефонах — нет.** Только в исходниках репозитория после 0.1.4. SQL-контракт проверен в Node на настоящем SQLite (`node:sqlite`), жизненный цикл — на подделке React Native и настоящем React 19; пример `examples/expo/` запущен в Expo Go 58.0.4 в iOS Simulator (iOS 26.3.1) и — вместе с отображением PL10.1 — в Android-эмуляторе (Android 16, API 36) с настоящими `expo-sqlite`, `AppState` и `AccessibilityInfo` (`examples/expo/README.md`). Физические iPhone и Android-телефон не проверялись; в Expo Go на Android события `AppState` `blur`/`focus` в JavaScript не приходят (там же). Здесь — хранение, резервирование дня сценки и события приложения для своего ядра; питомец на экране — раздел «Нативное отображение» (PL10.1).

`npm install pet-companion expo-sqlite` (и `react`, `react-native` приложения). Все три — необязательные партнёры пакета: их требуют только эти два входа, прежние входы — нет. Проверялась матрица Expo SDK 58: `expo` 58.0.12, `react-native` 0.88.0, `react` 19.3.0, `expo-sqlite` 58.0.13 (в Node — заменой `expo-sqlite` на тот же SQL через `node:sqlite`). «Голый» React Native без модулей Expo `expo-sqlite` не загрузит — нужны модули Expo (`npx install-expo-modules`).

```jsx
import { useEffect, useState } from 'react';
import { Text } from 'react-native';
import { openDatabaseAsync } from 'expo-sqlite';
import { createPetCore } from 'pet-companion/core';
import { calm } from 'pet-companion/behaviors';
import { useNativeLifecycle, usePetState } from 'pet-companion/native';
import { createSqliteScenes, createSqliteStorage } from 'pet-companion/native-sqlite';
import { cat, dog } from 'pet-companion/pets';

// База приложения → координатор и резервирование дня → await load() → ядро; start — после начальной синхронизации.
export function Pet({ progress }) {
  const [core, setCore] = useState(null);
  const ready = useNativeLifecycle(core);
  const pet = usePetState(core);
  useEffect(() => {
    let made = null;
    let live = true;
    (async () => {
      const db = await openDatabaseAsync('app.db');
      const storage = createSqliteStorage({ db, namespace: 'myapp' });
      await storage.load();
      if (!live) return;
      made = createPetCore({ storage, scenes: createSqliteScenes({ db, namespace: 'myapp' }), pets: [cat, dog], behaviors: [calm], progress });
      setCore(made);
    })();
    return () => {
      live = false;
      made?.destroy();
    };
  }, [progress]);
  useEffect(() => {
    if (core && ready && core.status === 'created') core.start();
  }, [core, ready]);
  return <Text>{pet ? `${pet.name.display}: ${pet.save.cat.status}` : 'Загрузка…'}</Text>;
}
```

**`createSqliteStorage({ db, namespace?, busyTimeout?, log? })`** — координатор хранения для `createPetCore` входа `pet-companion/core` этой же копии пакета; тот же объект для того же файла базы и `namespace`. **`createSqliteScenes(…)`** — резервирование дня редкой сценки (порт `scenes`) на том же файле. `db` — база приложения из `openDatabaseAsync`: от неё библиотеке нужен только путь файла (`databasePath`); к тому же файлу она открывает **своё соединение записи** (`useNewConnection: true`) — одно на файл в процессе, общее для всех `namespace`, записей и резервирования. На соединении приложения библиотека запросов не выполняет, не закрывает и не перенастраивает его. База в памяти (`:memory:`) не подходит. `busyTimeout` — сколько её соединение ждёт файл, занятый другим соединением (мс, 0…10000, по умолчанию 1000; одно значение на файл), `log` — предупреждения адаптера. Ошибка настроек — `PetError` (`invalid-options`).

- **Таблицы** `pet_kv (ns, key, value)` и `pet_scene (ns, value)` — создаются, только если их нет; ключ строки — `cat:v1` и т. д. (как у веба, без пространства имён). Своих таблиц приложения адаптер не трогает.
- **Запись** — операция ключа общей очереди (раздел «Хранение»): `BEGIN IMMEDIATE` (блокировка записи — до чтения) → свежий `SELECT` → правка поверх прочитанного → `INSERT … ON CONFLICT` и `COMMIT`, либо `ROLLBACK`, если писать нечего. «Сохранено» (`saved`) — только после `COMMIT`; до него — `pending`. Прочитанное в транзакции чужое значение (другое соединение или процесс) попадает в кэш и ко всем ядрам и при отказе записи.
- **Занятый файл** дольше `busyTimeout` — честный отказ (`failed`, у сценки — `fail` до показа), без скрытых повторов; несохранённое уходит со следующей правкой владельца. Ожидание — в потоке SQLite, не JS; замер на `node:sqlite`: отказ через ≈1,1 с при значении 1000.
- **Ошибки завершения транзакции.** Не удался `ROLLBACK` — адаптер проверяет `isInTransactionAsync()` (ошибка проверки — «транзакция открыта») и при открытой транзакции закрывает своё соединение: SQLite откатит её и снимет блокировки; следующая операция откроет новое. Не закрылось — предупреждение `log`, дальнейшие записи честно отказывают, пока файл занят.
- **Режим журнала** выбирает приложение; адаптер его и `synchronous` не меняет, но при режиме не WAL пишет одно предупреждение: гарантии те же, а `COMMIT` ждёт читателей других соединений (отказ после начала показа сценки вероятнее). Рекомендуется WAL (`PRAGMA journal_mode = WAL` на своём соединении).
- **Перед каждым новым ядром** — `await storage.load()`: барьер ждёт операций прежнего ядра и сверяет кэш свежим чтением.

**`useNativeLifecycle(core | null)`** → `boolean`: `AppState` `active` → `setVisible(true)`, `background` → `setVisible(false)` (фон снимает реакцию, сценку и задачи; возврат ничего не доигрывает и пересчитывает день), iOS `inactive` и Android `blur` — видимость прежняя, но идущий жест и перенос предмета отменяются; системное «уменьшить движение» → `setReducedMotion` (выбор владельца `prefs.motion` не меняется, итог — `prefs.effectiveMotion`). `true` — начальная настройка движения уже известна текущей привязке: тогда и звать `core.start()`. Готовность принадлежит привязке, а не ядру: отрисовка с другим `core` — в том числе снова с тем же после `null` (A → `null` → A) или A → B → A — уже в этой отрисовке возвращает `false`, и эффект хоста того же commit не запустит ядро по прежней готовности, пока новая привязка заново не узнает системную настройку (она могла измениться, пока ядро было отключено). Смена `core`, размонтирование, StrictMode и внешний `core.destroy()` снимают слушатели и готовность (после внешнего `destroy` — `false`); поздние ответы прежней привязки ничего не меняют; событие `reduceMotionChanged` главнее позднего начального ответа. **`usePetState(core | null)`** — тот же хук, что у `pet-companion/react` (раздел «React и серверный рендер»).

**Гарантии и границы.**

| Где | Что обещано | Чего нет |
| --- | --- | --- |
| один процесс, одна копия пакета | общий реестр файлов, очередь ключа, одно соединение записи и мьютекс файла; независимые правки разных полей не теряются; порядок правок одного поля — порядок очереди | транзакций между ключами |
| несколько соединений к одному файлу | `BEGIN IMMEDIATE` до чтения: конкурент ждёт и строится по подтверждённому либо честно отказывает; день сценки — один (проверено в Node на двух соединениях и в двух процессах) | — |
| несколько процессов (виджет, расширение в App Group, второй процесс Android) | та же файловая блокировка SQLite — **условие интегратора**: общий файл в общем контейнере, тот же `namespace`, та же версия пакета | на устройствах не проверено и не заявлено поддержанным; уведомлений между процессами нет — чужие данные видны после свежей операции этого ключа, `load()` или перезапуска; решение команды — по подтверждённому в процессе |
| завершение процесса | подтверждённое (`saved`) остаётся; незавершённая транзакция откатывается при следующем открытии, файл не заблокирован (проверено `SIGKILL` процесса Node, WAL и DELETE) | `pending` может потеряться; завершающего события для «дописать» нет и не используется |
| отключение питания | — | зависит от режима журнала и `synchronous` приложения и ОС; большего не обещается |
| устройства и приложение с сайтом | — | синхронизации нет: у каждого хранилища свои данные и дневные лимиты |

Симулятор, настоящий телефон и проверки Node — разные доказательства: в отчётах их не смешивают.

## Нативное отображение (pet-companion/native: PetView, PetProvider, PetCorner, PetPlay, catNative, dogNative)

> **Не выпущено (этапы PL10.1 — минимальный нативный потребитель, PL10.2.1 — уголок, PL10.2.2 — «Поиграть», «по зову» и игровые жесты); проверено в Node, в iOS Simulator и в Android-эмуляторе, на физических телефонах — нет.** Только в исходниках репозитория после 0.1.4. Пример `examples/expo/` запущен в Expo Go 58.0.4 в iOS Simulator (iOS 26.3.1) и в Android-эмуляторе (Android 16, API 36) — Hermes, Fabric — с настоящими `react-native-svg`, `expo-sqlite`, `AppState` и `AccessibilityInfo` (`examples/expo/README.md`). Уголок (`PetProvider`, `PetCorner`) — раздел «Уголок», «Поиграть» и вызов «по зову» (`PetPlay`) — раздел «Поиграть» ниже. PL10.2.2 доработана по независимой проверке Codex (`599be43`: начатые движения предметов, ввод после системной отмены без отпускания, устаревшие обработчики) и по повторной (`b121731`: движение предмета — своё, пока идёт хоть одна его координата) — ждёт повторной проверки. **Не закрыто в PL10.2.2:** отмена жеста при потере фокуса окна Android (шторка, «Недавние», ассистент) — в Expo Go событие `AppState` `blur` в JavaScript не приходит, а пока открыто окно игры (`Modal` — отдельное окно Dialog), оно не придёт и в собственной сборке; нужен решённый владельцем путь (раздел «Поиграть», «Ограничения»). «Обустроить уголок», редкие сценки, расширения PL06 на нативе и полная проверка VoiceOver и TalkBack — этапы PL10.2.3–PL10.2.4; этим входом пока не обещаны.

`npm install pet-companion react-native-svg` (и `react`, `react-native` приложения; хранение — раздел выше). `react-native-svg` — необязательный партнёр только этого входа: прежние входы и `/native-sqlite` его не требуют. Проверен 15.16.0 (Expo SDK 58, входит в Expo Go).

```jsx
import { useEffect } from 'react';
import { calm } from 'pet-companion/behaviors';
import { createPetCore } from 'pet-companion/core';
import { catNative, dogNative, PetView, useNativeLifecycle } from 'pet-companion/native';
import { cat, dog } from 'pet-companion/pets';

// Те же определения — ядру и отображению; ядро создаёт, запускает и уничтожает хост (раздел выше).
const PETS = [cat, dog];
const KITS = [catNative, dogNative];
export const makeCore = (storage, progress) => createPetCore({ storage, pets: PETS, behaviors: [calm], progress });

export function Pet({ core }) {
  const ready = useNativeLifecycle(core);
  useEffect(() => {
    if (core && ready && core.status === 'created') core.start();
  }, [core, ready]);
  return <PetView core={core} pets={PETS} kits={KITS} size={200} />;
}
```

**`PetView({ core, pets, kits, size?, style?, label?, hint?, announce?, touch?, testID? })`** — питомец на экране приложения: рисует публичный снимок ядра и превращает касание в публичную команду; своих правил поведения у него нет.

| Свойство | Что |
| --- | --- |
| `core` | ядро `createPetCore` (`null` — ничего не рисует). Создаёт, запускает (`start` — после `useNativeLifecycle` → `true`) и уничтожает его хост; `PetView` ядро не создаёт и не уничтожает |
| `pets` | те же определения, что у `createPetCore` (у ядра нет метода их получить); по ним проверяются наборы |
| `kits` | нативные наборы — штатные `catNative`, `dogNative` или свои (ниже); хотя бы один |
| `size` | ширина рисунка в точках (по умолчанию 180), высота — по пропорции рисунка определения (220×204) |
| `style` | стиль контейнера (`View`) |
| `label`, `hint` | доступное имя кнопки питомца (по умолчанию «<имя>, <вид>») и подсказка (по умолчанию «Погладить») |
| `announce` | объявлять эффекты `announce` ядра скринридеру (`AccessibilityInfo.announceForAccessibility`, по одному на эффект; по умолчанию `true`; второму `PetView` того же ядра — `false`) |
| `touch` | касание питомца — `activity()` и `interact({ type: 'pet' })` (по умолчанию `true`): отклик без знаков и наград |
| `testID` | префикс идентификаторов узлов для автоматизации: корень, `-touch`, `-motion`, `-art`, `-phrase`, `-problem` |

- **Что рисует.** Показанного питомца (`pet.shown`), имя, облик и надетый аксессуар (`look.worn`), позу `pose.shown.page` (реакцию — её позой; поза без рисунка в наборе — явной заменой набора, иначе заменой определения, иначе базовой позой снимка), реплику (`phrase`). Спрятанный или «по зову» не вызванный (`presence.around: false`) — не рисуется. Никакого собственного логического состояния: прямые команды хоста (`setPet`, `setName`, `setAppearance`, `notify`, `feed`) и касание видны одним путём — через снимок.
- **Что объявляет ядру** — только нарисованное: `setDisplay({ full: true, moving: false, pets: <питомцы с набором>, views: [], scenes: {} })`. Видов у отдельного `PetView` нет; сценок нет — ни резервирования дня, ни показа. Хосту `setDisplay` вызывать не нужно. Внутри `PetProvider` (раздел «Уголок» ниже) `PetView` не объявляет ничего — объявляет координатор.
- **Движение** — встроенный `Animated` на нативном драйвере, только как показ уже решённой ядром реакции (прыжок радости, мурлыканье, поклёвывание у миски): у запущенного ядра, на виду и с движением. Конец реакции, `effectiveMotion: 'none'` (выбор владельца или системное «уменьшить движение»), фон приложения, смена ядра и размонтирование снимают анимацию; смысл реакции остаётся статической позой и текстом. Длительности, приоритеты, лимиты, награды и кормление — в ядре.
- **Владение.** Подписки `PetView` — общий `usePetState` (снимок) и одна своя подписка объявлений; анимации — свои значения `Animated`; всё снимается при смене ядра и размонтировании, внешний `core.destroy()` — пустой `PetView`. Жизненный цикл приложения `PetView` не подключает: `useNativeLifecycle` — один раз у хоста. Два `PetView` на разных ядрах независимы.
- **Отказ.** Неверные `pets` или `kits` (нет определения, не нарисована обязательная поза, лапа, облик или аксессуар, рисунок — строка, лишние поля) — читаемый текст «Питомец не показан: …» с ролью `alert` и предупреждение журнала; ни подписки, ни `setDisplay`, ни команд.
- **Доступность (базовая).** Питомец — кнопка с именем, ролью, подсказкой и состоянием; рисунок скрыт от скринридера (подпись — у кнопки). Проверено деревом доступности XCUITest в iOS Simulator и UI Automator в Android-эмуляторе; VoiceOver и TalkBack вживую — PL10.2.

**Нативный набор** (`NativePetKit`) — код рисования одного питомца, отдельно от определения и модели поведения: `{ pet, poses, coats, accessories, substitutes?, Figure }` и необязательные ресурсы уголка `room`, `items`, `Item` (раздел «Уголок» ниже). `Figure({ pose, coat, accessory, toward, prefix })` — чистая функция без хуков, возвращает элементы `react-native-svg` в единицах рисунка определения без корневого `<Svg>` (его ставит `PetView`); не строка разметки — веб-наборы `catWeb`, `dogWeb` нативными не являются. Обязательное покрытие — как у веб-наборов: конечная поза (после `poseFallback`) каждой обязательной позы словаря и лапа, если у питомца есть `actions.paw`; все облики и аксессуары определения. `substitutes` — явные замены только необязательных поз (`yawn`, `settle`, позы сценок) на нарисованные. Штатные `catNative`, `dogNative` — прежние рисунки кота и собаки, перенесённые в элементы `react-native-svg` (220×204, позы — таблицы суставов веба), все позы словаря, `settle` — замена `content`; с PL10.2.1 — ещё ресурсы уголка (рисунок в комнате, клубок кота, канат и мячик собаки), с PL10.2.2 — ресурсы игры (`play: true`, раздел «Поиграть»); сценок нет. Миску и мячик «Поиграть» рисует сцена натива, не набор.

Симулятор, эмулятор, настоящий телефон и проверки Node — разные доказательства; PL10.1, PL10.2.1 и PL10.2.2 проверены в iOS Simulator и Android-эмуляторе, физические iPhone и Android-телефон не проверены.

### Уголок (PetProvider, PetCorner)

> **Не выпущено (этап PL10.2.1).** Проверено в Node, в iOS Simulator и в Android-эмуляторе (`examples/expo/README.md`, «Проверка PL10.2.1»); на физических телефонах — нет. «Поиграть», «Обустроить уголок», сценки и расширения на нативе — PL10.2.2–PL10.2.4.

```jsx
import { useEffect } from 'react';
import { catNative, dogNative, PetCorner, PetProvider, PetView, useNativeLifecycle } from 'pet-companion/native';

// insets — отступы безопасной области хоста, например useSafeAreaInsets() пакета react-native-safe-area-context.
export function PetHome({ core, pets, insets }) {
  const ready = useNativeLifecycle(core);
  useEffect(() => {
    if (core && ready && core.status === 'created') core.start();
  }, [core, ready]);
  return (
    <PetProvider core={core} pets={pets} kits={[catNative, dogNative]}>
      <PetView size={200} />
      <PetCorner insets={insets} />
    </PetProvider>
  );
}
```

- **`PetProvider({ core, pets, kits, announce?, children })`** — координатор поверхностей одного ядра и **единственный владелец объявления отображения**: `setDisplay({ full: true, moving: false, pets: <питомцы с набором>, views: <виды подключённых поверхностей — у PetCorner 'corner'>, scenes: {} })` и объявлений скринридеру (эффекты `announce`, по одному на эффект для всех поверхностей). Поверхность подключается сразу, отключается микрозадачей (StrictMode и пересоздание той же поверхности в одном такте — без промежуточного сброса); повтор того же объявления не отправляется. Уголок размонтирован — его открытый вид закрыт ядром (`core.close()`), `views` без `'corner'`; смена ядра и размонтирование координатора снимают его объявление с прежнего ядра (открытый вид закрыт, `views: []`). Неверные `pets` или `kits` — ничего не объявляется. Ядро, `useNativeLifecycle` и `start` — у хоста, как прежде. Объявляет один координатор ядра — **последний подключённый**: замена координатора на том же ядре (другой React `key`, новый экран поверх прежнего) передаёт ему объявление без промежуточного сброса; его отключение возвращает объявление предыдущему подключённому (тот объявляет свои виды, открытый вид без его поверхности закрыт), а последнего — снимает; объявления скринридеру — только у объявляющего. Обычно достаточно одного координатора у корня приложения.
- **`PetView` внутри координатора** — без `core`, `pets`, `kits`: те же рисунок, касание и доступность, но без своего `setDisplay` и объявлений (они у координатора; `announce` не действует). Отдельно используемый `PetView` (со своими `core`, `pets`, `kits`) — прежний PL10.1 без изменений.
- **`PetCorner({ insets?, entry?, label?, hint?, returnFocus?, testID?, style? })`** — только внутри `PetProvider`. Вход «Уголок <кого>» (кнопка; доступное имя «<имя> — уголок <кого>», «, есть новая вещь» при `progress.unseen`) вызывает `core.open('corner')`; окно уголка (`Modal`) открыто ровно тогда, когда в снимке `view.open === 'corner'` — кнопкой, прямой командой хоста или после восстановления, своего флага открытия нет. Закрытие — `core.close()`: «Закрыть», Android «Назад» (окно перехватывает его только пока открыто), жест VoiceOver «назад»; фокус — на «Закрыть» при показе и обратно на вход (или `returnFocus` хоста) после закрытия. `entry: false` — без входа: хост открывает `core.open('corner')` сам.
- **Что внутри.** Комната в единицах 400×250 (стена, окно, пол, место отдыха и вещи ступеней штатного уголка — по `items.list` определения и ступени снимка, миска — когда можно угостить и после, корм — пока питомец ест) и питомец по `size` определения в рамке `room.frame` (масштаб ядра), на месте `room.pos.rest`, поза — `pose.shown.page`, поза «ест» идёт к миске на сдвиг `room.feedShift`; свои вещи набора — на местах `room.pos`. «Погладить» (`interact({ type: 'pet' })`), «Дай лапу» у питомца с `actions.paw.ask`, кормление по `treat` снимка (решение — `feed()` ядра, отказ — его текст), счёт, ступени и подарки, праздник новой ступени и «Новое в уголке» — по эффектам `celebrate` и `seen` показанного питомца, пришедшим при открытом уголке (иначе `progress.unseen`), выбор питомца, облик, имя (готовые — подборкой `names.presets`, предложение — пока имя не выбирали, своё — с клавиатуры, до 24 знаков; фокус поля — тишина ввода `setContext({ typing })`, снимается при закрытии и смене ядра — вместе с фокусом поля), аксессуары (закрытые ступенью — недоступны с подсказкой), движение и реплики, состояние записи (`save`). Черновик имени, страница готовых имён, отказ и «Новое в уголке» принадлежат паре «ядро и показанный питомец»: смена питомца (кнопкой или командой ядра, даже туда и обратно в одном такте) или ядра их снимает — вернувшись к прежнему питомцу или ядру без «Сохранить имя», поле показывает его сохранённое имя; обработчик прежней пары (устаревшее нажатие) ничего не пишет и не применяет. Правил в отображении нет. **С PL10.2.2:** «Поиграть» у сцены — только когда вид `'play'` объявлен (подключён годный `PetPlay`), `core.open('play')`; возврат из игры — фокус на «Поиграть»; переход в игру снимает тишину ввода и поле имени (черновик не переносится). «Присутствие» — «Всегда рядом» / «Приходит по зову» (`core.setPresence`, ключ `presence`), «Скрыть <кого>» — `core.hide()` (окно закрывает ядро, объявление «… спрятан. Вернуть — «Показать …»»); спрятан — вместо входа «Показать <кого>» (`core.show()`; по зову — снова вызов, игра сама не открывается). «Обустроить уголок» — PL10.2.3, кнопки нет.
- **Раскладка.** По `onLayout`: портрет — сцена в прокрутке под заголовком, широкий экран — сцена слева, настройки справа; закреплена только «Закрыть», заголовок с длинным именем и крупный системный текст прокручиваются. `insets` (`{ top, right, bottom, left }`, точки) — отступы безопасной области **от хоста** (библиотека не зависит от пакета безопасных областей); с ними окно на Android — сквозное (под строкой состояния и полосой жестов), без них — системные отступы окна. iOS-окно — `overFullScreen`: экран хоста остаётся под ним и пересчитывает свои `insets` при повороте. Клавиатура: отступ снизу по её рамке и прокрутка к строке поля имени. Анимация окна — `slide`, при «спокойном» движении `fade`, без движения (выбор владельца или системное «уменьшить движение») — `none`; движение питомца — как у `PetView`.
- **Ресурсы уголка набора** (`NativePetKit`, необязательные — их требует только `PetCorner`): `room: true` — `Figure` рисует и в сцене комнаты: свойство рисунка `room: { feed }` — без своей миски, поза `feed` со сдвигом `feed` (`room.feedShift`, единицы рисунка); `items` — свои вещи комнаты (игрушки `room.toys` определения и вещи ступеней вне общего уголка — подушки, лежанки, кружки, блокнота, лампы, растения, доски); `Item({ id, prefix })` — чистая функция: элементы `react-native-svg` вещи в единицах сцены 400×250 на её исходном месте. Проверка — против переданного определения того же ID (изменённые игрушки и вещи), место отдыха — `cushion` или `bed`; не хватает ресурса — «Уголок не показан: …» с ролью `alert`, вид `'corner'` ядру не объявляется (`open('corner')` — `unsupported`). Набор PL10.1 без этих полей по-прежнему подходит `PetView`.
- **Сценки** этим срезом не рисуются: координатор объявляет `scenes: {}` — ни резервирования дня, ни показа.
- **Окно одно на ядро** (PL10.2.2): iOS не показывает новое модальное окно, пока прежнее уходит, — уголок и игра показывают окно по очереди (iOS — после `onDismiss` прежнего, Android — сразу).

### Поиграть и «по зову» (PetPlay)

> **Не выпущено (этап PL10.2.2).** Проверено в Node, в iOS Simulator и в Android-эмуляторе настоящим вводом (XCUITest, `adb input motionevent`; `examples/expo/README.md`, «Проверка PL10.2.2»); на физических телефонах — нет. Отмена жеста при потере фокуса окна Android (шторка) — не закрыта (ниже, «Ограничения»).

```jsx
<PetProvider core={core} pets={pets} kits={[catNative, dogNative]}>
  <PetView size={200} />
  <PetCorner insets={insets} />
  <PetPlay insets={insets} />
</PetProvider>
```

- **`PetPlay({ insets?, entry?, label?, hint?, returnFocus?, testID?, style? })`** — только внутри `PetProvider`; подключённый `PetPlay` с годными наборами объявляет ядру вид `'play'`. Окно (`Modal`) открыто ровно тогда, когда в снимке `view.open === 'play'`: кнопка «Поиграть» уголка, вход вызова, прямая команда хоста — одним путём, своего флага нет. **Назад** — «Закрыть», Android «Назад» (только пока окно открыто), жест VoiceOver «назад»: игра, открытая из уголка (`view.source === 'pet'`), — `core.open('corner')`, следующий «Назад» закрывает уголок; вызванная «по зову» или без поверхности уголка — `core.close()`, окно закрыто целиком. У вызванной ещё «Уголок» — `core.open('corner')` (источник `call` сохраняется до закрытия). Прямой `core.close()` закрывает всё; уголок сам не открывается. Фокус: при показе — «Закрыть», после закрытия целиком — вход вызова (по зову), вход уголка или `returnFocus` хоста.
- **«Приходит по зову».** Присутствие `on-call` (уголок или `core.setPresence('on-call')`): `PetView` не рисует питомца, вход уголка скрыт, `PetPlay` показывает вход «Позвать <кого>» (доступное имя «Позвать питомца: <имя>», `entry: false` — без входа, хост зовёт сам) → `core.open('play', { source: 'call' })`: сразу игра. `hide()` закрывает вид и снимает вход; `show()` возвращает вызов, игру не открывает. Присутствие хранится ядром (холодный перезапуск — то же). Открытие, вызов и закрытие знаков не добавляют и дня сценки не расходуют.
- **Что рисует — только снимок.** Питомец по `size` определения в позе `pose.shown.play` (удержание довольной позы между откликами, реакции, лимит — ядро); миска и мячик — `play.drag.at` при переносе, иначе `play.toys.*.at` (единицы рисунка; движение действия — плавно, по той же кривой, что `Animated`; перестановка из-за раскладки или пола — сразу; без движения — сразу; уже начатое движение снимается «уменьшить движение» системы или `motion: 'none'`, фоном (`AppState` или `setVisible(false)` хоста), закрытием и уходом окна, нулевой раскладкой, отключением, сменой ядра и размонтированием — предмет сразу на месте снимка, после возврата прежнее движение не доигрывается; движение своё, пока идёт хоть одна его координата: отклики «закончилась» x и y приходят порознь, и закончившаяся не снимает движение другой; катящийся предмет берут там, где он нарисован — идущая координата по кривой, закончившаяся на цели); итог — `play.outcome` / `play.text` вместо подсказки «Проведи по питомцу, чтобы погладить» в строке постоянной высоты (по самому длинному из текстов ядра) — смена итога и реплики не сдвигает питомца под пальцем. Кнопки «Погладить», «Коснуться лапы» / «Дай лапу» (`actions.paw.ask`; без лапы — нет), «Подвинуть миску» / «Вернуть миску» (по `play.toys.bowl.home`), «Катнуть мячик» — `interact()` с теми же правилами ядра; кнопка во время жеста сначала снимает жест.
- **Касания** — распознавание отображения (`pet/native/gesture.mjs`), смысл — ядро. Голова и тело (`play.hits` определения) — `stroke.start` → `stroke.step` на каждые 24 точки от начала или прошлого отклика → `stroke.end` (отпустили) или `stroke.cancel` (ушёл с питомца, отмена); касание без сдвига — не поглаживание (подсказка выделяется). Лапа (`play.paw`, у поднятой в позе `paw` — `play.paw.up`; область не меньше 22 точек радиусом) — короткое касание (не дольше 500 мс и не дальше 10 точек, отпустили на лапе) → `interact({ type: 'paw' })` на отпускание. Миска и мячик (область не меньше 44 точек) — `toy.drag` с места, где предмет нарисован сейчас (катящийся мячик берут там, где его видно), сдвиг пальца — относительно него; перенос — от 6 точек; миска — `toy.drop()` после заметного сдвига, мячик — бросок от 16 точек по горизонтали `toy.drop({ roll })` в единицах рисунка (докат и пределы — ядро), иначе `toy.cancel()`; простое касание мячика не катит. Пороги — точки экрана React Native (значения — как CSS px веба 0.1.4). Один жест на ядро (свой палец по `identifier`: второй палец не перехватывает и не завершает).
- **Отмены** — локально и ядру: система забрала касание (`onResponderTerminate`, в том числе системный жест «Назад» у края экрана Android), iOS «неактивно» и фон, Android `blur` (если система его доставляет), смена раскладки сцены (поворот, размер окна), кнопка во время жеста, закрытие окна, смена ядра и размонтирование; смену питомца, модели, облика, вида, присутствия и видимости ядро снимает само — отображение только отпускает свой жест. Снятый жест «мёртв» до отпускания пальца: позднее движение и отпускание ничего не вызывают (ни лапы, ни броска). **Система:** отпускания после прерывания может не быть, поэтому неактивно, фон и `blur` во время жеста снимают его сразу (ядру — отмена, замок ядра отпущен), а не ждут отпускания; пока приложение неактивно или в фоне, новые жесты не начинаются до `AppState` `active`, после `blur` во время жеста — до `focus`; после возврата новый палец начинает жест без закрытия игры — и через `onResponderGrant`, и через `onResponderStart` (сцена остаётся ответчиком React Native, если прежнее касание так и не завершилось). `blur` без жеста ввод не приостанавливает: в React Native Android `blur` / `focus` — фокус окна Activity, а окно игры (`Modal`) само забирает этот фокус при показе. Поздние движение, отпускание и `onResponderTerminate` прежнего касания новый жест не ведут и не завершают (палец по `identifier`, событие старше начала жеста по `timestamp` — от прежнего касания). Жизненный цикл ядра — по-прежнему `useNativeLifecycle` у хоста; `PetPlay` слушает `AppState` только для своего ввода и предметов (окно, открытое при неактивном приложении, ждёт `active`).
- **Устаревшие обработчики.** Кнопки и окно игры, вход «Позвать …», отказ и подсказка «проведи», отложенный возврат фокуса принадлежат сеансу показа — ядру, показанному питомцу, открытому виду и его источнику; сеанс сверяется по каждому обновлению ядра. Прежний обработчик после смены питомца (в том числе кот → собака → кот в одном такте), вида или ядра ничего не командует новому показу, не отменяет его жест, не навигирует и не переводит фокус; текущий вход вызова работает и из закрытого состояния. Прямые команды хоста `core.interact` / `open` / `close` — прежний контракт.
- **Единицы и пол.** Сцена меряется `onLayout`; питомец — 88 % ширины (не больше 440 точек) по свободной высоте, под ним полоса пола 20…64 точки и строка реплики. Пол ядру (`playFloor` — `[l, t, r, b]` в единицах рисунка, `playTouch` — радиус лапы 22 точки в единицах рисунка) объявляет координатор, когда замер устоялся (80 мс); нулевой, скрытый, неизмеренный или переходный замер (питомец уже 80 точек) пола не объявляет. Ядро снять пол не умеет, поэтому предметы — пальцем и кнопками — доступны, только пока в снимке пол именно этой сцены; новое ядро получает только свежий замер.
- **Раскладка и доступность.** Портрет: «Закрыть» (и «Уголок» у вызванной), имя и строка итога над сценой, кнопки — под ней (по две в ряд, область ≥ 48 точек); если имя и итог выше четверти окна (крупный системный текст, длинное имя), они уходят под сцену в прокрутку вместе с кнопками — сцена вне прокрутки. Широкий экран — сцена слева, колонка справа. `insets` — как у уголка. Реплика — не крупнее 1,5 системного размера. Сцена для скринридера — изображение с описанием и подсказкой, рисунки скрыты; кнопки — роль, подпись, состояние; объявления — эффекты ядра через координатор (по одному); отказ команды — текст ядра с ролью `alert`. Анимация окна — по `effectiveMotion` (`slide` / `fade` / `none`).
- **Ресурсы игры набора** (`play: true`; необязательное, требует только `PetPlay`): рисунок совпадает с областями `play` определения (голова и тело, лапа, поднятая лапа); проверка — пробный рисунок каждой позы сцены (обязательных по роли и лапы, если она есть, позы предметов — ещё и с поворотом `toward` влево и вправо) против переданного определения того же ID. Нет ресурса — «Игра не показана: …» с ролью `alert`, вид `'play'` ядру не объявляется (`open('play')` — `unsupported`), кнопки «Поиграть» в уголке нет. Своё определение другого размера без лапы — свои области и пол, кнопки лапы нет.
- **Ограничения.** (1) **Android, потеря фокуса окна** (шторка уведомлений, «Недавние», ассистент) во время жеста: в Expo Go 58 `AppState` `blur` в JavaScript не приходит, система касание не отменяет — жест продолжается под шторкой, отпускание даёт результат (проверено в Android-эмуляторе, `examples/expo/README.md`). В собственной сборке `blur` отражает фокус окна Activity, а окно игры — `Modal` (отдельное окно Dialog), поэтому и там при открытой игре событие не придёт (окно игры само забирает фокус Activity при показе); закрыть критерий можно только решением владельца о собственной сборке и способе доставки (ARCHITECTURE.md § 14.1.12). Если `blur` доставлен во время жеста, `PetPlay` жест снимает и ждёт `focus` (проверено в Node). Отменяют (проверено): «Домой» на Android, iOS «неактивно» и фон (другое приложение, Настройки), системный жест «Назад». **«Недавние» на Android** (эмулятор, Android 16, Expo Go 58, 18.10.2026) — как шторка: фокус окна у системы, `AppState` не меняется, `blur` нет, отпускание под «Недавними» доходит до игры; звонок не проверялся. (2) У края экрана Android с жестовой навигацией жест, начатый у края (мячик у правого края пола), система забирает как «Назад» — перенос отменён, окно — «Назад»; бросить такой мячик — сначала «Катнуть мячик». (3) Физические телефоны, VoiceOver и TalkBack вживую — не проверены (PL10.2.4 и родительский PL10).

## Файлы пакета без сборщика (manifest.json)

> **Не выпущено (этап PL08)** — как разделы выше.

Сервер без сборщика отдаёт файлы пакета как есть. Какие именно — говорит перечень `pet-companion/manifest.json` (файл `manifest.json` в корне пакета, рядом с `package.json`): держать свой список внутренних файлов не нужно, при обновлении пакета перечень обновляется вместе с ним. Имена внутренних файлов — не интерфейс и меняются между версиями; интерфейс — сам перечень.

```json
{
  "schema": 1,
  "name": "pet-companion",
  "version": "0.1.4",
  "entries": {
    "./web": {
      "module": "pet/web.mjs",
      "styles": [],
      "peers": {},
      "files": ["pet/cat-art.mjs", "pet/core/catalog.mjs", "…", "pet/web/view.css", "pet/web/view.mjs"]
    }
  }
}
```

| Поле | Что |
| --- | --- |
| `schema` | версия формата перечня (`1`). Новые поля добавляются совместимо; несовместимый формат — новый номер |
| `name`, `version` | пакет и его версия (та же, что в `package.json` и `VERSION`) |
| `entries` | входы пакета с кодом — ключи как в `exports`: `"."` (`mountPet`), `"./core"`, `"./pets"`, `"./behaviors"`, `"./web"`, `"./react"` |
| `module` | файл входа от корня пакета — его импортирует страница без сборщика |
| `files` | все файлы, которые нужно отдавать для входа, от корня пакета: сам вход, модули, которые он загружает, и стили, которые подключает вид в контейнере. По алфавиту, без повторов, без типов и документов |
| `styles` | стили, которые подключает сама страница, — `{ file, required }` в порядке каскада; только у `"."`: `pet-base.css` (`required: false` — по желанию, раздел «Стили»), `pet.css`, `dog.css`. Контейнер (`/web`, `/react`) подключает свои стили сам — у него `styles` пуст, файлы стилей — в `files` |
| `peers` | пакеты сайта, которые вход импортирует по имени, и их диапазон: у `"./react"` — `react`; странице нужен способ их найти (сборщик или карта импортов), в `files` их нет. У остальных входов — `{}` |

Перечень производный — его собирает `scripts/manifest.mjs` репозитория по импортам и адресам стилей, а проверки пакета сверяют его с самим архивом и загрузкой в браузере (CONTRIBUTING.md). Копирование по перечню — скрипт сайта (пример — `examples/manifest/copy.mjs` репозитория):

```js
// Файлы питомца для сайта без сборщика — по перечню пакета (manifest.json): только файлы выбранных входов, с той же
// структурой папок. Положите скрипт в проект рядом с node_modules/ и запускайте после установки или обновления пакета:
//   node copy-pet.mjs public/vendor/pet-companion ./web
import { copyFile, mkdir, readFile } from 'node:fs/promises';
import path from 'node:path';
import { fileURLToPath } from 'node:url';

const [target = 'public/vendor/pet-companion', ...entries] = process.argv.slice(2);
const manifestFile = fileURLToPath(import.meta.resolve('pet-companion/manifest.json'));
const manifest = JSON.parse(await readFile(manifestFile, 'utf8'));
const files = new Set();
for (const entry of entries.length ? entries : ['./web']) {
  if (!manifest.entries[entry]) throw new Error(`pet-companion: нет входа ${entry}`);
  for (const file of manifest.entries[entry].files) files.add(file);
}
for (const file of files) {
  await mkdir(path.dirname(path.join(target, file)), { recursive: true });
  await copyFile(path.join(path.dirname(manifestFile), file), path.join(target, file));
}
console.log(`pet-companion ${manifest.version}: ${files.size} файлов → ${target}`);
```

Страница импортирует вход по пути: папка копии + `module` — `import { mountPetIn } from './vendor/pet-companion/pet/web.mjs'`; для `mountPet` — `pet/pet.mjs` и стили `<link>` в порядке `styles`. Пакет можно положить под любым вложенным адресом: модули загружают друг друга относительными путями. Сервер, который отдаёт файлы прямо из `node_modules/pet-companion/`, может разрешать только пути из `files` нужных входов — остальное `node_modules` наружу не открывается. Встроенных скриптов и стилей нет — страница работает и под строгим CSP. Примеры — `examples/manifest/` репозитория: `index.html` (контейнер, `./web`) и `legacy.html` (`mountPet`, `"."`). Вход `./react` без сборщика не поддерживается (раздел «React и серверный рендер»).

Методы и свойства `pet`:

| Метод | Что |

Другие экспорты `pet/pet.mjs`:

| Экспорт | Что |
| --- | --- |
| `VERSION` | версия модуля — та же, что у пакета |
| `localDay(date?)` | местная дата `'ГГГГ-ММ-ДД'` (часовой пояс браузера) — граница дня, по которой модуль открывает лакомство и считает сценки. Сайт считает `progress().today` и `first` по этой же дате: например, «знаки, у которых `localDay(new Date(время)) === localDay()`» |

Ошибки внутри модуля после подключения сайту не мешают: методы и обработчики перехватывают их (`console.warn('Питомец:', …)`).

## Что передаёт сайт и когда

- **Знаки** — `progress()`: сайт сам решает, какое действие даёт знак, и отдаёт счёт по запросу. Ступени питомца (0, 3, 9, 18, 30 знаков) и лакомство дня (`today > 0`) модуль считает по этим числам; «сегодня» — местная дата (`localDay`).
- **Подтверждённое занятие** — `pet.notify('saved', { key, counted, hard, first })` после того, как сайт сохранил действие и уже учёл его в своём счёте: `progress().marks` в этот момент **уже включает** этот знак (модуль считает «до занятия» как `marks − 1`, если `counted`). Порядок: сохранить → обновить счёт сайта → `notify('saved', …)`.
  - `key` — постоянный id события (запись, урок): повтор того же `key` в этом подключении не играет реакцию дважды. После перезагрузки или нового `mountPet` учёт `key` начинается заново, но праздник ступени не повторяется — увиденная ступень хранится (`<ns>:cat:v1`, `seenStage`). Событие, пришедшее, пока питомец спрятан или «по зову» и закрыт, не учитывается: после «Показать» тот же `key` даст реакцию. **Ограничение выпущенной 0.1.4:** «Скрыть» тоже начинает учёт заново (после «Показать» повтор прежнего `key` снова даст радость), забывает тишину, переданную до этого через `update({ timer, dictation, dialog })` (она снова действует со следующего такого вызова), и паузы повторов (ожидание после `failed` — 10 с, отклик на готовое имя — 4 с, приветствие нового напарника — 6 с). В исходниках репозитория (не выпущено, этап PL04.1) это исправлено: учтённые события, тишина и паузы повторов живут до отключения экземпляра (`destroy` или новый `mountPet`), «Скрыть» и «Показать» их не трогают;
  - `counted` — действие дало знак (может открыть ступень — праздник и новая вещь);
  - `hard` — трудное действие: поддержка вместо радости;
  - `first` — первое занятие дня: радость подсказывает про миску (лакомство дня).
  - `detail = null` — сохранённое действие не занятие: только перечитать числа.
  - Пока питомец спрятан или «Приходит по зову» и закрыт, событие только обновляет числа: без реакций, праздника и сценки (новую ступень покажет уголок).
- **Ошибка сохранения** — `pet.notify('failed')`: нейтральное ожидание без награды; знаки сайт не меняет, ошибку пользователю показывает сайт. Если сохранение затем удалось — обычный `notify('saved', …)`.
- **Изменение чисел или шага без события** (другое устройство, синхронизация) — `pet.update()`.
- **Состояние страницы** — `pet.update({ focus, timer, dictation, dialog })` при смене экрана, таймера, диктовки или открытии важного диалога сайта.
- **Переход по сайту** — `pet.close({ restore: false })`, если уголок должен закрыться вместе со сменой экрана.

## Команды и состояние

> **Не выпущено (этап PL05).** Есть только в исходниках репозитория после 0.1.4; пакет `pet-companion@0.1.4` из npm и архив выпуска этого не содержат. Чтобы попробовать до выпуска: в корне исходников `npm pack` — архив `pet-companion-0.1.4.tgz` с невыпущенными изменениями (номер в нём ещё прежний, но это **не** опубликованный выпуск 0.1.4 — не смешивайте), в своём проекте — `npm install <путь>/pet-companion-0.1.4.tgz`. Интерфейс может уточниться до выпуска.

Сайт управляет питомцем программно — без нажатий на кнопки уголка. Кнопки питомца и команды идут через одни и те же правила ядра, и интерфейс показывает итог команды сразу: имя, облик, кормление, открытый вид, расстановка — без клика, `update()` и правок разметки сайтом.

| Метод | Что |
| --- | --- |

Уже показанный — `changed: false`, `reacted: false`, без записи. Питомец, которого отображение не рисует, — `unsupported` |
| `pet.setBehavior(id)` | модель поведения (PL06): `'calm'` или ID зарегистрированной; реакции, реплики, тайминги, лимит и сценки — по ней; текущая реакция, облако, попытка сценки и жест снимаются; учёт событий, паузы, лимиты, лакомство и день сценки — общие (раздел «Питомцы и модели поведения») |
| `pet.setAppearance({ coat?, accessory? })` | облик (`smoke`, `ginger`, `tuxedo` у кота; `caramel`, `spotted`, `blacktan` у собаки; у своего питомца — его облики) и аксессуар (`scarf`, `plaid`, `badge` — открывается ступенью, иначе `locked`); два ключа — итог может быть `partial` |

| `pet.setPresence('always' \| 'on-call')`, `pet.hide()`, `pet.show()` | присутствие, «Скрыть», «Показать» |
| `pet.feed()` | лакомство дня (сегодня было занятие — `progress().today > 0`) |
| `pet.refresh()` | перечитать `progress()` (как `update()`, но с результатом) |
| `pet.setContext({ focus?, timer?, dictation?, dialog?, typing? })` | состояние страницы с результатом (как `update(flags)`) |

| `pet.room.select(id)`, `.move(id, [x, y])`, `.nudge('left' \| 'right' \| 'up' \| 'down')`, `.reset()`, `.drag(id, [x, y])`, `.drop()`, `.dragCancel()`, `.save()`, `.cancel()` | «Обустроить уголок» (единицы сцены 400×250; только в открытом редакторе — `pet.core.open('room')`) |
| `pet.getState()` | снимок (ниже); `null` при отказе подключения |
| `pet.subscribe(listener, { initial? })` | подписка (ниже); возвращает отписку |
| `pet.core.open('corner' \| 'play' \| 'room', { source? })`, `pet.core.close()` | открыть, сменить и закрыть вид — диалог открывается, фокус и блокировка прокрутки — как кнопкой; `source: 'call'` — вызов «по зову» (только `'play'`). `pet.core.close()` возвращает фокус и прокрутку, как `pet.close()` |
| `pet.core.notify('saved', { key, counted?, hard?, first? } \| null)`, `pet.core.notify('failed')` | подтверждённое занятие с результатом: `key` — **непустая строка**, лишние поля — ошибка; результат — ещё `reacted`, `duplicate`, `celebrate`, `fresh` |

Совпавшие по имени `update`, `notify`, `open`, `close`, `destroy` — прежние методы `mountPet` (возвращают `undefined`, `notify('saved', {})` без `key` работает как в 0.1.4). Входы отображения `setVisible`, `setReducedMotion`, `activity`, `setDisplay` есть только у `pet.core` — у подключения `mountPet` их ведёт само отображение. Методы не зависят от `this`: их можно передавать отдельно. Прежний экземпляр после нового `mountPet` или отключения отвечает `destroyed` и новый не трогает.

**Результат команды.** Успех — `{ ok: true, changed, save, ...поля команды }`: изменение действует сразу; `changed` — изменилось ли состояние; поля команды есть в каждом успехе, и без изменений. `degraded: true` — только если после изменения отказала оркестровка: планировщик или исключение порта часов, случайности (изменение и запись остались, эффект `warning`; поля команды — без несостоявшейся реакции и итога). Отказ — `{ ok: false, error: { code, message } }`: команда ничего не изменила и не записала. Команды не бросают исключений.

| Код | Когда |
| --- | --- |
| `invalid-argument` | неверный тип или значение (в том числе событие без `key`) |
| `unknown-id` | неизвестный питомец, модель поведения, облик, аксессуар или предмет комнаты |
| `unsupported` | отображение не объявило вид или не рисует питомца; лапы у питомца нет (`actions.paw: null`); у кота вне «Поиграть» нет «Дай лапу»; пол «Поиграть» не объявлен |
| `locked` | аксессуар ещё не открыт ступенью |
| `hidden` / `away` | питомец спрятан / «по зову» и не вызван |
| `not-open` | комната вне редактора, жест и предметы вне «Поиграть» |
| `no-gesture` | `stroke.step(id)` для жеста, который уже не идёт |
| `treat-waiting` / `treat-fed` | сегодня ещё не было занятия / уже угостили |
| `already-started`, `reentrant`, `destroyed`, `internal` | повторный `start()`; команда из порта или `progress()` во время другого вызова; экземпляр отключён; внутренний сбой до изменения |

**Сохранение** — `save`: `{ status, keys, results, done? }`. `status`: `none` — писать нечего; `saved` — записано; `failed` — не записалось (правка действует до перезагрузки и уходит со следующей правкой того же ключа, скрытых повторов нет); `partial` — у команды с двумя ключами (`setAppearance`) один записан, другой нет (транзакции между ключами нет); `pending` — асинхронное хранилище приняло запись в очередь, итог — обещание `done` (`saved`, `failed`, `partial`; никогда не отклоняется, разрешается и после `destroy`). Браузерное хранилище `mountPet` синхронно: итог окончательный в том же вызове, `pending` не бывает.

**Снимок** — `getState()`: глубоко замороженный объект из простых данных; тот же объект, пока ничего не изменилось (подходит для `useSyncExternalStore`). Поля: `status`, `storage`, `pet` (`id` — выбранный, `shown` — показанный, `available` — зарегистрирован ли), `behavior` (то же для модели поведения, PL06), `name` (`value`, `chosen`, `display`), `look`, `pets` (имя, облик и аксессуар каждого зарегистрированного питомца), `prefs`, `presence` (`mode`, `hidden`, `surface`, `around`), `view` (`open`, `source`), `display`, `scene`, `visible`, `context`, `pose` (`base`, `resting`, `hold`, `shown.page/play/room`, `reaction`), `phrase`, `scenePhrase`, `play`, `room` (`pos`, `feedShift`, `draft`), `progress` (`null` до первого чтения счёта), `treat`, `save` (по ключам: `status`, `pending`, `unsaved`, `corrupt`). Объекты сайта не замораживаются и в снимок не попадают.

**Подписка** — `subscribe(listener, { initial = true })`: сразу текущий снимок (`reason: 'initial'`), затем одно обновление `{ snapshot, effects, reason }` на каждую фазу изменений; `reason` — имя команды, `'storage'` (другая вкладка), `'save'` (поздний итог записи), имя задачи (`'reaction'`, `'midnight'` …), `'destroyed'` — последнее. Эффекты — одноразовые события: `announce` (текст для скринридера), `celebrate` (новая ступень), `seen` (вещи ступени, увиденной в уголке), `micro`, `arrive`, `save`, `warning`. Команда, вызванная из слушателя, выполняется сразу; `getState()` в слушателе может быть новее переданного снимка. Исключение слушателя не мешает остальным и до команды не доходит.

```js
import { mountPet } from 'pet-companion';

const pet = mountPet({ storage: 'mysite', places, progress });
const off = pet.subscribe(({ snapshot, effects, reason }) => {
  badge.textContent = snapshot.treat === 'ready' ? 'Можно угостить' : '';
});
const named = pet.setName('Пиксель');
if (named.ok && named.save.status === 'failed') toast('Имя не сохранилось в этом браузере — действует до перезагрузки.');
const fed = pet.feed();
if (!fed.ok && fed.error.code === 'treat-waiting') hint('Одно занятие — и можно угостить.');
pet.core.open('room');
pet.room.move('bowl', [120, 230]);
pet.room.save(); // уголок с «Расстановка сохранена.»
off();
pet.core.destroy(); // то же, что pet.destroy()
```

## Ядро без отображения

> **Не выпущено (этап PL05)** — как раздел выше.

Вход `pet-companion/core` — то же ядро без DOM и браузера (Node, своё приложение, страница со своим отображением): `createPetCore`, `createStorage`, `definePet`, `defineBehavior` (PL06), `PetError`, `localDay`, `VERSION`; типы — `pet/core.d.mts`. Штатные определения — входы `pet-companion/pets` и `pet-companion/behaviors` (PL06). Отображения у него нет: состояние — снимок и подписка, рисует вызывающий.

```js
import { calm } from 'pet-companion/behaviors';
import { createPetCore, createStorage } from 'pet-companion/core';
import { cat, dog } from 'pet-companion/pets';

const data = new Map(); // своё хранилище: Map, файл, база
const storage = createStorage({
  namespace: 'myapp',
  backend: { get: (name) => data.get(name) ?? null, set: (name, text) => data.set(name, text) },
});
storage.load(); // 'ready' | 'failed' (failed — работает без записи)

const pet = createPetCore({ storage, pets: [cat, dog], behaviors: [calm], progress: () => ({ marks, today }) });
pet.subscribe(({ snapshot, effects }) => render(snapshot, effects));
pet.start();
pet.notify('saved', { key: `lesson-${id}`, counted: true });
```

- **Хранилище** — `createStorage({ backend, namespace })`: координатор над вашим хранилищем ключ-значение (имена — `<namespace>:<ключ>:v1`, форматы — как у браузера, раздел «Хранение»). Синхронный `backend` (`get`, `set` в том же вызове) или асинхронный — `{ async: true, get, set }` с обещаниями: тогда `await storage.load()`, а запись — `pending` с `done`. Один `backend` и `namespace` — один координатор, общий для всех ядер на нём: очередь записи по ключу, каждое ядро — своё подключение (правка одного приходит другим обновлением `'storage'`). Перед каждым новым ядром — `load()` (барьер: дожидается записей прежнего). Подключения создаёт само ядро.
- **Создание** — `createPetCore(options)` синхронно; неверные настройки — исключение `PetError` (`code`: `invalid-options`, `storage-not-loaded`; для определений — `definition-invalid` с `path`, `duplicate-id`, `unsupported-format`) до подключения к хранилищу. Настройки: `storage` (обязательна, из `createStorage`, загружена), `pets` и `behaviors` (обязательны с PL06: непустые списки определений — раздел «Питомцы и модели поведения»), `progress`, порты `clock` (`now`, `day`, `nextDay`), `random`, `scheduler` (`later(ms, task)` → отмена), `log` (`warn`) — по умолчанию системные; `scenes` — резервирование дня редкой сценки (`reserve(decide, show)`; без него сценок нет). При создании — ни записи, ни таймеров, ни вызовов слушателей; `start()` — один раз: первое включение, приветствие дня, покой и полночь (`already-started` при повторе). До `start()` команды меняют состояние без реакций.
- **Что умеет отображение** — `setDisplay({ views, pets, scenes, full, moving, playFloor, playTouch })`: без объявленных видов `open` отвечает `unsupported`, без `scenes` редких сценок нет, без `playFloor` предметов «Поиграть» нет. Переданное свойство заменяет прежнее целиком, непереданное сохраняется. Массивы — плотные, строка в каждом индексе: пустой индекс (`['corner', , 'room']`), `undefined`, `null` — `invalid-argument`, объявление прежнее целиком. Объявленное надо нарисовать самому — ядро рисунков не даёт.
- **Отключение** — `destroy()`: синхронно, повторно — ничего; задачи, жест, перенос, черновик и подписки сняты (слушатели получают последнее `'destroyed'`), подключение к хранилищу закрыто; уже принятые записи выполняются, их `done` сообщает итог. Дальше команды — `destroyed`, `getState()` — тот же снимок `destroyed`, `subscribe` с `initial` — один вызов `'destroyed'`.
- **Своё веб-отображение** на тех же адаптерах, что у `mountPet` и `mountPetIn` (`createWebStorage`, `createWebScenes` входа `pet-companion/web`, PL07), — раздел «Питомец в контейнере».
- **React** (PL08, не выпущено) — `usePetState(core)` входа `pet-companion/react` работает и со своим ядром: передайте ему экземпляр `createPetCore` (раздел «React и серверный рендер»).
- **Пока нет:** мобильного хранилища и нативного отображения — это следующие этапы (раздел «Архитектура и будущий API»). Полные рабочие примеры для Node — `examples/core-node.mjs` (штатные кот, собака, `calm`) и `examples/extension/node.mjs` (свой питомец и своя модель) в репозитории.

## Питомцы и модели поведения

> **Не выпущено (этап PL06)** — только в исходниках репозитория, как разделы выше; опубликованный 0.1.4 этого не содержит.

Питомец (кто это и как выглядит) и модель поведения (как себя ведёт) — **определения формата 1**: только данные, без кода. Ядро исполняет их своими правилами, поэтому любая корректная модель совместима с любым корректным питомцем. Штатные — кот и собака (`pet-companion/pets`) и модель `calm` (`pet-companion/behaviors`): данные 0.1.4, поведение и вид прежние. Регистрация — на экземпляр ядра, глобального реестра нет.

```js
import { calm } from 'pet-companion/behaviors';
import { createPetCore, defineBehavior, definePet } from 'pet-companion/core';
import { cat, corner, dog } from 'pet-companion/pets';

const bunny = definePet({
  format: 1, id: 'example.bunny', fallback: 'cat', title: 'Кролик', /* forms, names, coats, accessories, items, size, play */
  poses: ['calm', 'attentive', 'rest', 'content', 'joy', 'pet', 'feed', 'sniff', 'hop'],
  poseFallback: { wait: 'attentive', support: 'calm', unlock: 'joy', greet: 'joy', fed: 'content', watch: 'attentive', ball: 'attentive' },
  actions: { pet: { text: '{name} шевелит носом.' }, paw: null }, // лапы нет
  scenes: [{ id: 'hop', pose: 'hop', needs: 'any', ms: 2500, still: 1500, text: 'прыгает на месте' }],
  room: { ...corner, pet: { /* рамки */ }, feed: [/* … */], toys: [{ id: 'carrot', /* … */ }] },
});
const lively = defineBehavior({ format: 1, id: 'example.lively', /* reactions, timings, phrases */ limits: { pet: 2 }, scenes: { chance: 0.15, order: 'random', skip: ['cat/curl'] } });

const pet = createPetCore({ storage, pets: [cat, dog, bunny], behaviors: [calm, lively] });
pet.setPet('example.bunny'); // save.keys: ['ext'] — выбор своего питомца
pet.setBehavior('example.lively');
pet.interact({ type: 'paw' }); // { ok: false, error: { code: 'unsupported' } }
```

- **Регистрация.** `createPetCore({ pets, behaviors })` — обязательные непустые списки (ID уникальны; первый питомец — запасной показ, первая модель — по умолчанию). `mountPet({ pets?, behaviors?, kits? })` — по умолчанию штатные. Ошибки — исключение `PetError` при создании (у `mountPet` — отказ подключения): `invalid-options` (не список, пустой список), `definition-invalid` с `path` — место дефекта (`pets[2].scenes[0].pose`, `behaviors[1].reactions.joy.ms`, `behaviors[1].phrases.byPet["example.bunny"].pet[0]` — ID с точкой в скобках), `duplicate-id`, `unsupported-format` (`format` — целое, но не 1). Слабые ссылки — реплики `byPet` или `skip` для питомца или сценки, которых в этом экземпляре нет, — регистрацию не останавливают: на каждую `log.warn`.
- **`definePet(def)`, `defineBehavior(def)`** — проверка и собственная глубоко неизменяемая копия: только собственные перечисляемые свойства-данные простых объектов и плотных массивов (функции, аксессоры, символы, пропуски массива, циклы — `definition-invalid`). Правка исходного объекта после проверки ничего не меняет. В `pets` и `behaviors` можно передать и непроверенные данные — ядро проверит их так же.
- **ID.** Штатные — `cat`, `dog`, `calm`; свои — с точкой: строчные латинские буквы, цифры и дефис (`example.bunny`, `mysite.fox`, `mysite.fox.big`). Внутри определения — локальные ID обликов, аксессуаров, вещей, игрушек и сценок (`snow`, `hop`); ссылка на сценку — `petId/sceneId`.
- **Питомец** (`PetDefinition` в `pet/core.d.mts`): `title`, `forms` (родительный и винительный), `names` (по умолчанию, подборка, предложение), `coats`, `accessories` (со ступенью), `items` (вещи ступеней и пять подарков), `poses` и `poseFallback`, `micro` и `openMicro`, `actions` (текст поглаживания; `paw: null` — лапы нет, иначе `{ text, ask }`: `ask` — «Дай лапу» и вне игры), `scenes` (`id`, `pose`, `needs: 'any' | 'full'` — `full` не показывается портретом, `ms` до 4600, `still`, `text`), `size`, `play` (области попадания, лапа, где стоит), `room` (общий уголок `corner` плюс рамки питомца и свои игрушки) и `fallback` — штатный питомец, которого покажут отображения без набора этого и вкладки прежних версий.
- **Словарь поз.** Обязательные `calm`, `attentive`, `rest`, `content`, `wait`, `joy`, `support`, `unlock`, `greet`, `pet`, `feed`, `fed`, `sniff`, `watch`, `ball` — в `poses` или заменой `poseFallback` (по цепочке, без циклов; `calm` — только в `poses`); `paw` — только у питомца с лапой; `yawn` и `settle` необязательны — нет позы, реакция для этого питомца не играет. Свои позы — только для своих сценок.
- **Модель** (`BehaviorDefinition`): `reactions` — обязательные (`wait`, `joy`, `support`, `unlock`, `greet`, `meet`, `named`, `pet`, `calmPet`, `feed`, `fed`, `sniff`, `watch`, `ball`), реакции лапы (`paw`, `calmPaw` — играют только у питомца с лапой), `yawn` и `settle` по желанию; поза — из словаря, длительность не больше 0.1.4, приоритет 3–7 (декоративные — 7), пауза повтора не меньше 0.1.4; `timings` — моргание и движения не чаще 0.1.4, шанс зевка до 0,18, облако реплики до 3,2 с; `limits.pet` — 1–3 полных отклика поглаживания в минуту; `scenes` — `chance` 0…0,25, `order` (`fresh` — не прошлый вариант этого питомца, `random`), `skip`; `phrases` — `default` покрывает группы реакций и ядра, `byPet[petId]` — замены групп для питомца. Модель может только сократить длительности, шанс и лимит, но не ускорить повторы.
- **Сценки пары** — пересечение: сценки питомца без `skip` модели, объявленные отображением (`setDisplay({ scenes })`), подходящие к показу (портрет — только `needs: 'any'`). Пустое пересечение или шанс 0 — попытка учтена, но ни случайности на выбор, ни резервирования, ни показа. Отображение без сценок (не объявило `scenes` или `{}`) — сценок нет ни у кого. День сценки — один на всех питомцев и модели.
- **Не зарегистрирован, не нарисован, не умеет.** Сохранён ID, которого в этом экземпляре нет (определение не подключили или убрали): в снимке `pet.id` — сохранённый, `available: false`, показан штатный питомец, записанный рядом с выбором, иначе первый из `pets`; выбор и данные (имя, облик, расстановка) не трогаются и вернутся вместе с определением. Модель — так же (показ — первая модель). Отображение не рисует питомца (`setDisplay({ pets })` без него, у `mountPet` — нет набора) — показан его `fallback`, `setPet` такого — `unsupported`. Лапы нет — `interact({ type: 'paw' })` отвечает `unsupported` без изменений.
- **Смена модели** — `setBehavior(id)`: запись `ext.behavior`; текущая и отложенная реакции, облако реплики, попытка сценки, жест и итог «Поиграть» снимаются, задачи покоя ставятся заново. Учёт событий, паузы повторов, лимит поглаживания, лакомство дня и день сценки — общие: смена модели и питомца их не сбрасывает.
- **Версии и ресурсы.** Формат 1 закрыт: неизвестное поле — `definition-invalid`, а новое поле — новая версия формата; определение с `format`, которого пакет не знает, отклоняется `unsupported-format`, а не толкуется частично. Поэтому определение формата 1 подходит ко всем версиям пакета, знающим формат 1. Ресурсы своего питомца (рисунок, стили, тексты) принадлежат автору расширения: определение, набор и CSS поставляет сайт, пакет их не загружает и сети не использует. Удалённых плагинов и исполняемого кода в определениях нет: определение — данные, набор — модуль сайта.

**Наборы отображения веба.** Определение — данные, рисует набор отображения: `{ pet, poses, scenes, coats, accessories, items, art(options), item(id, { fresh }), mini?(id) }`. `art({ id, view, coat, className, box, accessory })` возвращает строку `<svg class="cat-art …" data-kind data-view data-coat data-pose data-acc …>`: позу, облик и аксессуар показывают атрибуты, движения — CSS набора (`data-pose`, `data-scene`, `data-micro`). Кот и собака — встроенные наборы с прежними рисунками. Свой питомец — `mountPet({ pets: [cat, dog, bunny], behaviors: [calm, lively], kits: [bunnyWeb] })` и CSS набора на странице (его подключает сайт; сети модуль не использует). Набор проверяется до подключения: набор без определения или не нарисовавший обязательные позы, облики, аксессуары и свои вещи — отказ подключения (прежний питомец остаётся, ничего не записано). Обязательные позы — по роли: конечная поза (после замен `poseFallback`) каждой обязательной позы словаря и лапы, если она есть у питомца, — даже если её использует сценка и даже если это своя поза сценки или `yawn`/`settle`; необязательные сценки и позы набор может не рисовать. Встроенные наборы кота и собаки проверяются тем же правилом против переданных `pets`: изменённое определение `cat` или `dog`, которое встроенный набор не покрывает (например, новый облик), — отказ с подсказкой передать свой набор в `kits`. Необязательную позу, которой нет в наборе, отображение рисует базовой позой; сценки отображение объявляет по набору — те, что есть в определении (лишняя сценка набора не ошибка). Полный пример — папка `examples/extension/` репозитория (в пакет не входит): кролик без лапы и зевка со своей сценкой `hop` и «живая» модель — `index.html` для браузера (карта импортов на `node_modules`) и `node.mjs` для Node.

## Места

Модель мест фиксирована: компьютер — `logo` (портрет в шапке, запасное место; здесь же «Показать …», когда питомец спрятан), `sidebar` (боковая панель: целиком с именем и репликой или портретом), `float` (правый нижний угол окна); телефон (до 860 px) — `top` (кнопка в шапке, запасное место), `bar` (нижняя панель). Места, для которых сайт не передал функцию, не используются. «Показать …» после «Скрыть»: на компьютере — у логотипа; на телефоне — в `restore` (например, в меню сайта, ссылкой с классом `classes.link`), а без `restore` — лапкой 44×44 в месте `top`, на месте питомца. Фокус после «Скрыть» — на видимую «Показать …», иначе — `home()`.

Пороги окна совпадают с `pet.css` и не настраиваются: боковая панель целиком — от 880 px высоты, портретом — от 840; внизу экрана — целиком от 1180 px ширины, портретом от 1140; наверху телефона целиком — от 390 px; нижняя панель — портрет от 340 px, целиком от 480. Место и вид выбирает пользователь в уголке; «Автоматически» — боковая панель на высоком экране, иначе шапка. Модель — окно браузера, а не произвольный контейнер: питомца `mountPet` нельзя поставить внутрь блока с прокруткой как в отдельное окно. Питомец в блоке сайта — `mountPetIn` (раздел «Питомец в контейнере», не выпущено).

Элементы мест создаёт модуль (`#cat-dock`, `#cat-side`, `#cat-float`, `#cat-bar`, кнопка `.cat-face`), сайт только вставляет их — порядок Tab как на экране. Расположение внутри своих панелей (отступы, высота панели под питомцем) — правила сайта.

## Стили

Раздел — о `mountPet`: его стили подключает страница. Питомец в контейнере (`mountPetIn`) подключает стили сам, в своё теневое дерево; странице остаются только переменные темы (раздел «Питомец в контейнере»).

- **Обязательны** `pet.css` и `dog.css` (собаку пользователь может выбрать в уголке).
- **`pet-base.css`** — для сайта, у которого нет своих классов кнопок (`classes` не передан): вид кнопок `pet-*` и защита питомца от общих правил сайта по тегам — основа шрифта окна (16 px, системный шрифт), у заголовков окна — свой шрифт, начертание, цвет и высота строки, у кнопок и подписей — без `text-transform` и `letter-spacing` сайта, у кнопок — `min-width`, у полей — `margin` и размер шрифта браузера по умолчанию. Сайт со своими `classes` этот файл не подключает и защищает питомца от своих общих правил сам.
- **Порядок:** стили сайта → `pet-base.css` (если нужен) → `pet.css` → `dog.css` → переопределения темы сайта.
- **Тема** — переменные на `:root` (светлая и тёмная по `prefers-color-scheme`), сайт переопределяет нужные после `pet.css`: `--pet-bg`, `--pet-surface`, `--pet-surface-2`, `--pet-ink`, `--pet-ink-2`, `--pet-line`, `--pet-accent`, `--pet-accent-ink`, `--pet-accent-soft`, `--pet-warn`, `--pet-warn-soft`, `--pet-radius`. Комната уголка — `--cat-wall-top`, `--cat-wall`, `--cat-floor` и др. (там же).
- **Границы.** Правила модуля — только по классам `cat-*`, `pet-*`, `dog-*`, атрибутам `data-cat-*`, `data-pet-*`, `data-play-*`, `data-room-*`, id `cat-*` и отметкам на `<html>`; сайту не стоит использовать эти имена. Проверено: CSS модуля (все три файла) не меняет ни одного вычисленного свойства элементов сайта — и на сайте без своих стилей, и на сайте с общими правилами `button`, `input`, `h2`, `dialog`; с `pet-base.css` питомец под такими правилами выглядит так же, как без них. Не поддерживаются: правила сайта с классом или id над питомцем (`.content button`, `#app h2`), `!important`, `*`, правила для `svg`, `path`, `circle` — рисунки встроены в страницу как SVG и наследуют такие правила.

## Отметки на html, прокрутка, перенос

Модуль ставит на `<html>`: `data-pet-at`, `data-pet-view` (где и как показан), `data-pet-call` (лапка вызова), `data-pet-move` (перенос), `data-cat-motion` (режим движения), классы `cat-on`, `cat-paused` (скрытая вкладка), `cat-open`. Пока открыт диалог питомца (`cat-open`), прокрутка страницы заблокирована: `overflow: hidden` у `<html>`. Пока питомца тянут мышью (`data-pet-move="drag"`), у всей страницы курсор `grabbing`. Сайт может опираться на эти отметки в своих правилах. После `destroy()` и отказа подключения их нет. Питомец в контейнере (`mountPetIn`) отметок на `<html>` не ставит и прокрутку не блокирует — сайт делает это сам по `onOpenChange`.

## Хранение

Только `localStorage` и IndexedDB этого браузера — по источнику сайта (схема, домен, порт) и пространству имён `storage`; данных сайта модуль не меняет, запросов не делает. Синхронизации между устройствами и браузерами нет: на телефоне и компьютере настройки свои. Два сайта на одном источнике с одинаковым `storage` делят настройки; разные `storage` — независимы.

| Ключ | Формат | Что | Запись меняет |
| --- | --- | --- | --- |
| `<ns>:cat:v1` | `{ v, name, accessory, motion, phrases, hidden, seenStage, greetDay }` | общие настройки, имя и аксессуар кота | только изменённые поля |
| `<ns>:companion:v1` | `{ v, kind, dog: { name, accessory } }` | выбор животного, собака | `kind` или изменённые поля `dog` |
| `<ns>:look:v1` | `{ v, cat, dog }` (в исходниках, PL06, — и `[petId]` своих питомцев) | облик | облик одного животного |
| `<ns>:treat:v1` | `{ v, fedDay }` | день лакомства | `fedDay` |
| `<ns>:place:v1` | `{ v, desktop: { place, view }, phone: { place, view } }` | место и вид | изменённые поля одного устройства |
| `<ns>:presence:v1` | `{ v, mode }` | «Всегда рядом» / «Приходит по зову» | `mode` |
| `<ns>:scene:v1` | `{ v, day, by, cat }` (PL06 — ещё `variants: { [petId]: sceneId }`) | копия дня редкой сценки | `day`, `by`, у кота — `cat`, у других питомцев (PL06) — `variants[petId]` |
| `<ns>:room:v1` | `{ v, cat: { rest, bowl, yarn }, dog: { … } }` (PL06 — и `[petId]`) | расстановка комнаты | `x`, `y` передвинутых предметов показанного животного |
| `<ns>:ext:v1` | `{ v, pet?: { id, over }, behavior?, pets?: { [id]: { name, accessory } } }` | только в исходниках (PL06): выбор своего питомца, модель поведения, имя и аксессуар своих питомцев | `pet`, `behavior` или изменённые поля одного питомца |
| IndexedDB `<ns>:scene` | хранилище `scene`, запись `shown` | день показа сценки — одной транзакцией с началом показа | `day`, `by`, у кота — `cat` |

`v1` в ключе и `v` в значении — версия формата данных, а не модуля.

> **Что выпущено.** Гарантии этого раздела — исходный код репозитория после этапов PL02, PL03, PL04.2 и PL04.3: **локальные изменения, ещё не выпущены**. В опубликованном пакете 0.1.4 (npm и архив выпуска) запись прежняя: `cat` и `companion` пишутся нормализованными (только поля `v1`, `cat` — и приветствием дня), точка передвинутого предмета `room` — заново `{ x, y }`, на исходном месте удаляется целиком, запись `shown` заменяется целиком, непонятный облик другого животного в `look` и непонятные значения в `cat` и `companion` становятся значениями по умолчанию, `v` записывается как 1 (кроме `place` и `presence`), отказ чтения не отличается от пустого ключа. Исправление выйдет следующей версией.

**Показ и запись.** Показ — нормализованные значения: непонятное этой версии (облик, аксессуар, вид животного, место из более новой версии) показывается значением по умолчанию — кот, первый облик, обычный платок, место «не выбирали». Запись — свежее значение ключа, прочитанное прямо перед записью, как есть, плюс только поля, изменённые этим действием (по правилам проверки). Остальное остаётся на своём месте: поля, которых эта версия не знает, вложенные данные, непонятные значения известных полей, данные других и неизвестных животных и предметов. Правка имени не меняет аксессуар, облик и вид животного; движение и реплики — общие поля `cat`, `companion` они не трогают. Имя и аксессуар кота хранятся в `cat`, собаки — в `companion.dog`, облик и расстановка обоих — в `look` и `room`. Неизвестный вид в `companion.kind` (показывается котом) остаётся, пока не выберут кота или собаку. Номер `v` больше известного не уменьшается. Правка пишет только известные поля формата: произвольных данных сайта модуль не записывает.

**Чтение: четыре случая.**

- **Ключа нет** (`getItem` вернул `null`) — умолчания; запись разрешена: первое подключение и приветствие дня записывают свои поля как раньше.
- **Повреждено** — не JSON или не объект (пустая строка, массив, строка, число, `null`): умолчания и предупреждение `Питомец: значение <ключ> повреждено…` в консоли. Неявные записи — приветствие дня, первое включение, отметка увиденной ступени (при открытии уголка и после занятия), копия дня сценки — такое значение **не трогают**: их поля действуют в памяти страницы, подсказка в «Настройках» говорит, что сохранённое повреждено. Явное действие пользователя (имя, облик, аксессуар, движение, реплики, выбор животного, место и вид, присутствие, «Покормить», «Сохранить» расстановки, «Скрыть» и «Показать») **заменяет** повреждённое значение своего ключа записью из изменённых полей и полей из памяти: понятных данных в нём нет, остальное снова по умолчанию. Объект, в котором непонятно отдельное значение, повреждённым не считается.
- **Отказ чтения** при подключении (исключение `getItem` или самого доступа к `localStorage`) — экземпляр работает в памяти страницы: умолчания, правки до перезагрузки, подсказки «хранилище недоступно», сценок нет. В хранилище он **ничего не пишет** и больше не читает, даже если доступ вернулся в той же сессии; новая попытка — следующее подключение (перезагрузка, `mountPet`), и оно покажет сохранённое. Отказ чтения перед конкретной записью — эта запись не делается, правка остаётся в памяти, как при отказе записи.
- **Более новая совместимая схема** (`v` больше 1, новые поля) — понятые поля показываются, неизвестное и `v` при записи сохраняются. Несовместимый формат будущих версий будет в новом ключе (`:v2`), а не в преобразованном прежнем.

**Увиденная ступень** (`seenStage` в `cat` — до какой ступени новые вещи уже показаны и отпразднованы) только растёт. Если ключа или поля нет либо там `-1`, первое включение молча отмечает текущую ступень, без праздника прошлых. Значение, непонятное этой версии (больше её ступеней — из более новой версии, не целое число, другой тип), в валидном объекте сохраняется. Его не трогают первое включение, отметка при открытии уголка и праздник после занятия. Не трогают его и явные правки других полей, в том числе вместе с полями, оставшимися в памяти страницы после отказа записи или повреждения. Пока такое значение в хранилище, эта версия показывает вещи по знакам, без точки «новое», «Новое в уголке» и праздника новой ступени. Понятная сохранённая ступень правкой из памяти страницы не понижается. День приветствия (`greetDay`), наоборот, заменяемое поле: оно хранит только последний день, и приветствие записывает сегодняшний день поверх прежнего значения, в том числе непонятного этой версии.

**Отказ записи и переполнение.** `setItem` бросил исключение (переполнено, запрещено) — прочитанное не уничтожается; изменённые поля действуют на этой странице до перезагрузки и уходят со следующей удачной записью того же ключа; подсказки говорят «не сохранилось». «Сохранено» — только после успешной записи. День сценки — одна транзакция IndexedDB: отказ до показа — сценки нет, после начала показа — показ останавливается, день свободен.

**Границы замены.**

- Если правке нужна вложенная структура, а в хранилище на её месте не объект — `companion.dog` (имя или аксессуар собаки), `place.desktop` или `place.phone` (место или вид устройства), `room.<животное>` или точка предмета (передвинутый предмет), — заменяется только она, объектом с изменёнными полями.
- У передвинутого предмета меняются только `x` и `y`; на исходном месте у точки нет координат, прочие её поля остаются, пустая точка удаляется. «Сохранить» пишет только предметы, которые передвигали (переносом, кнопками, «Вернуть обычную расстановку»), и только если их место отличается от сохранённого: место, показанное вместо непонятного значения, правкой не считается. Предметы других животных, неизвестные предметы и предметы закрытых ступеней не переписываются.
- Выбор вида не закрепляет место, если в хранилище — место, непонятное этой версии.
- Запись дня сценки в IndexedDB, которая не объект, — не свободный день: сценки нет, запись не заменяется. Сценка собаки не меняет вариант кота ни в базе, ни в копии.

**Вкладки, версии, устройства.**

- Запись перечитывает ключ непосредственно перед записью: последовательные правки разных полей в двух вкладках не теряются, у одного поля побеждает последняя. Записи `localStorage` между вкладками не транзакционны: две записи одного ключа в одно мгновение могут потерять одну правку.
- Открытая вкладка прежней версии (0.1.4 и раньше) выполняет свой код и при своей записи может отбросить неизвестные поля `cat` и `companion`, поля внутри точек `room`, заменить непонятный облик другого животного и запись `shown`, понизить `v`. Новая версия этого не исправляет; после такой записи она сохраняет то, что осталось. Поэтому данные будущих версий размещаются в новых ключах (например, ключ расширений) или там, где их сохраняют и прежние версии.
- Обновлённые файлы модуля действуют только после перезагрузки страницы: уже открытая вкладка выполняет код, загруженный при её открытии.
- Синхронизации между устройствами и браузерами нет; ключа расширений в опубликованной 0.1.4 нет (в исходниках — `ext:v1`, ниже), миграций личных данных нет.

Другие вкладки того же сайта применяют изменения тихо (событие `storage`); редкая сценка не повторяется в другой вкладке. Отключение и отказ подключения сохранённого не удаляют.

**Как это устроено в исходниках (PL03, не выпущено).** Ключи `cat`, `companion`, `look`, `treat` читает и пишет только внутреннее ядро через общий координатор пространства имён: одна очередь на ключ, запись — свежее значение, прочитанное в том же вызове, и только изменённые поля; результат известен сразу, до объявления («не сохранилось» — честно). Решение принимается по сохранённому, а не по памяти страницы: перед каждым действием питомца (кормление, занятие, приветствие, отметка уголка, настройки) эти ключи перечитываются. Изменение другой вкладки, событие `storage` которой ещё не пришло, и значение, которое сайт восстановил на этой же странице (такого события нет вовсе), применяются до решения, тихо, как событие другой вкладки: уже угостили сегодня — второго лакомства и объявления нет, день сброшен — «Покормить» снова доступно, уже увиденная или непонятная ступень — без праздника. Запоздалое событие повторно ничего не делает. Не прочиталось — решение по последнему прочитанному, запись не делается, «сохранено» не говорится. Перед записью кэш тоже сверяется со свежим значением; если значение не изменилось, запись не делается. Загрузка при подключении читает все восемь ключей: отказ любого — подключение без записей. Поведение и форматы для сайта прежние; межвкладочной транзакции `localStorage` очередь страницы не даёт (как и раньше).

**Присутствие и день сценки в исходниках (PL04.2, не выпущено).** Ключи `presence` и `scene` (копия дня) тоже читает и пишет только ядро тем же путём: выбор «Всегда рядом» / «Приходит по зову» — явная запись (заменяет повреждённое), копия дня — неявная (повреждённую не заменяет); неизвестные поля и больший `v` остаются, собака не меняет вариант кота. День сценки резервирует веб-адаптер IndexedDB (`<ns>:scene`): одна readwrite-транзакция — чтение записи, решение ядра, постановка записи и сразу начало показа, затем подтверждение; записи нет — свободный день, запись не объект — повреждена (сценки нет, не заменяется); копия `scene:v1` пишется только после подтверждённого показа живым экземпляром. Метка вкладки в записи строится из времени и `Math.random`, а не из `crypto`.

**Расширения в исходниках (PL06, не выпущено).** Девятый ключ `<ns>:ext:v1` — новые данные лежат отдельно, потому что вкладки 0.1.4 нормализуют `cat` и `companion` и отбросили бы их. Выбор своего питомца — `ext.pet = { id, over }`, где `over` — штатный питомец из `companion.kind` в момент выбора: его и дальше видят вкладки 0.1.4. Запись действительна, пока `companion.kind === over`; если вкладка прежней версии выбрала другого штатного, побеждает её более поздний выбор, а запись засыпает (оживёт, если `kind` снова станет равным `over`). Имя и аксессуар своего питомца — `ext.pets[id]`, облик и расстановка — поля его ID в `look` и `room` (их 0.1.4 сохраняет), вариант сценки — `scene.variants[id]` (у собаки тоже; кот — по-прежнему `scene.cat`). Модель поведения — `ext.behavior`. Как и в остальных ключах: неизвестные поля, ID, значения и больший `v` остаются; повреждённый `ext` показывается по умолчанию, неявные записи его не трогают, явная команда (`setPet`, `setBehavior`, имя или аксессуар своего питомца) заменяет. ID с точкой — одно поле (`ext.pets["example.bunny"]`, `look["example.bunny"]`), не вложенный путь.

**Выбор питомца — без транзакции между ключами.** `setPet` пишет один или два ключа цепочкой шагов так, что после любого шага сохранённое показывает прежний или новый выбор, а не третьего питомца: штатный или свой → свой — только `ext.pet`; свой (`over = O`) → `O` — `ext` без `pet`; свой (`over = O`) → другой штатный — сначала `companion.kind`, после его подтверждения — снятие той же записи `ext.pet` (чужую более новую не снимает); штатный при спящей записи с `over = X` → `X` — сначала снятие, затем `kind`; штатный → штатный — только `kind`, как 0.1.4. Второй шаг ставится только после результата первого; итог — `save.keys` в порядке шагов, `results` по ключам: отказ первого шага — `failed` (второй — `skipped`), отказ второго — `partial`. Несохранённые поля шагов уходят со следующей правкой того же ключа, кроме `companion.kind`, который оживил бы спящую запись: он ждёт следующего `setPet`. С асинхронным хранилищем новый выбор, пришедший, пока своя запись выбора ещё не подтверждена (шаг прежнего выбора или правка, унёсшая несохранённое поле выбора), действует в памяти сразу, а шаги строит только после её результата — по тому, что действительно сохранено после её успеха или отказа: порядок и снимаемая запись — по правилам выше, ключ, которому писать нечего, — `saved` без записи. Отчёт такого выбора перечисляет оба ключа выбора штатного питомца (своего — `ext`) в порядке, ожидаемом по памяти; если после отказа нужен обратный порядок, шаги идут в нём (`results`, `done` — по фактическим шагам). Браузерное хранилище `mountPet` синхронно: там ожидания и `pending` нет. **Предел:** если снятие записи не удалось, а затем вкладка 0.1.4 выбрала питомца, равного `over`, новые версии снова покажут своего питомца, а вкладка 0.1.4 — штатного; без транзакции между ключами это не исправить.

**Комната и место в исходниках (PL04.3, не выпущено).** Ключи `room` и `place` тоже читает и пишет только ядро тем же путём — теперь все восемь ключей; своей записи и своего слушателя события `storage` у оболочки нет. `room` пишет только «Сохранить» редактора (явная запись — заменяет повреждённое): передвинутые предметы показанного животного, чьё место отличается от сохранённого, — по расстановке, перечитанной перед решением; у точки меняются `x` и `y`, остальное (поля точек, неизвестные предметы и животные, больший `v`) остаётся. Отказ записи — редактор открыт, «Не удалось сохранить расстановку. Попробуй ещё раз.»; расстановка действует на этой странице до перезагрузки и уходит со следующим удачным «Сохранить», а «Отмена» (или Esc) после отказа говорит это прямо: «Отменено. Расстановка не сохранилась в этом браузере: она действует на этой странице до перезагрузки.» (в 0.1.4 — «Отменено: расстановка прежняя.»). Другая вкладка сохранила расстановку, пока редактор открыт, — черновик не затирается, одно сообщение «В другой вкладке сохранена новая расстановка…». `place` — выбор места и вида: значение ключа как есть плюс изменённые поля одного устройства; непонятное место, чужие поля и больший `v` остаются; отказ записи — выбор действует до перезагрузки, подсказка «не сохранилось»; изменение другой вкладки применяется тихо.

## Отключение

`pet.destroy()`: идущие жесты и перенос отменяются, диалог закрывается, все слушатели (`document`, `window`, медиазапросы, элементы), таймеры, кадры анимации, наблюдатели и захваты указателя снимаются, элементы питомца и отметки на `<html>` удаляются. Отложенные операции прежнего экземпляра (реакции, объявления, фокус, завершение транзакции сценки) после отключения ничего не делают и не пишут — ни в прежнее пространство имён, ни в новый экземпляр (с любым `storage`). День сценки, уже записанный в IndexedDB до отключения, остаётся. Повторный `destroy()` ничего не делает; повторный `mountPet` — новый экземпляр с теми же сохранёнными настройками и без дублей слушателей. В исходниках (не выпущено, раздел «Команды и состояние») так же отключает `pet.core.destroy()` — и вызванный хостом напрямую, и из слушателя подписки; `pet.core` остаётся отключённым экземпляром, его команды отвечают `destroyed`.

Одностраничное приложение (SPA): подключать, когда разметка мест уже на странице, отключать при уходе с экрана, сообщать о данных и закрывать уголок при переходе:

```js
import { mountPet } from 'pet-companion'; // или './pet/pet.mjs' — папка на сайте

let pet = null;

// Экран с питомцем показан (разметка шапки уже в DOM).
export function enter(options) {
  pet = mountPet(options);
}

// Экран убран (размонтирование, выход из раздела): всё снято, настройки остались.
export function leave() {
  pet?.destroy();
  pet = null;
}

// Сайт пересчитал знаки или шаг; сменился маршрут — уголок закрывается вместе с экраном.
export const changed = () => pet?.update();
export const navigated = () => pet?.close({ restore: false });
```

## Отказ подключения

`mountPet` не бросает исключений и не оставляет полуподключённого питомца. Отказ — `console.error('Питомец не подключён: <причина>')`, `pet.mounted === false`, методы экземпляра ничего не делают, `destroy()` безопасен; сохранённые настройки не трогаются. После исправления причины можно снова вызвать `mountPet`.

- **До любых действий** (ничего не создано, прежний работающий питомец не тронут): нет `places`; `places.logo` или `places.top` — не функция; другое место, `progress`, `step`, `go`, `zone` или `home` переданы, но не функция; `storage` — не непустая строка; `mountPet` вызван изнутри идущего подключения (из функции места или `progress()`); на странице уже есть элемент с id модуля (`#cat-sheet`, `#cat-live`, `#cat-dock`, `#cat-side`, `#cat-float`, `#cat-bar`) — копия модуля до 0.1.2 или разметка сайта.
- **Исключение сайта при запуске** (функция места — до или после вставки элемента, `progress()`): всё, что успел создать модуль, убирается — элементы (и вставленные сайтом), слушатели, медиазапросы, таймеры, отметки на `<html>`. Чужие элементы, классы, данные и обработчики, даже с именами `cat-*`, не трогаются. Прежний питомец к этому моменту уже отключён (новое подключение заменяет прежнее) — подключите заново с исправленными функциями.

## Один питомец на странице

Раздел — о `mountPet`. Питомцы в контейнерах (`mountPetIn`, не выпущено) в этом реестре не участвуют: их на странице может быть несколько, вместе с одним `mountPet`; новый `mountPet` их не отключает (раздел «Питомец в контейнере»).

Активен один питомец `mountPet`: новый `mountPet` сначала отключает прежний (методы прежнего после этого ничего не делают, `mounted === false`). С 0.1.2 это действует и между копиями модуля — одними и теми же файлами по разным адресам (например, `/pet/` и `/vendor/pet/`, копия в сборке и рядом, перезагрузка модуля при разработке): владелец страницы записан в `globalThis[Symbol.for('pet-module')]` (`{ version, busy, destroy }`), новое подключение любой копии 0.1.2+ отключает прежнего владельца, а `destroy()` прежнего не трогает нового. Предел гарантий:

- копия до 0.1.2 реестра не знает: если она уже работает, новая копия откажет (видит её id), её не трогая; если копия до 0.1.2 подключится после новой, она создаст второй комплект элементов — так не поддерживается;
- одновременная загрузка разных версий 0.1.2+ рассчитана на этот реестр, но проверена только для одинаковых файлов по разным адресам и для пары с 0.1.1; держите на странице одну копию.

## Версии и обновление

- Номер версии — по [семантическому версионированию](https://semver.org/lang/ru/): исправления и совместимые дополнения без изменения прежнего поведения корректных подключений — patch (`0.1.3`).
- До стабильного интерфейса — версии `0.x`: несовместимое изменение публичного интерфейса (`mountPet`, настройки, методы, `localDay`, `places`, классы и переменные CSS, отметки на `<html>`, ключи хранения) — minor (`0.2.0`) с явным описанием в CHANGELOG. Для npm это значит: `^0.1.3` принимает только `0.1.x`.
- `1.0.0` — после того как интерфейс принят стабильным; после неё несовместимые изменения — major.
- Версии форматов данных (`v1` в ключах) меняются отдельно и только с чтением прежних: обновление модуля не теряет сохранённые настройки. Вкладка, открытая до обновления, работает прежним кодом до перезагрузки и пишет по своим правилам (раздел «Хранение», «Вкладки, версии, устройства»).
- Опубликованная версия не меняется: исправление — новая версия.
- **Обновление на сайте:** прочитайте CHANGELOG между версиями; npm — `npm install pet-companion@<версия>`; папка на сайте — замените `pet/` целиком файлами новой версии (не смешивайте файлы разных версий: модули импортируют друг друга) и перезагрузите страницу; кэш браузера — по правилам сайта (например, папка с версией в адресе: `/vendor/pet-0.1.3/`).

## Ограничения

- `mountPet`: один активный питомец на странице; фиксированные id `cat-*`; модель мест (пять мест, пороги окна) фиксирована; перенос мышью и пальцем — только при `zone`.
- `mountPetIn` (не выпущено): тема — только переменными `--pet-*` и `--cat-*`, правила сайта внутрь не проходят; прокрутку при открытом диалоге блокирует сайт; вид (целиком, портрет) — только по размеру контейнера, переноса питомца по странице нет; мест, `classes` и `texts` нет; один вид на контейнер; общий `namespace` — общие настройки и лимиты.
- `pet-companion/react` (не выпущено): только клиент — на сервере пустой контейнер; настройки подключения меняются новым подключением, не горячей заменой; детей у контейнера нет; без сборщика не поддерживается; проверены React 18.3.1 и 19.3.1 со сборщиком Vite 8.3.4.
- `manifest.json` (не выпущено): перечисляет файлы, а не зависимости сайта — `react` для `./react` странице даёт сборщик; сборщики, кроме Vite 8.3.4, не проверялись.
- Тексты и реплики — на русском; проверенный браузер — Chrome (раздел «Окружение и проверки»).
- CDN-сборки нет: папку `pet/` копируют из пакета или архива выпуска.
- `pet-companion/native-sqlite` и `pet-companion/native` (не выпущено): проверены в iOS Simulator и Android-эмуляторе, на телефонах (iPhone, Android) не запускались; в Expo Go на Android события `AppState` `blur`/`focus` в JavaScript не приходят (отмена жеста по `blur` проверена только в Node); отображение — `PetView` (PL10.1) и уголок `PetProvider`/`PetCorner` (PL10.2.1); «Поиграть», редактор, сценки, жесты и расширения на нативе — PL10.2.2–PL10.2.4; VoiceOver и TalkBack вживую не проверялись (роли, подписи и состояния — деревом доступности XCUITest и UI Automator); в Expo Go плавающая кнопка меню разработчика лежит поверх правого верхнего угла экрана и окна уголка (в собственной сборке её нет); смена масштаба шрифта на Android пересоздаёт Activity Expo Go — JavaScript перезапускается, открытый уголок (состояние сессии) закрывается, сохранённое восстанавливается; несколько процессов с общим файлом — условие интегратора, не проверено; разные написания одного файла через символические ссылки — разные файлы для реестра (корректно, но конкурентно); база в памяти не подходит; проверена только матрица Expo SDK 58.
- `pet-companion/core` (не выпущено): свой питомец рисуется только своим набором отображения (веб — `kits` у `mountPet`; натив — `kits` у `PetView` и `PetProvider`, PL10.1 и PL10.2.1; уголку — ещё ресурсы `room`, `items`, `Item`); общий координатор и очередь записи — в одной копии модуля (две копии файлов на странице или в процессе — независимые координаторы); межпроцессных уведомлений нет — изменение другого процесса видно после `load()` или записи того же ключа.

## Архитектура и будущий API

Проект следующих версий — общее ядро без DOM для веба и мобильных приложений на React Native, команды вида `pet.setName`, `pet.feed`, `pet.getState`, `pet.subscribe`, подключаемые питомцы и модели поведения, контракты хранения и редких сценок, порядок этапов — в файле `docs/ARCHITECTURE.md` репозитория (https://github.com/jivchic88/pet-companion/blob/main/docs/ARCHITECTURE.md; в пакет npm не входит). Это **проект, а не описание 0.1.4**: в выпущенной версии из него ничего не реализовано — методов `pet.*` сверх прежних и входов `pet-companion/core`, `pet-companion/web`, `pet-companion/native` в ней нет, мобильные приложения не поддерживаются. В исходниках репозитория (не выпущено) реализованы этапы:

- **PL02** — сохранность данных при записи и различение случаев чтения (раздел «Хранение»);
- **PL03** — первый внутренний срез ядра без DOM (`pet/core/`). Ядро хранит настройки (имя, выбор кота или собаки, облик, аксессуар, движение, реплики, «скрыт», увиденная ступень, день приветствия, день лакомства) и решает, что происходит после подтверждённого занятия, кормления и первого открытия за день. `mountPet` создаёт ядро на каждое подключение и показывает его состояние.
- **PL04.1** — реакции и время в ядре: очередь реакций и их приоритеты, учёт событий по `key`, тишина сайта и ввода, отложенная реакция, покой (моргание, движения, зевок, дремота), местная полночь, фон и возврат вкладки, «уменьшить движение», выбор реплик, приветствие, отклики на имя и нового напарника; исправление «Скрыть» (раздел «Что передаёт сайт и когда», `key`). Оболочка `mountPet` передаёт ядру события страницы и показывает его состояние; вид и анимации прежние. Пока вкладка в фоне, реакции не начинаются и не откладываются — и когда таймер, диктовка или диалог сайта кончаются в фоне; возврат ничего не доигрывает (числа, праздник ступени и лакомство обновляются как обычно).
- **PL04.2** — присутствие, виды и редкие сценки в ядре: «Всегда рядом» / «Приходит по зову» (лапка, вызов сразу в «Поиграть», закрытый по зову ничего не играет и не копит), «Скрыть» / «Показать» (по зову «Показать» возвращает лапку, игру не открывает), открытый вид уголка и его источник, праздник и отметка новой ступени по виду («Поиграть» и редактор не празднуют, «Новое в уголке» — при возврате), выбор редкой сценки и её отмена, резервирование дня (веб-адаптер IndexedDB), копия дня; ключи `presence` и `scene` — через ядро (раздел «Хранение»). Оболочка объявляет ядру, что умеет рисовать (кот и собака, три вида, сценки кота и собаки), и переводит нажатия, Esc и закрытие диалога в команды ядра; вид, тексты, фокус и прокрутка прежние. Отличия от 0.1.4 — мелкие: сценку отменяют и закрытие уголка, и смена аксессуара, а «Покормить», выбор готового имени, отклики игры и начало жеста — окончательно, даже если запись дня ещё ждёт очереди (в 0.1.4 их отклик только сменял идущую сценку).
- **PL04.3** — комната и игра в ядре: геометрия комнаты и игрушек в логических единицах без рисунков, редактор «Обустроить уголок» (черновик, выбор, шаги, перенос и его отдельная отмена, обычная расстановка, новая ступень, другая вкладка, сохранение и отмена), сдвиг к миске при кормлении, «Поиграть» (поглаживание и лапа с лимитом, миска и мячик, итог под сценой), долгое поглаживание с удержанием довольной позы и объявлением без повторов, поза для каждой поверхности; ключи `room` и `place` — через ядро (раздел «Хранение»). Оболочка распознаёт мышь, палец и клавиатуру и передаёт ядру смысл (начало, шаг и конец жеста, перенос, отпускание, отмена); вид, тексты, пороги распознавания жестов, фокус и прокрутка прежние. Отличия от 0.1.4 — честное сообщение «Отмена» в редакторе после неудачного сохранения и мелкие пограничные (CHANGELOG «Не выпущено»).

- **PL05** — публичные команды и наблюдение за состоянием: вход `pet-companion/core` (`createPetCore`, `createStorage`, `PetError`, `localDay`, `VERSION`, типы), команды `pet.*` и свойство `pet.core` у `mountPet`, результаты с честным статусом сохранения, снимок и подписка (разделы «Команды и состояние», «Ядро без отображения»). Кнопки уголка и команды — один путь правил ядра; интерфейс показывает итог прямой команды сразу; `pet.core.destroy()` отключает всё. Внутренние файлы (`pet/core/**`, `pet/web/**`) по-прежнему закрыты `exports`.
- **PL06** — подключаемые питомцы и модели поведения: определения формата 1 (`definePet`, `defineBehavior`), штатные кот, собака и `calm` как определения (входы `pet-companion/pets`, `pet-companion/behaviors`), регистрация `pets` и `behaviors` на экземпляр, `setBehavior`, ключ `ext:v1` и выбор своего питомца цепочкой `companion` → `ext`, запасной показ, наборы отображения веба (`mountPet({ kits })`) и внешний пример `examples/extension/` (раздел «Питомцы и модели поведения»). В ядре нет ветвлений по виду животного: кот и собака — данные; поведение и вид прежние.
- **PL07** — питомец в одном контейнере: вход `pet-companion/web` (`mountPetIn`, `createWebStorage`, `createWebScenes`, `catWeb`, `dogWeb`, типы), свой элемент и открытый Shadow DOM, вид по размеру контейнера, диалог в своём дереве, `onOpenChange` вместо блокировки прокрутки, тема переменными, несколько видов на странице вместе с `mountPet`, стили наборов (`styles`), строгий CSP (раздел «Питомец в контейнере»). Отображение `mountPet` перестроено на общую оболочку экземпляра (её состояние, указатель жестов и слушатели — на экземпляр, а не на модуль); его поведение, вид, id, места, отметки на `<html>` и реестр одного питомца прежние, а атрибутов `style` в разметке больше нет.
- **PL08** — установка в веб-проекты: вход `pet-companion/react` (`PetCompanion`, `usePetState`, серверный рендер и гидратация, StrictMode), перечень файлов `pet-companion/manifest.json` для серверов без сборщика и проверенная сборка Vite 8.3.4 — стили контейнера теперь находит и переносит сборщик (разделы «Подключение из npm», «React и серверный рендер», «Файлы пакета без сборщика»). `react` — необязательный партнёр только этого входа.
- **PL09** (реализовано, проверено в iOS Simulator и принято после независимой проверки 2026-10-16; телефоны не проверялись) — мобильное хранение и жизненный цикл: вход `pet-companion/native-sqlite` (`createSqliteStorage`, `createSqliteScenes`: своё соединение записи, `BEGIN IMMEDIATE` до чтения, мьютекс файла), частичный `pet-companion/native` (`useNativeLifecycle`, `usePetState`), диагностический пример `examples/expo/` (раздел «Мобильное хранение и жизненный цикл»). `react-native` и `expo-sqlite` — необязательные партнёры только этих входов.

- **PL10.1** (реализовано, проверено в Node, в iOS Simulator и в Android-эмуляторе, принято после повторной независимой проверки 2026-10-17; физические iPhone и Android-телефон не проверялись) — минимальное нативное отображение: `PetView`, `catNative`, `dogNative` во входе `pet-companion/native`, экран питомца в примере `examples/expo/` (раздел «Нативное отображение»). `react-native-svg` — необязательный партнёр только этого входа.
- **PL10.2.1** (реализовано, проверено в Node, в iOS Simulator и в Android-эмуляторе; по независимой проверке 2026-10-18 доработано — передача объявления при замене координатора, черновик имени и «Новое в уголке» по паре «ядро и показанный питомец» — и ждёт повторной проверки; физические телефоны не проверялись) — уголок на нативе: координатор `PetProvider` (один владелец объявления отображения), `PetCorner`, режим композиции `PetView`, ресурсы уголка наборов; в примере — уголок и настоящие отступы безопасной области (раздел «Уголок»).

Дальше по проекту: «Поиграть» и игровые жесты (PL10.2.2), «Обустроить уголок» (PL10.2.3), сценки, расширения PL06 на нативе и итоговая проверка доступности (PL10.2.4), проверка на физических iPhone и Android-телефоне (PL10) — их пока нет.
