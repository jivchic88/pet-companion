# pet-companion — питомец для сайта

Версия **0.1.4** (номер — в `package.json`; история — [CHANGELOG.md](CHANGELOG.md)). В исходниках репозитория после неё — невыпущенные изменения: хранение (раздел «Хранение») и общее ядро без DOM, на котором работает `mountPet`, — с реакциями и временем, исправлением «Скрыть», которое забывало учтённые события и тишину сайта, с присутствием, видами уголка и редкими сценками, комнатой и игрой, а также **публичные команды, снимок и подписка**: методы `pet.setName`, `pet.feed`, `pet.subscribe` и другие, свойство `pet.core` и вход ядра `pet-companion/core` для приложений без браузера (разделы «Команды и состояние», «Ядро без отображения», «Хранение», «Архитектура и будущий API»; CHANGELOG «Не выпущено»). Прежний интерфейс 0.1.4 сохранён; **опубликованный пакет 0.1.4 этих изменений не содержит** — как получить их для проверки, сказано в разделе «Команды и состояние».

> **In English, briefly.** A calm cat or dog companion that lives next to a web page and reacts to the site’s confirmed
> learning activity. Plain browser ES modules + CSS, inline SVG art, no runtime dependencies, no network, no build step.
> The interface texts and this guide are in Russian; other languages are not supported yet. License — [LICENSE](LICENSE).

Кот или собака рядом со страницей: спокойный спутник, который радуется подтверждённым занятиям сайта. Уголок (ступени по знакам, лакомство дня, имя, облик, аксессуар, место и вид, присутствие, движение), сцена «Поиграть» (поглаживание, лапа, миска, мячик), «Обустроить уголок» (расстановка комнаты), редкие сценки после занятия, «Всегда рядом» / «Приходит по зову». Клавиатура, Esc, возврат фокуса, объявления для скринридера, «уменьшить движение». Без сети, аналитики и сборки: ES-модули и CSS.

Модуль не знает, что такое занятие: знаки, «первое занятие дня» и следующий шаг считает сайт и передаёт их через небольшой интерфейс ниже. Оценки ответов питомцу не передаются.

## Установка

Три способа — одни и те же файлы одной версии:

- **npm** (сайт со сборщиком или с `node_modules` на сервере): `npm install pet-companion` — раздел «Подключение из npm».
- **Архив выпуска** (сайт без npm и сборки): файл `pet-companion-<версия>.tgz` — на странице выпуска (Releases) репозитория или из реестра командой `npm pack pet-companion@<версия>`. Это тот же архив, что в npm: внутри папка `package/` с `pet/`, `example.html`, README, CHANGELOG, LICENSE. Скопируйте `package/pet/` на сайт — раздел «Быстрый старт».
- **Папка из установленного пакета:** `node_modules/pet-companion/pet/` можно скопировать на сайт целиком (например, в `/vendor/pet/`). Скопированные файлы не правят — обновляют целиком (раздел «Версии и обновление»).

## Быстрый старт

1. Скопируйте папку `pet/` на сайт целиком, в любое место: модули импортируют друг друга относительными путями (`./pet-rules.mjs`), поэтому папка работает и в корне сайта, и во вложенном адресе.
2. Подключите стили и вызовите `mountPet` после того, как в разметке есть места для питомца (у `<script type="module">` в конце `<body>` — уже есть).
3. Сообщайте питомцу о подтверждённых занятиях (`pet.notify('saved', …)`).

Полный рабочий пример — `example.html` (пути `./pet/…` — относительно страницы; страница в другом месте — поправьте их). Открывать через http(s), а не `file://`: браузер не загружает ES-модули с диска.

```html
<!doctype html>
<html lang="ru">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>Мой сайт</title>
    <link rel="stylesheet" href="./pet/pet-base.css" />
    <link rel="stylesheet" href="./pet/pet.css" />
    <link rel="stylesheet" href="./pet/dog.css" />
  </head>
  <body>
    <header id="head" style="position: relative"><span id="title">Мой сайт</span></header>
    <main><button id="done" type="button">Урок пройден</button></main>
    <script type="module">
      import { mountPet } from './pet/pet.mjs';

      let marks = 0; // знаки за занятия — считает сайт
      let today = 0; // из них сегодня
      const head = document.getElementById('head');
      const pet = mountPet({
        storage: 'mysite',
        places: {
          logo: (el) => head.append(el), // компьютер: в шапке; здесь же «Показать …» после «Скрыть»
          top: (el) => head.prepend(el), // телефон: в шапке; без places.restore здесь же «Показать …»
          float: (el) => document.body.append(el), // компьютер: в правом нижнем углу окна
        },
        progress: () => ({ marks, today, limit: 3 }),
      });
      if (!pet.mounted) console.info('Питомец не подключён — причина выше в консоли');

      // Занятие сохранено и засчитано (здесь — по кнопке): сначала счёт сайта, затем событие.
      document.getElementById('done').addEventListener('click', () => {
        marks += 1;
        today += 1;
        pet.notify('saved', { key: `lesson-${marks}`, counted: true, first: today === 1 });
      });
    </script>
  </body>
</html>
```

Это полный минимум: `logo` и `top` обязательны (без них питомца негде показать и после «Скрыть» не вернуть — подключение откажет), остальные места — по желанию.

## Подключение из npm

**Со сборщиком** (Vite, webpack, esbuild и др.) — публичные входы пакета:

```js
import { mountPet, localDay } from 'pet-companion';
import 'pet-companion/pet-base.css'; // только если у сайта нет своих классов кнопок (раздел «Стили»)
import 'pet-companion/pet.css';
import 'pet-companion/dog.css';
```

Порядок импорта стилей — порядок каскада (раздел «Стили»). Стили объявлены в `sideEffects` пакета — сборщик их не выбрасывает. Другие пути внутри пакета (`pet-companion/pet/pet-rules.mjs` и т. п.) не экспортируются: внутренние модули не входят в публичный интерфейс.

**Без сборщика, `node_modules` отдаёт сервер** — карта импортов и ссылки на стили (пути — от страницы):

```html
<link rel="stylesheet" href="./node_modules/pet-companion/pet/pet-base.css" />
<link rel="stylesheet" href="./node_modules/pet-companion/pet/pet.css" />
<link rel="stylesheet" href="./node_modules/pet-companion/pet/dog.css" />
<script type="importmap">
  { "imports": { "pet-companion": "./node_modules/pet-companion/pet/pet.mjs" } }
</script>
<script type="module">
  import { mountPet } from 'pet-companion';
  // дальше — как в «Быстром старте»
</script>
```

**Типы.** `pet/pet.d.mts` описывает `mountPet`, настройки, экземпляр, `localDay` и `VERSION`; TypeScript находит их по входу пакета (`moduleResolution` — `bundler`, `node16` или `nodenext`), а при копировании папки — рядом с `pet.mjs`. У входов стилей — своя декларация `pet/css.d.mts` (условие `types` в `exports`; сборщик по тем же входам получает настоящий `.css`): импорт стилей выше проходит проверку типов и с `noUncheckedSideEffectImports`, без общей декларации `declare module '*.css'` в проекте сайта. Значений стиль не экспортирует — это не CSS Modules.

## Интерфейс

`mountPet(options) → pet` — не бросает исключений: при отказе возвращает неподключённый экземпляр (раздел «Отказ подключения»).

| Настройка | Что | По умолчанию |
| --- | --- | --- |
| `storage` | пространство имён хранения (непустая строка): ключи `<storage>:cat:v1` и т. д., база IndexedDB `<storage>:scene` | `'pet'` |
| `places` | `{ logo, top, sidebar, float, bar, restore }` — функции `(element) => …`, которые ставят элемент питомца в разметку сайта (раздел «Места»); `logo` и `top` обязательны, остальные — функция или нет | — |
| `progress()` | `{ marks, today, limit }` — знаков всего, за сегодня (для лакомства дня и строки «сегодня N из limit»), предел дня только для подписи. Вызывается часто (подключение, `update()`, событие занятия, открытие уголка, полночь) — должен быть быстрым и без побочных действий | `{ marks: 0, today: 0 }` |
| `step()` | следующий шаг на сайте `{ type, kind, title, action, href }` или `null` — карточка в уголке (после `pet.update()` появляется, меняется и убирается в открытом уголке) | нет карточки |
| `go(href)` | переход к шагу (уголок закрыт без возврата фокуса); без неё — обычная ссылка | — |
| `zone(device, id)` | рамка места для переноса `{ left, top, width, height }` (px окна) или `null`; `device` — `'desktop'` или `'phone'`, `id` — `'logo'`, `'sidebar'`, `'bottom'` (компьютер), `'top'`, `'bottom'` (телефон); без неё перенос между местами выключен | — |
| `home(panel?)` | куда поставить фокус, когда своего входа у питомца нет: внутри открытого диалога сайта `panel` — его кнопка закрытия; без `panel` — путь сайта к «Показать …» (на телефоне, если она в закрытом меню `restore`) | видимая «Показать …» |
| `classes` | классы кнопок и служебных элементов: `{ btn, alt, small, link, close, sr, muted }` | `pet-btn`, `pet-btn pet-btn-alt`, `pet-btn-small`, `pet-link`, `pet-close`, `pet-sr`, `pet-muted` (`pet-base.css`) |
| `texts` | тексты, зависящие от сайта: `wait` (лакомство до занятия), `rules` (массив абзацев «Как появляются знаки и лакомство»), `origin` (откуда знаки — в «Настройках»), `back` (где «Показать …» после «Скрыть»), `call` (где лапка вызова) | общие формулировки |

Методы и свойства `pet`:

| Метод | Что |
| --- | --- |
| `pet.update()` | знаки или шаг изменились — перечитать `progress()` и `step()`: открытый уголок обновится на месте (карточка шага появится, сменится или исчезнет; фокус с её ссылки — на «Как появляются знаки…»; пока вводят имя — после ухода из поля). Пока питомец спрятан, ничего не делает |
| `pet.update({ focus, timer, dictation, dialog })` | состояние страницы: `focus` — экран занятия (питомец собран); `timer`, `dictation`, `dialog` — тишина (без реакций и сценок; отложенная реакция — после, если ей меньше минуты; `dialog` ещё отменяет перенос). Ввод в текстовые поля страницы модуль отслеживает сам |
| `pet.notify('saved', detail)` | занятие подтверждено сайтом (раздел «Что передаёт сайт») |
| `pet.notify('failed')` | занятие не сохранилось — нейтральное ожидание без награды |
| `pet.open('corner' \| 'play')`, `pet.close({ restore })` | открыть уголок или сразу «Поиграть» (пока питомец спрятан, не открывает: вернуть — «Показать …»); закрыть (`restore: false` — без возврата фокуса и прокрутки) |
| `pet.opened` | открыт ли диалог питомца |
| `pet.mounted` | подключён ли этот экземпляр: `false` после отказа, `destroy()` или замены новым подключением |
| `pet.destroy()` | полное отключение (раздел «Отключение»); повторный вызов ничего не делает |
| `pet.version` | `VERSION` |

Команды ядра (`pet.setName`, `pet.feed`, `pet.getState`, `pet.subscribe` и др.) и свойство `pet.core` — в исходниках, не выпущено: раздел «Команды и состояние».

Другие экспорты `pet/pet.mjs`:

| Экспорт | Что |
| --- | --- |
| `VERSION` | версия модуля — та же, что у пакета |
| `localDay(date?)` | местная дата `'ГГГГ-ММ-ДД'` (часовой пояс браузера) — граница дня, по которой модуль открывает лакомство и считает сценки. Сайт считает `progress().today` и `first` по этой же дате: например, «знаки, у которых `localDay(new Date(время)) === localDay()`» |

Ошибки внутри модуля после подключения сайту не мешают: методы и обработчики перехватывают их (`console.warn('Питомец:', …)`).

## Что передаёт сайт и когда

- **Знаки** — `progress()`: сайт сам решает, какое действие даёт знак, и отдаёт счёт по запросу. Ступени питомца (0, 3, 9, 18, 30 знаков) и лакомство дня (`today > 0`) модуль считает по этим числам; «сегодня» — местная дата (`localDay`).
- **Подтверждённое занятие** — `pet.notify('saved', { key, counted, hard, first })` после того, как сайт сохранил действие и уже учёл его в своём счёте: `progress().marks` в этот момент **уже включает** этот знак (модуль считает «до занятия» как `marks − 1`, если `counted`). Порядок: сохранить → обновить счёт сайта → `notify('saved', …)`.
  - `key` — постоянный id события (запись, урок): повтор того же `key` в этом подключении не играет реакцию дважды. После перезагрузки или нового `mountPet` учёт `key` начинается заново, но праздник ступени не повторяется — увиденная ступень хранится (`<ns>:cat:v1`, `seenStage`). Событие, пришедшее, пока питомец спрятан или «по зову» и закрыт, не учитывается: после «Показать» тот же `key` даст реакцию. **Ограничение выпущенной 0.1.4:** «Скрыть» тоже начинает учёт заново (после «Показать» повтор прежнего `key` снова даст радость), забывает тишину, переданную до этого через `update({ timer, dictation, dialog })` (она снова действует со следующего такого вызова), и паузы повторов (ожидание после `failed` — 10 с, отклик на готовое имя — 4 с, приветствие нового напарника — 6 с). В исходниках репозитория (не выпущено, этап PL04.1) это исправлено: учтённые события, тишина и паузы повторов живут до отключения экземпляра (`destroy` или новый `mountPet`), «Скрыть» и «Показать» их не трогают;
  - `counted` — действие дало знак (может открыть ступень — праздник и новая вещь);
  - `hard` — трудное действие: поддержка вместо радости;
  - `first` — первое занятие дня: радость подсказывает про миску (лакомство дня).
  - `detail = null` — сохранённое действие не занятие: только перечитать числа.
  - Пока питомец спрятан или «Приходит по зову» и закрыт, событие только обновляет числа: без реакций, праздника и сценки (новую ступень покажет уголок).
- **Ошибка сохранения** — `pet.notify('failed')`: нейтральное ожидание без награды; знаки сайт не меняет, ошибку пользователю показывает сайт. Если сохранение затем удалось — обычный `notify('saved', …)`.
- **Изменение чисел или шага без события** (другое устройство, синхронизация) — `pet.update()`.
- **Состояние страницы** — `pet.update({ focus, timer, dictation, dialog })` при смене экрана, таймера, диктовки или открытии важного диалога сайта.
- **Переход по сайту** — `pet.close({ restore: false })`, если уголок должен закрыться вместе со сменой экрана.

## Команды и состояние

> **Не выпущено (этап PL05).** Есть только в исходниках репозитория после 0.1.4; пакет `pet-companion@0.1.4` из npm и архив выпуска этого не содержат. Чтобы попробовать до выпуска: в корне исходников `npm pack` — архив `pet-companion-0.1.4.tgz` с невыпущенными изменениями (номер в нём ещё прежний, но это **не** опубликованный выпуск 0.1.4 — не смешивайте), в своём проекте — `npm install <путь>/pet-companion-0.1.4.tgz`. Интерфейс может уточниться до выпуска.

Сайт управляет питомцем программно — без нажатий на кнопки уголка. Кнопки питомца и команды идут через одни и те же правила ядра, и интерфейс показывает итог команды сразу: имя, облик, кормление, открытый вид, расстановка — без клика, `update()` и правок разметки сайтом.

| Метод | Что |
| --- | --- |
| `pet.core` | экземпляр ядра этого подключения (вход `pet-companion/core`): все команды ниже и ещё `notify`, `open`, `close`, `start`, `destroy`, входы отображения. `null` при отказе подключения; после отключения — тот же отключённый экземпляр (`status: 'destroyed'`). `pet.core.destroy()` снимает всё, как `pet.destroy()` |
| `pet.setName(name)` | имя показанного питомца (очистка: без управляющих символов и `<>`, не длиннее 24 знаков; `''` — «ещё не выбирали»). Готовое имя из подборки — короткий отклик (не чаще раза в 4 с) и объявление «Имя: …»; своё — тихо. Результат — ещё `reacted` |
| `pet.setPet('cat' \| 'dog')` | показанный питомец (на виду — приветствие нового); `reacted` |
| `pet.setAppearance({ coat?, accessory? })` | облик (`smoke`, `ginger`, `tuxedo` у кота; `caramel`, `spotted`, `blacktan` у собаки) и аксессуар (`scarf`, `plaid`, `badge` — открывается ступенью, иначе `locked`); два ключа — итог может быть `partial` |
| `pet.setPreferences({ motion?, phrases? })` | движение `normal`, `calm`, `none`; короткие реплики |
| `pet.setPresence('always' \| 'on-call')`, `pet.hide()`, `pet.show()` | присутствие, «Скрыть», «Показать» |
| `pet.feed()` | лакомство дня (сегодня было занятие — `progress().today > 0`) |
| `pet.refresh()` | перечитать `progress()` (как `update()`, но с результатом) |
| `pet.setContext({ focus?, timer?, dictation?, dialog?, typing? })` | состояние страницы с результатом (как `update(flags)`) |
| `pet.interact({ type: 'pet' \| 'paw' })`, `{ type: 'bowl', to: 'near' \| 'home' \| [u, v] }`, `{ type: 'ball', to: 'roll' \| число }` | погладить, лапа, миска и мячик (предметы — только в открытой «Поиграть»); результат — ещё `outcome` и `text` |
| `pet.stroke.start()` → `{ id }`, `.step(id)`, `.end(id)`, `.cancel(id)` | долгое поглаживание (в открытой «Поиграть») — то, что передаёт жест отображения |
| `pet.toy.drag(id, [u, v])`, `.drop({ roll? })`, `.cancel()` | перенос миски или мячика в «Поиграть» (единицы рисунка 220×204) |
| `pet.room.select(id)`, `.move(id, [x, y])`, `.nudge('left' \| 'right' \| 'up' \| 'down')`, `.reset()`, `.drag(id, [x, y])`, `.drop()`, `.dragCancel()`, `.save()`, `.cancel()` | «Обустроить уголок» (единицы сцены 400×250; только в открытом редакторе — `pet.core.open('room')`) |
| `pet.getState()` | снимок (ниже); `null` при отказе подключения |
| `pet.subscribe(listener, { initial? })` | подписка (ниже); возвращает отписку |
| `pet.core.open('corner' \| 'play' \| 'room', { source? })`, `pet.core.close()` | открыть, сменить и закрыть вид — диалог открывается, фокус и блокировка прокрутки — как кнопкой; `source: 'call'` — вызов «по зову» (только `'play'`). `pet.core.close()` возвращает фокус и прокрутку, как `pet.close()` |
| `pet.core.notify('saved', { key, counted?, hard?, first? } \| null)`, `pet.core.notify('failed')` | подтверждённое занятие с результатом: `key` — **непустая строка**, лишние поля — ошибка; результат — ещё `reacted`, `duplicate`, `celebrate`, `fresh` |

Совпавшие по имени `update`, `notify`, `open`, `close`, `destroy` — прежние методы `mountPet` (возвращают `undefined`, `notify('saved', {})` без `key` работает как в 0.1.4). Входы отображения `setVisible`, `setReducedMotion`, `activity`, `setDisplay` есть только у `pet.core` — у подключения `mountPet` их ведёт само отображение. Методы не зависят от `this`: их можно передавать отдельно. Прежний экземпляр после нового `mountPet` или отключения отвечает `destroyed` и новый не трогает.

**Результат команды.** Успех — `{ ok: true, changed, save, ...поля команды }`: изменение действует сразу; `changed` — изменилось ли состояние; `degraded: true` — только если после изменения отказал планировщик (изменение и запись остались, эффект `warning`). Отказ — `{ ok: false, error: { code, message } }`: команда ничего не изменила и не записала. Команды не бросают исключений.

| Код | Когда |
| --- | --- |
| `invalid-argument` | неверный тип или значение (в том числе событие без `key`) |
| `unknown-id` | неизвестный питомец, облик, аксессуар или предмет комнаты |
| `unsupported` | отображение не объявило вид или питомца; у кота вне «Поиграть» нет «Дай лапу»; пол «Поиграть» не объявлен |
| `locked` | аксессуар ещё не открыт ступенью |
| `hidden` / `away` | питомец спрятан / «по зову» и не вызван |
| `not-open` | комната вне редактора, жест и предметы вне «Поиграть» |
| `no-gesture` | `stroke.step(id)` для жеста, который уже не идёт |
| `treat-waiting` / `treat-fed` | сегодня ещё не было занятия / уже угостили |
| `already-started`, `reentrant`, `destroyed`, `internal` | повторный `start()`; команда из порта или `progress()` во время другого вызова; экземпляр отключён; внутренний сбой до изменения |

**Сохранение** — `save`: `{ status, keys, results, done? }`. `status`: `none` — писать нечего; `saved` — записано; `failed` — не записалось (правка действует до перезагрузки и уходит со следующей правкой того же ключа, скрытых повторов нет); `partial` — у команды с двумя ключами (`setAppearance`) один записан, другой нет (транзакции между ключами нет); `pending` — асинхронное хранилище приняло запись в очередь, итог — обещание `done` (`saved`, `failed`, `partial`; никогда не отклоняется, разрешается и после `destroy`). Браузерное хранилище `mountPet` синхронно: итог окончательный в том же вызове, `pending` не бывает.

**Снимок** — `getState()`: глубоко замороженный объект из простых данных; тот же объект, пока ничего не изменилось (подходит для `useSyncExternalStore`). Поля: `status`, `storage`, `pet` (`id`, `shown`, `available`), `name` (`value`, `chosen`, `display`), `look`, `pets` (имя, облик и аксессуар кота и собаки), `prefs`, `presence` (`mode`, `hidden`, `surface`, `around`), `view` (`open`, `source`), `display`, `scene`, `visible`, `context`, `pose` (`base`, `resting`, `hold`, `shown.page/play/room`, `reaction`), `phrase`, `scenePhrase`, `play`, `room` (`pos`, `feedShift`, `draft`), `progress` (`null` до первого чтения счёта), `treat`, `save` (по ключам: `status`, `pending`, `unsaved`, `corrupt`). Объекты сайта не замораживаются и в снимок не попадают.

**Подписка** — `subscribe(listener, { initial = true })`: сразу текущий снимок (`reason: 'initial'`), затем одно обновление `{ snapshot, effects, reason }` на каждую фазу изменений; `reason` — имя команды, `'storage'` (другая вкладка), `'save'` (поздний итог записи), имя задачи (`'reaction'`, `'midnight'` …), `'destroyed'` — последнее. Эффекты — одноразовые события: `announce` (текст для скринридера), `celebrate` (новая ступень), `seen` (вещи ступени, увиденной в уголке), `micro`, `arrive`, `save`, `warning`. Команда, вызванная из слушателя, выполняется сразу; `getState()` в слушателе может быть новее переданного снимка. Исключение слушателя не мешает остальным и до команды не доходит.

```js
import { mountPet } from 'pet-companion';

const pet = mountPet({ storage: 'mysite', places, progress });
const off = pet.subscribe(({ snapshot, effects, reason }) => {
  badge.textContent = snapshot.treat === 'ready' ? 'Можно угостить' : '';
});
const named = pet.setName('Пиксель');
if (named.ok && named.save.status === 'failed') toast('Имя не сохранилось в этом браузере — действует до перезагрузки.');
const fed = pet.feed();
if (!fed.ok && fed.error.code === 'treat-waiting') hint('Одно занятие — и можно угостить.');
pet.core.open('room');
pet.room.move('bowl', [120, 230]);
pet.room.save(); // уголок с «Расстановка сохранена.»
off();
pet.core.destroy(); // то же, что pet.destroy()
```

## Ядро без отображения

> **Не выпущено (этап PL05)** — как раздел выше.

Вход `pet-companion/core` — то же ядро без DOM и браузера (Node, своё приложение, страница со своим отображением): `createPetCore`, `createStorage`, `PetError`, `localDay`, `VERSION`; типы — `pet/core.d.mts`. Отображения у него нет: состояние — снимок и подписка, рисует вызывающий.

```js
import { createPetCore, createStorage } from 'pet-companion/core';

const data = new Map(); // своё хранилище: Map, файл, база
const storage = createStorage({
  namespace: 'myapp',
  backend: { get: (name) => data.get(name) ?? null, set: (name, text) => data.set(name, text) },
});
storage.load(); // 'ready' | 'failed' (failed — работает без записи)

const pet = createPetCore({ storage, progress: () => ({ marks, today }) });
pet.subscribe(({ snapshot, effects }) => render(snapshot, effects));
pet.start();
pet.notify('saved', { key: `lesson-${id}`, counted: true });
```

- **Хранилище** — `createStorage({ backend, namespace })`: координатор над вашим хранилищем ключ-значение (имена — `<namespace>:<ключ>:v1`, форматы — как у браузера, раздел «Хранение»). Синхронный `backend` (`get`, `set` в том же вызове) или асинхронный — `{ async: true, get, set }` с обещаниями: тогда `await storage.load()`, а запись — `pending` с `done`. Один `backend` и `namespace` — один координатор, общий для всех ядер на нём: очередь записи по ключу, каждое ядро — своё подключение (правка одного приходит другим обновлением `'storage'`). Перед каждым новым ядром — `load()` (барьер: дожидается записей прежнего). Подключения создаёт само ядро.
- **Создание** — `createPetCore(options)` синхронно; неверные настройки — исключение `PetError` (`code`: `invalid-options`, `storage-not-loaded`) до подключения к хранилищу. Настройки: `storage` (обязательна, из `createStorage`, загружена), `progress`, порты `clock` (`now`, `day`, `nextDay`), `random`, `scheduler` (`later(ms, task)` → отмена), `log` (`warn`) — по умолчанию системные; `scenes` — резервирование дня редкой сценки (`reserve(decide, show)`; без него сценок нет). При создании — ни записи, ни таймеров, ни вызовов слушателей; `start()` — один раз: первое включение, приветствие дня, покой и полночь (`already-started` при повторе). До `start()` команды меняют состояние без реакций.
- **Что умеет отображение** — `setDisplay({ views, pets, scenes, full, moving, playFloor, playTouch })`: без объявленных видов `open` отвечает `unsupported`, без `scenes` редких сценок нет, без `playFloor` предметов «Поиграть» нет. Объявленное надо нарисовать самому — ядро рисунков не даёт.
- **Отключение** — `destroy()`: синхронно, повторно — ничего; задачи, жест, перенос, черновик и подписки сняты (слушатели получают последнее `'destroyed'`), подключение к хранилищу закрыто; уже принятые записи выполняются, их `done` сообщает итог. Дальше команды — `destroyed`, `getState()` — тот же снимок `destroyed`, `subscribe` с `initial` — один вызов `'destroyed'`.
- **Пока нет:** третьего питомца и другой модели поведения (настройки `pets` и `behaviors` — ошибка `invalid-options`: кот и собака встроены), контейнерного веб-режима (`pet-companion/web`), React-обёртки, мобильного хранилища и нативного отображения — это следующие этапы (раздел «Архитектура и будущий API»). Полный рабочий пример для Node — `examples/core-node.mjs` в репозитории.

## Места

Модель мест фиксирована: компьютер — `logo` (портрет в шапке, запасное место; здесь же «Показать …», когда питомец спрятан), `sidebar` (боковая панель: целиком с именем и репликой или портретом), `float` (правый нижний угол окна); телефон (до 860 px) — `top` (кнопка в шапке, запасное место), `bar` (нижняя панель). Места, для которых сайт не передал функцию, не используются. «Показать …» после «Скрыть»: на компьютере — у логотипа; на телефоне — в `restore` (например, в меню сайта, ссылкой с классом `classes.link`), а без `restore` — лапкой 44×44 в месте `top`, на месте питомца. Фокус после «Скрыть» — на видимую «Показать …», иначе — `home()`.

Пороги окна совпадают с `pet.css` и не настраиваются: боковая панель целиком — от 880 px высоты, портретом — от 840; внизу экрана — целиком от 1180 px ширины, портретом от 1140; наверху телефона целиком — от 390 px; нижняя панель — портрет от 340 px, целиком от 480. Место и вид выбирает пользователь в уголке; «Автоматически» — боковая панель на высоком экране, иначе шапка. Модель — окно браузера, а не произвольный контейнер: питомца нельзя поставить внутрь блока с прокруткой как в отдельное окно.

Элементы мест создаёт модуль (`#cat-dock`, `#cat-side`, `#cat-float`, `#cat-bar`, кнопка `.cat-face`), сайт только вставляет их — порядок Tab как на экране. Расположение внутри своих панелей (отступы, высота панели под питомцем) — правила сайта.

## Стили

- **Обязательны** `pet.css` и `dog.css` (собаку пользователь может выбрать в уголке).
- **`pet-base.css`** — для сайта, у которого нет своих классов кнопок (`classes` не передан): вид кнопок `pet-*` и защита питомца от общих правил сайта по тегам — основа шрифта окна (16 px, системный шрифт), у заголовков окна — свой шрифт, начертание, цвет и высота строки, у кнопок и подписей — без `text-transform` и `letter-spacing` сайта, у кнопок — `min-width`, у полей — `margin` и размер шрифта браузера по умолчанию. Сайт со своими `classes` этот файл не подключает и защищает питомца от своих общих правил сам.
- **Порядок:** стили сайта → `pet-base.css` (если нужен) → `pet.css` → `dog.css` → переопределения темы сайта.
- **Тема** — переменные на `:root` (светлая и тёмная по `prefers-color-scheme`), сайт переопределяет нужные после `pet.css`: `--pet-bg`, `--pet-surface`, `--pet-surface-2`, `--pet-ink`, `--pet-ink-2`, `--pet-line`, `--pet-accent`, `--pet-accent-ink`, `--pet-accent-soft`, `--pet-warn`, `--pet-warn-soft`, `--pet-radius`. Комната уголка — `--cat-wall-top`, `--cat-wall`, `--cat-floor` и др. (там же).
- **Границы.** Правила модуля — только по классам `cat-*`, `pet-*`, `dog-*`, атрибутам `data-cat-*`, `data-pet-*`, `data-play-*`, `data-room-*`, id `cat-*` и отметкам на `<html>`; сайту не стоит использовать эти имена. Проверено: CSS модуля (все три файла) не меняет ни одного вычисленного свойства элементов сайта — и на сайте без своих стилей, и на сайте с общими правилами `button`, `input`, `h2`, `dialog`; с `pet-base.css` питомец под такими правилами выглядит так же, как без них. Не поддерживаются: правила сайта с классом или id над питомцем (`.content button`, `#app h2`), `!important`, `*`, правила для `svg`, `path`, `circle` — рисунки встроены в страницу как SVG и наследуют такие правила.

## Отметки на html, прокрутка, перенос

Модуль ставит на `<html>`: `data-pet-at`, `data-pet-view` (где и как показан), `data-pet-call` (лапка вызова), `data-pet-move` (перенос), `data-cat-motion` (режим движения), классы `cat-on`, `cat-paused` (скрытая вкладка), `cat-open`. Пока открыт диалог питомца (`cat-open`), прокрутка страницы заблокирована: `overflow: hidden` у `<html>`. Пока питомца тянут мышью (`data-pet-move="drag"`), у всей страницы курсор `grabbing`. Сайт может опираться на эти отметки в своих правилах. После `destroy()` и отказа подключения их нет.

## Хранение

Только `localStorage` и IndexedDB этого браузера — по источнику сайта (схема, домен, порт) и пространству имён `storage`; данных сайта модуль не меняет, запросов не делает. Синхронизации между устройствами и браузерами нет: на телефоне и компьютере настройки свои. Два сайта на одном источнике с одинаковым `storage` делят настройки; разные `storage` — независимы.

| Ключ | Формат | Что | Запись меняет |
| --- | --- | --- | --- |
| `<ns>:cat:v1` | `{ v, name, accessory, motion, phrases, hidden, seenStage, greetDay }` | общие настройки, имя и аксессуар кота | только изменённые поля |
| `<ns>:companion:v1` | `{ v, kind, dog: { name, accessory } }` | выбор животного, собака | `kind` или изменённые поля `dog` |
| `<ns>:look:v1` | `{ v, cat, dog }` | облик | облик одного животного |
| `<ns>:treat:v1` | `{ v, fedDay }` | день лакомства | `fedDay` |
| `<ns>:place:v1` | `{ v, desktop: { place, view }, phone: { place, view } }` | место и вид | изменённые поля одного устройства |
| `<ns>:presence:v1` | `{ v, mode }` | «Всегда рядом» / «Приходит по зову» | `mode` |
| `<ns>:scene:v1` | `{ v, day, by, cat }` | копия дня редкой сценки | `day`, `by`, у кота — `cat` |
| `<ns>:room:v1` | `{ v, cat: { rest, bowl, yarn }, dog: { … } }` | расстановка комнаты | `x`, `y` передвинутых предметов показанного животного |
| IndexedDB `<ns>:scene` | хранилище `scene`, запись `shown` | день показа сценки — одной транзакцией с началом показа | `day`, `by`, у кота — `cat` |

`v1` в ключе и `v` в значении — версия формата данных, а не модуля.

> **Что выпущено.** Гарантии этого раздела — исходный код репозитория после этапов PL02, PL03, PL04.2 и PL04.3: **локальные изменения, ещё не выпущены**. В опубликованном пакете 0.1.4 (npm и архив выпуска) запись прежняя: `cat` и `companion` пишутся нормализованными (только поля `v1`, `cat` — и приветствием дня), точка передвинутого предмета `room` — заново `{ x, y }`, на исходном месте удаляется целиком, запись `shown` заменяется целиком, непонятный облик другого животного в `look` и непонятные значения в `cat` и `companion` становятся значениями по умолчанию, `v` записывается как 1 (кроме `place` и `presence`), отказ чтения не отличается от пустого ключа. Исправление выйдет следующей версией.

**Показ и запись.** Показ — нормализованные значения: непонятное этой версии (облик, аксессуар, вид животного, место из более новой версии) показывается значением по умолчанию — кот, первый облик, обычный платок, место «не выбирали». Запись — свежее значение ключа, прочитанное прямо перед записью, как есть, плюс только поля, изменённые этим действием (по правилам проверки). Остальное остаётся на своём месте: поля, которых эта версия не знает, вложенные данные, непонятные значения известных полей, данные других и неизвестных животных и предметов. Правка имени не меняет аксессуар, облик и вид животного; движение и реплики — общие поля `cat`, `companion` они не трогают. Имя и аксессуар кота хранятся в `cat`, собаки — в `companion.dog`, облик и расстановка обоих — в `look` и `room`. Неизвестный вид в `companion.kind` (показывается котом) остаётся, пока не выберут кота или собаку. Номер `v` больше известного не уменьшается. Правка пишет только известные поля формата: произвольных данных сайта модуль не записывает.

**Чтение: четыре случая.**

- **Ключа нет** (`getItem` вернул `null`) — умолчания; запись разрешена: первое подключение и приветствие дня записывают свои поля как раньше.
- **Повреждено** — не JSON или не объект (пустая строка, массив, строка, число, `null`): умолчания и предупреждение `Питомец: значение <ключ> повреждено…` в консоли. Неявные записи — приветствие дня, первое включение, отметка увиденной ступени (при открытии уголка и после занятия), копия дня сценки — такое значение **не трогают**: их поля действуют в памяти страницы, подсказка в «Настройках» говорит, что сохранённое повреждено. Явное действие пользователя (имя, облик, аксессуар, движение, реплики, выбор животного, место и вид, присутствие, «Покормить», «Сохранить» расстановки, «Скрыть» и «Показать») **заменяет** повреждённое значение своего ключа записью из изменённых полей и полей из памяти: понятных данных в нём нет, остальное снова по умолчанию. Объект, в котором непонятно отдельное значение, повреждённым не считается.
- **Отказ чтения** при подключении (исключение `getItem` или самого доступа к `localStorage`) — экземпляр работает в памяти страницы: умолчания, правки до перезагрузки, подсказки «хранилище недоступно», сценок нет. В хранилище он **ничего не пишет** и больше не читает, даже если доступ вернулся в той же сессии; новая попытка — следующее подключение (перезагрузка, `mountPet`), и оно покажет сохранённое. Отказ чтения перед конкретной записью — эта запись не делается, правка остаётся в памяти, как при отказе записи.
- **Более новая совместимая схема** (`v` больше 1, новые поля) — понятые поля показываются, неизвестное и `v` при записи сохраняются. Несовместимый формат будущих версий будет в новом ключе (`:v2`), а не в преобразованном прежнем.

**Увиденная ступень** (`seenStage` в `cat` — до какой ступени новые вещи уже показаны и отпразднованы) только растёт. Если ключа или поля нет либо там `-1`, первое включение молча отмечает текущую ступень, без праздника прошлых. Значение, непонятное этой версии (больше её ступеней — из более новой версии, не целое число, другой тип), в валидном объекте сохраняется. Его не трогают первое включение, отметка при открытии уголка и праздник после занятия. Не трогают его и явные правки других полей, в том числе вместе с полями, оставшимися в памяти страницы после отказа записи или повреждения. Пока такое значение в хранилище, эта версия показывает вещи по знакам, без точки «новое», «Новое в уголке» и праздника новой ступени. Понятная сохранённая ступень правкой из памяти страницы не понижается. День приветствия (`greetDay`), наоборот, заменяемое поле: оно хранит только последний день, и приветствие записывает сегодняшний день поверх прежнего значения, в том числе непонятного этой версии.

**Отказ записи и переполнение.** `setItem` бросил исключение (переполнено, запрещено) — прочитанное не уничтожается; изменённые поля действуют на этой странице до перезагрузки и уходят со следующей удачной записью того же ключа; подсказки говорят «не сохранилось». «Сохранено» — только после успешной записи. День сценки — одна транзакция IndexedDB: отказ до показа — сценки нет, после начала показа — показ останавливается, день свободен.

**Границы замены.**

- Если правке нужна вложенная структура, а в хранилище на её месте не объект — `companion.dog` (имя или аксессуар собаки), `place.desktop` или `place.phone` (место или вид устройства), `room.<животное>` или точка предмета (передвинутый предмет), — заменяется только она, объектом с изменёнными полями.
- У передвинутого предмета меняются только `x` и `y`; на исходном месте у точки нет координат, прочие её поля остаются, пустая точка удаляется. «Сохранить» пишет только предметы, которые передвигали (переносом, кнопками, «Вернуть обычную расстановку»), и только если их место отличается от сохранённого: место, показанное вместо непонятного значения, правкой не считается. Предметы других животных, неизвестные предметы и предметы закрытых ступеней не переписываются.
- Выбор вида не закрепляет место, если в хранилище — место, непонятное этой версии.
- Запись дня сценки в IndexedDB, которая не объект, — не свободный день: сценки нет, запись не заменяется. Сценка собаки не меняет вариант кота ни в базе, ни в копии.

**Вкладки, версии, устройства.**

- Запись перечитывает ключ непосредственно перед записью: последовательные правки разных полей в двух вкладках не теряются, у одного поля побеждает последняя. Записи `localStorage` между вкладками не транзакционны: две записи одного ключа в одно мгновение могут потерять одну правку.
- Открытая вкладка прежней версии (0.1.4 и раньше) выполняет свой код и при своей записи может отбросить неизвестные поля `cat` и `companion`, поля внутри точек `room`, заменить непонятный облик другого животного и запись `shown`, понизить `v`. Новая версия этого не исправляет; после такой записи она сохраняет то, что осталось. Поэтому данные будущих версий размещаются в новых ключах (например, ключ расширений) или там, где их сохраняют и прежние версии.
- Обновлённые файлы модуля действуют только после перезагрузки страницы: уже открытая вкладка выполняет код, загруженный при её открытии.
- Синхронизации между устройствами и браузерами нет; ключа расширений и миграций личных данных в этой версии нет.

Другие вкладки того же сайта применяют изменения тихо (событие `storage`); редкая сценка не повторяется в другой вкладке. Отключение и отказ подключения сохранённого не удаляют.

**Как это устроено в исходниках (PL03, не выпущено).** Ключи `cat`, `companion`, `look`, `treat` читает и пишет только внутреннее ядро через общий координатор пространства имён: одна очередь на ключ, запись — свежее значение, прочитанное в том же вызове, и только изменённые поля; результат известен сразу, до объявления («не сохранилось» — честно). Решение принимается по сохранённому, а не по памяти страницы: перед каждым действием питомца (кормление, занятие, приветствие, отметка уголка, настройки) эти ключи перечитываются. Изменение другой вкладки, событие `storage` которой ещё не пришло, и значение, которое сайт восстановил на этой же странице (такого события нет вовсе), применяются до решения, тихо, как событие другой вкладки: уже угостили сегодня — второго лакомства и объявления нет, день сброшен — «Покормить» снова доступно, уже увиденная или непонятная ступень — без праздника. Запоздалое событие повторно ничего не делает. Не прочиталось — решение по последнему прочитанному, запись не делается, «сохранено» не говорится. Перед записью кэш тоже сверяется со свежим значением; если значение не изменилось, запись не делается. Загрузка при подключении читает все восемь ключей: отказ любого — подключение без записей. Поведение и форматы для сайта прежние; межвкладочной транзакции `localStorage` очередь страницы не даёт (как и раньше).

**Присутствие и день сценки в исходниках (PL04.2, не выпущено).** Ключи `presence` и `scene` (копия дня) тоже читает и пишет только ядро тем же путём: выбор «Всегда рядом» / «Приходит по зову» — явная запись (заменяет повреждённое), копия дня — неявная (повреждённую не заменяет); неизвестные поля и больший `v` остаются, собака не меняет вариант кота. День сценки резервирует веб-адаптер IndexedDB (`<ns>:scene`): одна readwrite-транзакция — чтение записи, решение ядра, постановка записи и сразу начало показа, затем подтверждение; записи нет — свободный день, запись не объект — повреждена (сценки нет, не заменяется); копия `scene:v1` пишется только после подтверждённого показа живым экземпляром. Метка вкладки в записи строится из времени и `Math.random`, а не из `crypto`.

**Комната и место в исходниках (PL04.3, не выпущено).** Ключи `room` и `place` тоже читает и пишет только ядро тем же путём — теперь все восемь ключей; своей записи и своего слушателя события `storage` у оболочки нет. `room` пишет только «Сохранить» редактора (явная запись — заменяет повреждённое): передвинутые предметы показанного животного, чьё место отличается от сохранённого, — по расстановке, перечитанной перед решением; у точки меняются `x` и `y`, остальное (поля точек, неизвестные предметы и животные, больший `v`) остаётся. Отказ записи — редактор открыт, «Не удалось сохранить расстановку. Попробуй ещё раз.»; расстановка действует на этой странице до перезагрузки и уходит со следующим удачным «Сохранить», а «Отмена» (или Esc) после отказа говорит это прямо: «Отменено. Расстановка не сохранилась в этом браузере: она действует на этой странице до перезагрузки.» (в 0.1.4 — «Отменено: расстановка прежняя.»). Другая вкладка сохранила расстановку, пока редактор открыт, — черновик не затирается, одно сообщение «В другой вкладке сохранена новая расстановка…». `place` — выбор места и вида: значение ключа как есть плюс изменённые поля одного устройства; непонятное место, чужие поля и больший `v` остаются; отказ записи — выбор действует до перезагрузки, подсказка «не сохранилось»; изменение другой вкладки применяется тихо.

## Отключение

`pet.destroy()`: идущие жесты и перенос отменяются, диалог закрывается, все слушатели (`document`, `window`, медиазапросы, элементы), таймеры, кадры анимации, наблюдатели и захваты указателя снимаются, элементы питомца и отметки на `<html>` удаляются. Отложенные операции прежнего экземпляра (реакции, объявления, фокус, завершение транзакции сценки) после отключения ничего не делают и не пишут — ни в прежнее пространство имён, ни в новый экземпляр (с любым `storage`). День сценки, уже записанный в IndexedDB до отключения, остаётся. Повторный `destroy()` ничего не делает; повторный `mountPet` — новый экземпляр с теми же сохранёнными настройками и без дублей слушателей. В исходниках (не выпущено, раздел «Команды и состояние») так же отключает `pet.core.destroy()` — и вызванный хостом напрямую, и из слушателя подписки; `pet.core` остаётся отключённым экземпляром, его команды отвечают `destroyed`.

Одностраничное приложение (SPA): подключать, когда разметка мест уже на странице, отключать при уходе с экрана, сообщать о данных и закрывать уголок при переходе:

```js
import { mountPet } from 'pet-companion'; // или './pet/pet.mjs' — папка на сайте

let pet = null;

// Экран с питомцем показан (разметка шапки уже в DOM).
export function enter(options) {
  pet = mountPet(options);
}

// Экран убран (размонтирование, выход из раздела): всё снято, настройки остались.
export function leave() {
  pet?.destroy();
  pet = null;
}

// Сайт пересчитал знаки или шаг; сменился маршрут — уголок закрывается вместе с экраном.
export const changed = () => pet?.update();
export const navigated = () => pet?.close({ restore: false });
```

## Отказ подключения

`mountPet` не бросает исключений и не оставляет полуподключённого питомца. Отказ — `console.error('Питомец не подключён: <причина>')`, `pet.mounted === false`, методы экземпляра ничего не делают, `destroy()` безопасен; сохранённые настройки не трогаются. После исправления причины можно снова вызвать `mountPet`.

- **До любых действий** (ничего не создано, прежний работающий питомец не тронут): нет `places`; `places.logo` или `places.top` — не функция; другое место, `progress`, `step`, `go`, `zone` или `home` переданы, но не функция; `storage` — не непустая строка; `mountPet` вызван изнутри идущего подключения (из функции места или `progress()`); на странице уже есть элемент с id модуля (`#cat-sheet`, `#cat-live`, `#cat-dock`, `#cat-side`, `#cat-float`, `#cat-bar`) — копия модуля до 0.1.2 или разметка сайта.
- **Исключение сайта при запуске** (функция места — до или после вставки элемента, `progress()`): всё, что успел создать модуль, убирается — элементы (и вставленные сайтом), слушатели, медиазапросы, таймеры, отметки на `<html>`. Чужие элементы, классы, данные и обработчики, даже с именами `cat-*`, не трогаются. Прежний питомец к этому моменту уже отключён (новое подключение заменяет прежнее) — подключите заново с исправленными функциями.

## Один питомец на странице

Активен один питомец: новый `mountPet` сначала отключает прежний (методы прежнего после этого ничего не делают, `mounted === false`). С 0.1.2 это действует и между копиями модуля — одними и теми же файлами по разным адресам (например, `/pet/` и `/vendor/pet/`, копия в сборке и рядом, перезагрузка модуля при разработке): владелец страницы записан в `globalThis[Symbol.for('pet-module')]` (`{ version, busy, destroy }`), новое подключение любой копии 0.1.2+ отключает прежнего владельца, а `destroy()` прежнего не трогает нового. Предел гарантий:

- копия до 0.1.2 реестра не знает: если она уже работает, новая копия откажет (видит её id), её не трогая; если копия до 0.1.2 подключится после новой, она создаст второй комплект элементов — так не поддерживается;
- одновременная загрузка разных версий 0.1.2+ рассчитана на этот реестр, но проверена только для одинаковых файлов по разным адресам и для пары с 0.1.1; держите на странице одну копию.

## Окружение и проверки

- **Язык** интерфейса и реплик — русский; другие языки не поддерживаются.
- **Браузер:** ES-модули (`<script type="module">` по http(s)), `<dialog>` с `showModal()`, `:has()`, контейнерные запросы, `AbortSignal` у `addEventListener`, `crypto.getRandomValues`; IndexedDB — только для сценок (без неё сценок нет), `localStorage` — для настроек (без него — до перезагрузки и без сценок; раздел «Хранение»).
- **Проверено** в Google Chrome на macOS и Linux (CI репозитория) через Playwright (`npm run test:browser`, `npm run test:package`): компьютер (1280×900 и др.) и эмуляция телефона по ширине (390×844, 320×740, 844×390, касания) — на проверочном стенде, в примере `example.html` из установленного пакета и из распакованного архива по вложенному адресу. Сохранность данных (раздел «Хранение») — функции записи в Node и действия уголка на стенде: запись, повторное подключение, повреждённые значения, отказы чтения и записи, две вкладки, вкладка прежней 0.1.4 (неизменяемая копия её файлов в проверках). Внутреннее ядро (исходники, не выпущено) — в Node без браузерных глобалов (ловушки `window`, `document`, `localStorage` и др.): команды, снимок, подписка, раунд доставки, координатор хранения на синхронном и асинхронном (тестовом) хранилище; реакции и время — с ручными часами (местный день, смена пояса), ручным планировщиком и заданной случайностью; на стенде — `mountPet` пишет ключи ядра только через него, реакции, тишина, приветствие, фон, «уменьшить движение», полночь и «Скрыть» / «Показать» настоящими кнопками; «Поиграть» и «Обустроить уголок» — мышью, клавиатурой и пальцем (касания CDP) на 1280×900, 390×844, 320×740 и 844×390, котом и собакой, с тем же итогом сценариев жестов в Node. Команды и состояние (не выпущено, PL05) — вход `pet-companion/core` в Node (поверхность, результаты и отказы, отчёт сохранения синхронно и асинхронно, снимок, порядок подписки), прямые команды `pet.*` и `pet.core` на стенде с настоящим интерфейсом (имя, облик, кормление, виды, комната, «Скрыть», присутствие, `pet.core.destroy()`, повторное подключение) на 1280×900, 390×844, 320×740 и 844×390; упакованный архив — пример `examples/core-node.mjs` в Node, типы, `examples/commands.html` в Chrome. **Не проверено:** Safari и настоящий iPhone (эмуляция ширины в Chrome — не проверка iOS), Firefox, скринридеры, строгий CSP (модуль вставляет разметку через `innerHTML` с атрибутами `style` — без `'unsafe-inline'` в `style-src` вид может нарушиться), React Native, CSS-фреймворки сайтов, встраивание во фреймы.

## Версии и обновление

- Номер версии — по [семантическому версионированию](https://semver.org/lang/ru/): исправления и совместимые дополнения без изменения прежнего поведения корректных подключений — patch (`0.1.3`).
- До стабильного интерфейса — версии `0.x`: несовместимое изменение публичного интерфейса (`mountPet`, настройки, методы, `localDay`, `places`, классы и переменные CSS, отметки на `<html>`, ключи хранения) — minor (`0.2.0`) с явным описанием в CHANGELOG. Для npm это значит: `^0.1.3` принимает только `0.1.x`.
- `1.0.0` — после того как интерфейс принят стабильным; после неё несовместимые изменения — major.
- Версии форматов данных (`v1` в ключах) меняются отдельно и только с чтением прежних: обновление модуля не теряет сохранённые настройки. Вкладка, открытая до обновления, работает прежним кодом до перезагрузки и пишет по своим правилам (раздел «Хранение», «Вкладки, версии, устройства»).
- Опубликованная версия не меняется: исправление — новая версия.
- **Обновление на сайте:** прочитайте CHANGELOG между версиями; npm — `npm install pet-companion@<версия>`; папка на сайте — замените `pet/` целиком файлами новой версии (не смешивайте файлы разных версий: модули импортируют друг друга) и перезагрузите страницу; кэш браузера — по правилам сайта (например, папка с версией в адресе: `/vendor/pet-0.1.3/`).

## Ограничения

- Один активный питомец на странице; фиксированные id `cat-*`; модель мест (пять мест, пороги окна) фиксирована; перенос мышью и пальцем — только при `zone`.
- Тексты и реплики — на русском; проверенный браузер — Chrome (раздел «Окружение и проверки»).
- CDN-сборки нет: папку `pet/` копируют из пакета или архива выпуска.
- `pet-companion/core` (не выпущено): питомцы — только встроенные кот и собака; общий координатор и очередь записи — в одной копии модуля (две копии файлов на странице или в процессе — независимые координаторы); межпроцессных уведомлений нет — изменение другого процесса видно после `load()` или записи того же ключа.

## Архитектура и будущий API

Проект следующих версий — общее ядро без DOM для веба и мобильных приложений на React Native, команды вида `pet.setName`, `pet.feed`, `pet.getState`, `pet.subscribe`, подключаемые питомцы и модели поведения, контракты хранения и редких сценок, порядок этапов — в файле `docs/ARCHITECTURE.md` репозитория (https://github.com/jivchic88/pet-companion/blob/main/docs/ARCHITECTURE.md; в пакет npm не входит). Это **проект, а не описание 0.1.4**: в выпущенной версии из него ничего не реализовано — методов `pet.*` сверх прежних и входов `pet-companion/core`, `pet-companion/web`, `pet-companion/native` в ней нет, мобильные приложения не поддерживаются. В исходниках репозитория (не выпущено) реализованы этапы:

- **PL02** — сохранность данных при записи и различение случаев чтения (раздел «Хранение»);
- **PL03** — первый внутренний срез ядра без DOM (`pet/core/`). Ядро хранит настройки (имя, выбор кота или собаки, облик, аксессуар, движение, реплики, «скрыт», увиденная ступень, день приветствия, день лакомства) и решает, что происходит после подтверждённого занятия, кормления и первого открытия за день. `mountPet` создаёт ядро на каждое подключение и показывает его состояние.
- **PL04.1** — реакции и время в ядре: очередь реакций и их приоритеты, учёт событий по `key`, тишина сайта и ввода, отложенная реакция, покой (моргание, движения, зевок, дремота), местная полночь, фон и возврат вкладки, «уменьшить движение», выбор реплик, приветствие, отклики на имя и нового напарника; исправление «Скрыть» (раздел «Что передаёт сайт и когда», `key`). Оболочка `mountPet` передаёт ядру события страницы и показывает его состояние; вид и анимации прежние. Пока вкладка в фоне, реакции не начинаются и не откладываются — и когда таймер, диктовка или диалог сайта кончаются в фоне; возврат ничего не доигрывает (числа, праздник ступени и лакомство обновляются как обычно).
- **PL04.2** — присутствие, виды и редкие сценки в ядре: «Всегда рядом» / «Приходит по зову» (лапка, вызов сразу в «Поиграть», закрытый по зову ничего не играет и не копит), «Скрыть» / «Показать» (по зову «Показать» возвращает лапку, игру не открывает), открытый вид уголка и его источник, праздник и отметка новой ступени по виду («Поиграть» и редактор не празднуют, «Новое в уголке» — при возврате), выбор редкой сценки и её отмена, резервирование дня (веб-адаптер IndexedDB), копия дня; ключи `presence` и `scene` — через ядро (раздел «Хранение»). Оболочка объявляет ядру, что умеет рисовать (кот и собака, три вида, сценки кота и собаки), и переводит нажатия, Esc и закрытие диалога в команды ядра; вид, тексты, фокус и прокрутка прежние. Отличия от 0.1.4 — мелкие: сценку отменяют и закрытие уголка, и смена аксессуара, а «Покормить», выбор готового имени, отклики игры и начало жеста — окончательно, даже если запись дня ещё ждёт очереди (в 0.1.4 их отклик только сменял идущую сценку).
- **PL04.3** — комната и игра в ядре: геометрия комнаты и игрушек в логических единицах без рисунков, редактор «Обустроить уголок» (черновик, выбор, шаги, перенос и его отдельная отмена, обычная расстановка, новая ступень, другая вкладка, сохранение и отмена), сдвиг к миске при кормлении, «Поиграть» (поглаживание и лапа с лимитом, миска и мячик, итог под сценой), долгое поглаживание с удержанием довольной позы и объявлением без повторов, поза для каждой поверхности; ключи `room` и `place` — через ядро (раздел «Хранение»). Оболочка распознаёт мышь, палец и клавиатуру и передаёт ядру смысл (начало, шаг и конец жеста, перенос, отпускание, отмена); вид, тексты, пороги распознавания жестов, фокус и прокрутка прежние. Отличия от 0.1.4 — честное сообщение «Отмена» в редакторе после неудачного сохранения и мелкие пограничные (CHANGELOG «Не выпущено»).

- **PL05** — публичные команды и наблюдение за состоянием: вход `pet-companion/core` (`createPetCore`, `createStorage`, `PetError`, `localDay`, `VERSION`, типы), команды `pet.*` и свойство `pet.core` у `mountPet`, результаты с честным статусом сохранения, снимок и подписка (разделы «Команды и состояние», «Ядро без отображения»). Кнопки уголка и команды — один путь правил ядра; интерфейс показывает итог прямой команды сразу; `pet.core.destroy()` отключает всё. Внутренние файлы (`pet/core/**`, `pet/web/**`) по-прежнему закрыты `exports`.

Дальше по проекту: питомцы и модели поведения как подключаемые определения, контейнерный веб-режим, React, мобильное хранение и нативное отображение — их пока нет.

Рабочий интерфейс 0.1.4 — разделы выше; проект сохраняет совместимость с ним.
