# Мобильный пример PL09 — диагностика хранения и жизненного цикла

Минимальный потребитель `pet-companion` в Expo: настоящий `expo-sqlite` (`pet-companion/native-sqlite`) и настоящие `AppState` / `AccessibilityInfo` (`pet-companion/native`). Экран — обычные `View`, `Text`, `Button`: ни рисунков, ни уголка, ни анимаций (нативное отображение — этап PL10). В пакет не входит. Данные синтетические, база — свой файл `pet-companion-example.db`, пространство имён `expo-example`.

**Статус:** 16.10.2026 пример запущен и проверен **в iOS Simulator** (iOS 26.3.1, Expo Go 58.0.4) — все девять сценариев ниже (раздел «Проверка в iOS Simulator»). На физическом iPhone и на Android **не запускался**: по решению владельца для этапа PL09 достаточно симулятора, телефоны и Android — этап PL10. Симулятор и телефон — разные отметки.

## Матрица версий (Expo SDK 58)

Сверено 16.10.2026 по реестру npm: `expo@58.0.12` (`latest`), его `bundledNativeModules.json` и шаблон `expo-template-blank@sdk-58`.

API `expo-sqlite` 58.0.13, на которое опирается адаптер (исходник пакета `src/SQLiteDatabase.ts`, `src/pathUtils.ts`): `openDatabaseAsync(имя, { useNewConnection: true }, папка)` — отдельное соединение к тому же файлу; `db.databasePath` — папка + `/` + имя (или `:memory:`); `isInTransactionAsync()`, `closeAsync()`, `execAsync`, `getFirstAsync`, `runAsync`. `withExclusiveTransactionAsync` начинает обычным `BEGIN` (не `IMMEDIATE`) — адаптер его не использует.

**Node для Expo CLI.** `@expo/cli@58` и `react-native@0.88.0` объявляют `node: ^22.13 || ^24.3 || ≥26` (у `@expo/cli` ещё `≥27`). При подготовке примера на машине разработки был Node 25.8.2 — вне диапазона; Metro при проверке работал на переносимом Node 24.22.0 (официальный архив nodejs.org, контрольная сумма сверена), системный Node не менялся.

## Запуск

```sh
cd examples/expo
npm ci              # зависимости по package-lock.json (Expo, React Native, expo-sqlite — без --force и --legacy-peer-deps)
npm run lib         # npm pack текущей библиотеки → .lib/, установка архива без записи в package.json и lock
npm start           # Metro в локальной сети (expo start --lan), без туннеля и облачных сборок
```

Телефон и Mac — в одной сети Wi-Fi; в Expo Go (версия для SDK 58) отсканировать QR-код из терминала. `npm run lib` печатает версию, `integrity` и SHA-256 установленного архива — записать в отчёт.

**Папка проекта и iCloud.** Если папка синхронизируется с iCloud Drive и включена оптимизация хранилища Mac, macOS может выгрузить файлы `node_modules` (в Finder — облачко): Metro и Node тогда ждут загрузки или читают пустой файл. Запускайте пример из несинхронизируемой папки (точная копия файлов примера и тот же lock).

## Запуск в iOS Simulator (так проверялось 16.10.2026)

Нужны Xcode с runtime iOS и отдельный симулятор iPhone. Если `xcode-select -p` указывает на Command Line Tools, команды `xcrun simctl`, `xcodebuild` и Expo CLI запускайте с `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` (глобально не переключать).

```sh
NODE_OPTIONS=--dns-result-order=ipv4first npx expo start --localhost   # Metro на 127.0.0.1:8081
xcrun simctl install <UDID> ~/.expo/ios-simulator-app-cache/Expo-Go-58.0.4.tar.app
xcrun simctl launch <UDID> host.exp.Exponent
xcrun simctl openurl <UDID> 'exp://127.0.0.1:8081'
```

- Без `--dns-result-order=ipv4first` Metro на Node 24 слушает только `[::1]:8081`, а Expo CLI открывает `exp://127.0.0.1:8081` — в Expo Go «Could not connect to the server».
- Expo Go для симулятора скачивает и ставит сам Expo CLI (`npx expo start --ios` или клавиша `i`), сборку `Expo-Go-58.0.4.tar.app` он кладёт в `~/.expo/ios-simulator-app-cache/`. Симулятор он выбирает сам; на нужный другой — `xcrun simctl install`, как выше.
- В первый раз iOS спрашивает «Открыть в приложении «Expo Go»?» — подтвердить. Повторно открыть проект — те же `launch` и `openurl`.

**Диагностика в разработке** (`__DEV__`; в Node-проверках её нет): строки журнала, проверок и экрана дублируются в консоль — Metro печатает их с префиксом `[PL09]`. Мост `globalThis.__PL09__` — `titles`, `press(title)` (вызывает ту же функцию, что отдана кнопке последнего смонтированного экрана, и возвращает её результат) и `screen()` (показанные строки, проверки, журнал); им пользуется инспектор Metro (CDP, `Runtime.evaluate`; Metro требует заголовок `Origin: http://127.0.0.1:8081`). Своих действий у моста нет. Касания в симуляторе — XCUITest (Xcode); фон, «Уменьшение движения» и завершение процесса — средствами iOS и `simctl`, а не вызовами `setVisible` / `setReducedMotion`.

## Что проверить на устройстве

Записать: ОС и её версию, модель, «Expo Go <версия>» или своя сборка, телефон или симулятор (разные отметки).

1. **Загрузка.** Первый запуск: «Хранилище: ready», «Ядро: running, ready», в журнале «start после useNativeLifecycle → ready»; «Перезапуск…: первый запуск».
2. **Имя и движение.** «Имя», затем «Движение»: в журнале `setName: pending` → `cat: pending → saved`, `done → saved`; строка «cat» — `saved, [], []`.
3. **Подтверждённое занятие.** «Подтверждённое занятие»: «Реакция» — `joy`, затем `—`.
4. **Фон и возврат.** Сразу после «Подтверждённого занятия» свернуть приложение и вернуть: в журнале `AppState: background`, `ядро visible: true → false`, затем `AppState: active`, `ядро visible: false → true`; реакция задним числом не играет («Реакция» — `—`). На iPhone — центр уведомлений: `AppState: inactive`, видимость не меняется.
5. **Уменьшение движения.** Включить системное «Уменьшение движения» (iOS: Универсальный доступ → Движение; Android: Специальные возможности → Удалить анимацию) и вернуться: «Движение» — `<выбор владельца> / true / none`; выключить — снова `false`. Выбор владельца не меняется.
6. **Новое ядро.** «Новое ядро»: ✓ «destroy → load → новое ядро», имя и движение — подтверждённые. Два быстрых нажатия подряд: в журнале одна строка «новое ядро после load», «Ядро: running, ready» (результат первого нажатия уничтожен).
7. **Резервирование дня.** «Резервирование дня»: ✓ `shown, затем skip; показов 1` (повторно в тот же день — `skip, затем skip; показов 0`).
8. **Занятый файл.** «Занятый файл»: ✓ `failed` после ожидания ~1000 мс (с накладными расходами — до ~1,5 с); затем «Имя» — несохранённое уходит, `saved`.
9. **Перезапуск с тем же файлом.** Сменить имя и движение, дождаться `saved`, полностью закрыть приложение (смахнуть из переключателя, не просто свернуть), открыть снова: ✓ «Перезапуск с тем же файлом: восстановлено». Это завершение процесса; «Новое ядро» (шаг 6) — перезапуск ядра в том же процессе.

Неподтверждённая правка (`pending`) при закрытии процесса может потеряться — это граница (README библиотеки, «Мобильное хранение»): сохранение обещается только после `saved`.

## Проверка в iOS Simulator (16.10.2026)

Среда: Xcode 26.3 (17C529), runtime iOS 26.3.1 (23D8133), отдельный симулятор iPhone 17, Expo Go 58.0.4, Hermes (Static Hermes), новая архитектура (Fabric, bridgeless), `__DEV__`. Пример — по этому lock; библиотека — архивом `npm pack` (73 файла, содержимое совпадает с исходниками ревизии). Настоящий `expo-sqlite` (нативный модуль `ExpoSQLite`); база примера — файл в контейнере Expo Go симулятора, записи сверялись чтением `sqlite3 -readonly`.

| Сценарий | Итог | Как выполнено |
| --- | --- | --- |
| 1. Загрузка | ✓ `ready`, `running, ready`, start после ready, без ошибок | запуск Expo Go и `simctl openurl`; первое «Открыть» — касание XCUITest |
| 2. Имя и движение | ✓ `pending` → `saved`, `done` → `saved`; в SQLite то же | касания XCUITest |
| 3. Подтверждённое занятие | ✓ `joy`, затем `—` | касание XCUITest |
| 4. Фон и возврат | ✓ `inactive` → `background`, `visible: true → false`; событие в фоне — `saved` без реакции; возврат — `active`, `visible: false → true`, ничего не доигрывается | «Домой» и возврат — XCUITest; событие в фоне — вызов обработчика через inspector |

## Что этот пример не доказывает

Интерфейс питомца, iOS и Android вместе, поворот, безопасные области, несколько процессов (виджеты, App Groups) — не проверяются. Node-проверки библиотеки (`npm run test:native`) доказывают SQL-контракт на `node:sqlite`, но не работу `expo-sqlite`, Metro и нативных API — это сделал запуск в iOS Simulator; физический iPhone, Android и отключение питания (завершение процесса — не оно) им не проверены.

**Владение ядром экрана** (`App.js`): у экрана одно текущее ядро; «Новое ядро» уничтожает прежнее до барьера загрузки, каждое нажатие получает номер — результат более раннего уничтожается; размонтирование уничтожает текущее ядро, а созданное после него — сразу; после размонтирования экран своё состояние не меняет. Это проверяет в Node `test/native-example.test.mjs` библиотеки: исполняет этот `App.js` (только JSX → вызовы React) с настоящими React и хуками, подделкой React Native и управляемым вводом-выводом `diagnostics.mjs` — тоже не устройство.
