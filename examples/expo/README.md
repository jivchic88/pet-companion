# Мобильный пример — питомец на экране, хранение и жизненный цикл (PL09, PL10.1)

Минимальный потребитель `pet-companion` в Expo, без WebView: питомец нарисован настоящими нативными компонентами — `PetView` и штатные наборы `catNative`, `dogNative` входа `pet-companion/native` (элементы `react-native-svg`); хранение — настоящий `expo-sqlite` (`pet-companion/native-sqlite`); жизненный цикл — настоящие `AppState` и `AccessibilityInfo` (`useNativeLifecycle`). В пакет не входит. Данные синтетические, база — свой файл `pet-companion-example.db`, пространство имён `expo-example`.

**Статус:** 16.10.2026 пример PL10.1 запущен и проверен **в iOS Simulator** (iOS 26.3.1, Expo Go 58.0.4) и **в Android-эмуляторе** (Android 16, API 36, Expo Go 58.0.4) — разделы «Проверка PL10.1 в iOS Simulator» и «Проверка PL10.1 в Android-эмуляторе». На **физических телефонах** (iPhone, Android) **не запускался**: физический iPhone отложен владельцем, Android-телефона нет. Симулятор, эмулятор и телефон — разные отметки. Этап PL10 (вместе с PL10.2 — уголок, «Поиграть», «Обустроить уголок», жесты, поворот и безопасные области) не завершён.

## Запуск

```sh
cd examples/expo
npm ci              # зависимости по package-lock.json (Expo, React Native, expo-sqlite, react-native-svg)
npm run lib         # npm pack текущей библиотеки → .lib/, установка архива без записи в package.json и lock
npm start           # Metro в локальной сети (expo start --lan), без туннеля и облачных сборок
```

Телефон и Mac — в одной сети Wi-Fi; в Expo Go (версия для SDK 58) отсканировать QR-код из терминала. `npm run lib` печатает версию, `integrity` и SHA-256 установленного архива — записать в отчёт.

**Папка проекта и iCloud.** Если папка синхронизируется с iCloud Drive и включена оптимизация хранилища Mac, macOS может выгрузить файлы `node_modules` (в Finder — облачко): Metro и Node тогда ждут загрузки или читают пустой файл. Запускайте пример из несинхронизируемой папки (точная копия файлов коммита и тот же lock).

## Запуск в iOS Simulator (так проверялось)

Нужны Xcode с runtime iOS и отдельный симулятор iPhone. Если `xcode-select -p` указывает на Command Line Tools, команды `xcrun simctl`, `xcodebuild` и Expo CLI запускайте с `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` (глобально не переключать).

```sh
NODE_OPTIONS=--dns-result-order=ipv4first npx expo start --localhost   # Metro на 127.0.0.1:8081
xcrun simctl install <UDID> ~/.expo/ios-simulator-app-cache/Expo-Go-58.0.4.tar.app
xcrun simctl launch <UDID> host.exp.Exponent
xcrun simctl openurl <UDID> 'exp://127.0.0.1:8081'
```

- Без `--dns-result-order=ipv4first` Metro на Node 24 слушает только `[::1]:8081`, а Expo CLI открывает `exp://127.0.0.1:8081` — в Expo Go «Could not connect to the server».
- Expo Go для симулятора ставит сам Expo CLI (`npx expo start --ios` или клавиша `i`) в `~/.expo/ios-simulator-app-cache/`; на нужный другой симулятор — `xcrun simctl install`, как выше. В первый раз iOS спрашивает «Открыть в приложении «Expo Go»?» — подтвердить.
- **Касания** — XCUITest (отдельный проект UI-тестов, `xcodebuild test-without-building`): элементы находятся по `testID` (на iOS это `accessibilityIdentifier`) или подписи; ввод — клавиатурой симулятора. **Фон, «Уменьшение движения» и завершение процесса** — средствами iOS («Домой», Настройки, `xcrun simctl terminate`), а не вызовами `setVisible` / `setReducedMotion` / пересозданием ядра.

**Диагностика в разработке** (`__DEV__`; в Node-проверках её нет): журнал, проверки и строки экрана дублируются в консоль — Metro печатает их с префиксом `[PET]` (переходы реакции и нарисованной позы, статусы записи, `AppState`, видимость ядра). Мост `globalThis.__PET_EXAMPLE__` — `titles`, `press(title или testID)` (та же функция, что отдана кнопке последнего смонтированного экрана) и `screen()` (строки, проверки, журнал, итог); им пользуется инспектор Metro (CDP, `Runtime.evaluate`; Metro требует заголовок `Origin: http://127.0.0.1:8081`; цели iOS и Android различаются по `deviceName` в `/json/list`). Вызов через мост — это вызов обработчика, а не касание; в отчётах называется именно так.

## Запуск в Android-эмуляторе (так проверялось)

Нужны JDK 17 (его требует `sdkmanager`/`avdmanager`; Gradle-плагин React Native 0.88 тоже собирает на `jvmToolchain(17)`) и Android SDK: `platform-tools`, `emulator`, платформа `android-36` (targetSdk React Native 0.88; minSdk 24) и один образ `system-images;android-36;google_apis;arm64-v8a` на Mac с Apple Silicon. Нативная сборка (Gradle, NDK, build-tools) для Expo Go не нужна.

```sh
avdmanager create avd -n <имя> -k "system-images;android-36;google_apis;arm64-v8a" -d pixel_7
emulator -avd <имя> -no-window -no-audio -no-boot-anim -no-snapshot -gpu swiftshader_indirect   # без окна
NODE_OPTIONS=--dns-result-order=ipv4first npx expo start --localhost   # Metro на 127.0.0.1:8081
adb install Expo-Go-58.0.4.apk                     # androidClientUrl SDK 58 из api.expo.dev/v2/versions
adb reverse tcp:8081 tcp:8081                      # 127.0.0.1:8081 эмулятора → Metro на Mac
adb shell am start -a android.intent.action.VIEW -d exp://127.0.0.1:8081 host.exp.exponent
```

- `adb reverse` снимается при перезапуске `adbd` (например, `adb root`) — повторить команду; без неё Expo Go теряет Metro.
- После `am force-stop host.exp.exponent` первый `am start` иногда поднимает только экран запуска Expo Go и уходит в фон — повторить тот же `am start` (процесс уже новый).
- На каждом новом процессе Expo Go показывает подсказку меню разработчика («Continue») — её закрывает касание или жест вниз.
- **Касания и ввод** — `adb shell input` по координатам из дерева UI Automator (`uiautomator dump`): `testID` React Native — это `resource-id`, подпись кнопки — `content-desc`, состояния «выбрана» / «недоступна» — `selected` / `enabled`. Не касаться под экранной клавиатурой (её рамка — `dumpsys window`, источник `type=ime`) и ждать остановки прокрутки по инерции; жест прокрутки не начинать над полем ввода (поле забирает жест) и у края экрана (системный жест «Назад»). Ввод `adb shell input text` — только латиница. **Фон, возврат, «Удалить анимацию» и завершение процесса** — средствами Android: «Домой» (`KEYCODE_HOME`), «Недавние», Настройки → Специальные возможности → Цвет и движение → «Удалить анимацию», `am force-stop`. Файл SQLite на эмуляторе с образом Google APIs читается после `adb root`: `/data/data/host.exp.exponent/files/SQLite/pet-companion-example.db` (`sqlite3 -readonly`).

## Экран

Сверху — питомец (`PetView`, 200 точек) и строка состояния (хранилище, ядро, итог последнего действия). Ниже группы кнопок (у каждой — роль, подпись, состояние «выбрана» / «недоступна», область касания от 48 точек, `testID`):

- **Действия:** «Погладить» (`interact({ type: 'pet' })`, как касание питомца), «Покормить» (подпись — по `treat` снимка: «сначала занятие», «Покормить», «сегодня уже угостили»; кнопка доступна всегда — проверку делает ядро, отказ показывается его текстом), «Занятие сохранено» (хост сначала записывает занятие в свой счёт `example_marks`, затем `progress()` уже со знаком и `notify('saved', { key, counted: true })`), «Занятие не сохранилось» (хост отказывает до записи — знака нет, `notify('failed')`), «Повторить уведомление» (тот же `key` — ядро не награждает повторно).
- **Питомец** (кот / собака — `setPet`), **Имя** (поле с клавиатурой: фокус — тишина ввода `setContext({ typing: true })`; «Сохранить имя» или «Готово» — `setName`, фокус снимается; ядро очищает имя до 24 знаков; несохранённый ввод принадлежит ядру и показанному питомцу — смена питомца или ядра его снимает, чужой черновик не сохраняется; смена ядра снимает фокус поля), **Облик** (`setAppearance({ coat })`), **Платок** (`setAppearance({ accessory })`; ещё не открытый ступенью — недоступен с подсказкой), **Движение** (`setPreferences({ motion })`).
- **Подключение и день:** «Отключить питомца» (`destroy`, питомца нет) / «Подключить питомца» (`load` → новое ядро → `ready` → `start`, сверка восстановленного), «Следующий день (проверка)» (сдвиг дня хоста — порт `clock` публичного `createPetCore`; сдвиг хранится в `example_clock` и переживает перезапуск; ядро создаётся заново).
- **Диагностика PL09:** строки состояния, «Новое ядро», «Резервирование дня», «Занятый файл», проверки и журнал.

Объявления питомца (лакомство, готовое имя) делает `PetView` по эффектам ядра; экран объявляет только свои важные итоги (отказы, итог занятия) — без повторов.

## Что проверить на устройстве

Записать: ОС и её версию, модель, «Expo Go <версия>» или своя сборка, телефон, симулятор или эмулятор (разные отметки).

1. **Холодный запуск.** Питомец нарисован; «Хранилище: ready · ядро running»; в журнале «start после useNativeLifecycle → ready».
2. **Выбор, имя, облик.** «Кот» / «Собака», имя с клавиатуры и «Сохранить имя», облик, платок: рисунок меняется, итог — `сохранено`. Ввести имя коту, не сохранять, выбрать собаку — в поле имя собаки, «Сохранить имя» — `без изменений`; у кота — его сохранённое имя.
3. **Занятие.** «Занятие сохранено» — радость (глаза-дуги, улыбка, хвост трубой, реплика), через ~1,5 с — покой; «Занятие не сохранилось» — нейтральное ожидание, знака нет; «Повторить уведомление» — без новой реакции.
4. **Кормление.** После занятия «Покормить» — ест у миски, затем доволен, затем покой после лакомства; повторно — «Сегодня уже угостили.».
5. **Перезапуск.** После `сохранено` полностью закрыть приложение и открыть снова: «✓ Перезапуск с тем же файлом: восстановлено» — питомец, имя, движение, облик, платок и лакомство дня. Лакомство сверяется только в тот же день хоста (запись диагностики хранит день): открыть на следующий день — «✓ … лакомство не сверяется — подтверждено fed за <день>, сегодня <день>: waiting» (лакомство нового дня решает ядро), сохранённые настройки сверяются всегда; несовпадение — «✗ НЕ совпало». Запись прежнего формата без дня — «лакомство не сверяется — в записи нет дня».
6. **Фон.** Во время реакции свернуть и вернуть: реакция снята, ничего не доигрывается.
7. **Уменьшение движения.** Включить системное (iOS: Универсальный доступ → Движение; Android: Специальные возможности → Удалить анимацию): `<выбор владельца> / true / none`, реакция — статичной позой; выключить — снова `false`.
8. **Касания.** Касание питомца и «Погладить» — поза «гладят», знаков не прибавляется.
9. **Отключение.** «Отключить питомца» во время реакции — питомца нет; «Подключить питомца» — всё восстановлено.

## Что этот пример не доказывает

Полный нативный интерфейс (уголок, «Поиграть», «Обустроить уголок», расширения PL06 на нативе, жесты, поворот, безопасные области), физические телефоны, несколько процессов (виджеты, App Groups). Node-проверки библиотеки (`npm run test:native`) доказывают контракт хранения на `node:sqlite` и контракт отображения на подделках React Native и `react-native-svg`, но не работу нативных модулей — это делает запуск на платформе.

**Владение ядром экрана** (`App.js`): у экрана одно текущее ядро; «Новое ядро», «Подключить питомца» и «Следующий день» уничтожают прежнее до барьера загрузки, каждое создание получает номер — результат более раннего уничтожается; размонтирование уничтожает текущее ядро, а созданное после него — сразу; после размонтирования экран своё состояние не меняет. Это проверяет в Node `test/native-example.test.mjs` библиотеки: исполняет этот `App.js` (только JSX → вызовы React) с настоящими React, хуками и `PetView`, подделками React Native и `react-native-svg` и управляемым вводом-выводом `diagnostics.mjs` — тоже не устройство. Там же — черновик имени по ядру и питомцу (смена кнопкой, прямой командой ядра и в такте нажатия, отключение, «Новое ядро») и сверка перезапуска по дню хоста на настоящей логике примера с публичным ядром (тот же и следующий день, потерянная запись, прежние форматы).
